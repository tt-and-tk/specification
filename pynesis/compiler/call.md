# 関数呼び出しの命令
言語として書ける関数の規則は，[pynesis/language/function.md](../language/function.md)を参照．  

関数呼び出しでスタックに積むものは，次の2つである．  

- 戻り先: CALL命令が積む([qurge/cpu/stack.md](../../qurge/cpu/stack.md)を参照)  
- スタックフレーム: 呼び出された関数が確保する(「スタックフレーム」を参照)  

# スタックフレーム
関数は，自分のフレームを先頭で確保し(SPを下げる)，戻る直前に解放する(SPを戻す)．  
確保した直後のSPを基準とした配置は次のとおりで，基準はフレームの中で最も小さい番地にあたる．  

| 位置 | 内容 |
|:-|:-|
| `SP+0` | ローカル変数の領域(Lバイト．宣言ごとに固有の位置を割り当て，ブロックを抜けても再利用しない) |
| `SP+L` | レジスタの退避領域(Sバイト．`r{i}`の退避先は`SP+L+i*4`) |
| `SP+L+S` | 引数の領域(4×nバイト．宣言の順に1つ1ワード) |
| `SP+L+S+4n` | 戻り先(CALLが積む) |

フレームの大きさはコンパイル時に確定する．  
このため，大きさが実行時に決まる領域(C言語の処理系の`alloca`など)は，スタック上に確保できない．  
L・S・nがすべて0の関数は，フレームを持たない．  

# 呼び出し規約
呼び出し元はSPを動かさず，i番目(先頭を0とする)の引数を`SP-4-4n+4i`番地へ書き込んでから`call`する．  
CALLが戻り先を`SP-4`番地へ積み，呼び出し先がフレームを確保してSPを下げると，書き込んだ引数がそのまま呼び出し先の引数の領域になる．  

- 値は，引数の型の幅で書き込む([pynesis/language/type.md](../language/type.md)の「読み出しと格納」を参照)  
- ポインタの引数へは，番地を1ワードで書き込む．配列を渡す場合は，先頭要素の番地を書き込む  
- 戻り値は，RAX(`6'h1e`)を経由する  

## 引数に関数呼び出しを含む場合
引数の書き込み先は，同じSPから行うどの呼び出しでも同じ位置になる．  
このため，`add(1, add(2, 3))`のように引数の式が関数呼び出しを含む場合，先に`1`を書き込むと，内側の`add(2, 3)`が同じ位置へ自分の引数を書いて壊してしまう．  
内側の呼び出しを含む引数までは値をレジスタに残したまま評価し，内側の呼び出しがすべて終わってからまとめて書き込む．  

## 関数ポインタを通した呼び出し
引数の受け渡しと戻り値の受け取りは，直接の呼び出しと同じである．  

- 関数名による直接の呼び出しは，`call add`のように飛び先に関数名を書く  
- 関数ポインタを通した呼び出しでは，呼び出す関数の番地(関数ポインタの値)を，引数より先にレジスタへ読み込む．引数を書き込んだ後に，そのレジスタを飛び先にした`call`(番地を`r1`に読み込んだ場合は`call r1`)で呼び出す([pyntaxis/language/instruction.md](../../pyntaxis/language/instruction.md)の「ジャンプ系(J系)」を参照)  
- 関数の番地(関数の先頭の命令のPC)は，アセンブリのイミディエイトデータの位置に関数名を書いて求める([pyntaxis/language/program.md](../../pyntaxis/language/program.md)の「関数のPC」を参照)  

# 実行ファイルのmain
## 引数の受け取り
実行ファイルの`main`は，シェルから`call`されずに実行を始めるが，引数はこの規約のとおりに読む．  
シェルが置く`argc`・`argv`の位置(SP-8・SP-4．[qosmos/kernel/exec.md](../../qosmos/kernel/exec.md)の「引数の置き方」を参照)は，この規約で2つの引数を渡して`call`した直後の引数の位置と一致する．  
このため，`int main(int argc, char **argv)`の引数として受け取れる．  

## 終了
実行ファイルの`main`は，終了の機能(番号`5`)のシステムコールで，戻り値を終了状態としてシェルへ伝えて終える([qosmos/program/syscall.md](../../qosmos/program/syscall.md)を参照)．  

- このシステムコールは，`return`文と，最後の文が`return`文でない`main`の終わりで，フレームを解放してから呼ぶ  
- 値の並べ方は組み込み関数`syscall`と同じで(「システムコールの呼び出し」を参照)，SPを24バイト下げてから番号と1つ目の引数だけを書き込む  
- `main`を`ret`で終えないのは，シェルが`main`を`call`せずに実行し始め，戻り先がないためである  
- アセンブリではどの関数にも`ret`が必要なため，`main`の末尾にも`ret`を置く．OSは終了のシステムコールから実行ファイルへ戻らないため，この`ret`は実行されない  

ROMの`main`の終わりは，アセンブラが`ret`を自分自身へ飛ぶ`jmp`に置き換える([pyntaxis/assembler/encoding.md](../../pyntaxis/assembler/encoding.md)の「mainのretの扱い」を参照)．  

# システムコールの呼び出し
組み込み関数`syscall(number, a, b, c, d)`([pynesis/language/builtin.md](../language/builtin.md)を参照)は，Qosmosの取り決め([qosmos/program/syscall.md](../../qosmos/program/syscall.md)を参照)に従い，次の順に命令を生成する．  

1. `number`と`a`〜`d`を順に評価する  
2. SPを24バイト下げる．24バイトは，戻り値の置き場・番号・引数4つの6つの値を，4バイトずつ並べる大きさである  
3. SP+4へ番号を，SP+8〜SP+20へ`a`〜`d`を書き込む  
4. SYSCALL命令を実行する  
5. SP+0(戻り値の置き場)から戻り値を読み，SPを24バイト戻す  

この順にする理由は次のとおりである．  

- SPを下げてから書き込む理由: SPより上にあるスタックフレームや，シェルが置いたコマンド名と引数を壊さないため  
- 評価を済ませてからSPを下げる理由: 評価の途中でローカル変数を読み書きする位置が，フレームを確保した時点のSPを基準にしているため  

OSは，戻るときにレジスタの値を保たない([qosmos/program/syscall.md](../../qosmos/program/syscall.md)を参照)．  
このため，式の途中で`syscall`を呼ぶ場合は，関数呼び出しと同じく，評価済みの値をフレーム上へ退避し，戻った後に復元する(「レジスタの使い方」を参照)．  

# レジスタの使い方
変数(const変数とハードウェア変数を除く)はメモリ上に置くため，汎用レジスタr0〜r15(`6'h00`〜`6'h0f`)は変数の保持には使わず，式の評価のための一時的なレジスタとして使う．  

- 式の評価には，r0から順に割り当てる(部分式の結果を番号の小さいレジスタから積み，演算で畳んで解放する)．式の複雑さの上限は，[pynesis/language/limit.md](../language/limit.md)の「式の複雑さ」を参照  
- 関数の戻り値と演算結果の最終的な置き場には，RAX(`6'h1e`)を使う  

## callをまたぐレジスタ
r0〜r15の値は，`call`をまたぐと保たれない．  
呼び出した後も必要な値は，メモリ(変数)に置く．  

- ハードウェアはレジスタを物理的にリセットしない．呼び出し先が自由に上書きしてよいという取り決めにより，結果として値が壊れる．各関数のコード生成がr0から番号を振り直すため，番号の小さいレジスタが衝突する  
- この取り決めは，ハードウェアが退避するのは戻り先だけであり，汎用レジスタの退避を呼び出し元・呼び出し先のどちらにも義務づけていないためである  

式の評価の途中に関数呼び出しを含む場合，呼び出しをまたいで残したい他のレジスタの値は，呼び出しの前後で自分のフレームの退避領域へ退避・復元する．  
退避先が呼び出しごとに別の番地になるため，呼び出し先が同じレジスタを退避しても，呼び出し元の退避した値は壊れない．
