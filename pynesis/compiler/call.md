# 関数呼び出しの命令
言語として書ける関数の規則は，[pynesis/language/function.md](../language/function.md)を参照．  
この文書の命令は，コンパイラが出力するアセンブリ言語Pyntaxisの命令で書く．  
番地の上と下は，それぞれ番地の大きい側と小さい側を指す([qurge/memory.md](../../qurge/memory.md)の「容量と番地」を参照)．  

関数を呼び出すと，スタックに次の2つが積まれる．  

- 戻り先: Pyntaxisの`call`が積む([qurge/cpu/stack.md](../../qurge/cpu/stack.md)を参照)  
- スタックフレーム: 呼び出された関数が確保する(「スタックフレーム」を参照)  

# スタックフレーム
関数は，自分のフレームを先頭で確保し(SPから引く)，戻る直前に解放する(SPへ足し戻す)．  
確保した直後のSPを基準にすると，フレームと戻り先は次のように並ぶ．  
SPはフレームの中で最も小さい番地を指す．  

| 位置 | 内容 |
|:-|:-|
| `SP+0` | ローカル変数の領域(Lバイト) |
| `SP+L` | レジスタの退避領域(Sバイト．`r{i}`の退避先は`SP+L+i*4`) |
| `SP+L+S` | 引数の領域(4×nバイト．宣言の順に1つ1ワード) |
| `SP+L+S+4n` | 戻り先(Pyntaxisの`call`が積む) |

- ローカル変数の領域には，関数の中で宣言したすべてのローカル変数に，宣言ごとに別の位置を割り当てる  
- L・S・nは，コンパイル時に決まる  
- L・S・nがすべて0の関数は，フレームを持たない  

# 呼び出し規約
## 引数の渡し方
呼び出し元はSPを動かさずに引数を書き込み，Pyntaxisの`call`で呼び出す．  
引数がn個のとき，i番目(先頭を0とする)の引数は`SP-4-4n+4i`番地へ書き込む．  

呼び出し元のSPを基準にすると，呼び出し先がフレームを確保した後のスタックは次のようになる．  
引数と戻り先は，呼び出し元のフレームより下にあり，呼び出し先のフレームの一部になる．  

| 呼び出し元のSPからの位置 | 内容 | 書き込むもの |
|:-|:-|:-|
| `SP+0`以上 | 呼び出し元のフレーム | 呼び出し元 |
| `SP-4` | 戻り先 | Pyntaxisの`call` |
| `SP-4-4n`〜`SP-8` | 引数 | 呼び出し元 |
| それより下 | 呼び出し先の退避領域とローカル変数の領域 | 呼び出し先 |

引数の値は，次のように書き込む．  

- 整数: 引数の型の幅で書き込む([pynesis/language/type.md](../language/type.md)の「読み出しと格納」を参照)  
- ポインタ: 番地を1ワードで書き込む  
- 配列: 先頭要素の番地を1ワードで書き込む  

## 戻り値の受け取り方
戻り値は，RAX(`6'h1e`)に入れて返す．  

## 引数に関数呼び出しを含む場合
引数の書き込み先は，呼び出し元のSPより下にある．  
この位置は，引数の式の中で呼ぶ関数の戻り先とフレームが使う位置と重なる．  

`f(1, g(2))`を例にすると，次のようになる．  

1. 引数の式の値を求めた時点で書き込むと，`1`を`f`の1番目の引数の位置へ書き込む  
2. 次に`g(2)`を呼ぶと，`g`の戻り先と引数`2`が同じ位置へ書き込まれ，`1`が壊れる  

このため，関数呼び出しを含む引数がある場合は，その引数までの値をレジスタに残したまま求める．  
すべての呼び出しから戻った後に，残しておいた値をまとめて書き込む．  
組み込み関数`syscall`を含む引数も，システムコールの値をSPより下へ並べるため，同じように扱う．  

## 関数ポインタを通した呼び出し
引数の渡し方と戻り値の受け取り方は，関数名による呼び出しと同じである．  
呼び出す関数の番地(関数ポインタの値)は，引数より先にレジスタへ読み込み，そのレジスタを飛び先にしたPyntaxisの`call`で呼び出す．  

# 実行ファイルのmain
## 引数の受け取り
実行ファイルの`main`は，ほかの関数と同じ規約で引数を読む．  
シェルは`main`を呼び出さずに実行を始めるが，`argc`と`argv`を，この規約で2つの引数を渡して呼び出した場合と同じ位置に置く([qosmos/kernel/exec.md](../../qosmos/kernel/exec.md)の「引数の置き方」を参照)．  
このため，`main`は`int main(int argc, char **argv)`の引数として受け取れる．  

## 終了
実行ファイルの`main`は，Qosmosの「実行ファイルの終了」の機能([qosmos/program/syscall.md](../../qosmos/program/syscall.md)を参照)を呼んで終える．  
`return`文の位置と，最後の文が`return`文でない`main`の終わりで，フレームを解放してからこの機能を呼ぶ．  
戻り値を，終了状態としてこの機能へ渡す．  
値の並べ方は，組み込み関数`syscall`と同じである(「システムコールの呼び出し」を参照)．  

# システムコールの呼び出し
組み込み関数`syscall(number, a, b, c, d)`([pynesis/language/builtin.md](../language/builtin.md)を参照)は，Qosmosの取り決めに従って値を並べ，Pyntaxisの`syscall`を実行する．  
取り決めでは，Pyntaxisの`syscall`を実行する時点のSPから，戻り値の置き場・機能の番号・引数`a`〜`d`の6つの値を4バイトずつ並べる([qosmos/program/syscall.md](../../qosmos/program/syscall.md)の「アセンブリから呼ぶ場合」を参照)．  

生成する命令の順は次のとおりである．  

1. `number`と`a`〜`d`の式の値を，順に求める  
2. SPから24バイト(4バイト×6つの値)を引く  
3. SP+4へ機能の番号を，SP+8〜SP+20へ`a`〜`d`を書き込む  
4. Pyntaxisの`syscall`を実行する  
5. SP+0(戻り値の置き場)から戻り値を読み，SPへ24バイトを足し戻す  

- 値を求めてからSPを動かす理由: 値を求める間にローカル変数を読み書きする位置は，フレームを確保した時点のSPを基準にしているため  
- SPを動かしてから書き込む理由: 取り決めが，SPからの位置で値を受け渡すため  

OSは，戻るときにレジスタの値を保たない([qosmos/program/syscall.md](../../qosmos/program/syscall.md)を参照)．  
このため，式の途中で組み込み関数`syscall`を呼ぶ場合は，関数呼び出しと同じく，値を求め終えたレジスタをフレームの退避領域へ退避し，戻った後に復元する(「レジスタの使い方」を参照)．  

# レジスタの使い方
コンパイラは，汎用レジスタr0〜r15(`6'h00`〜`6'h0f`)を，式の値を求めるための一時的なレジスタとして使う．  
変数(const変数とハードウェア変数を除く)はメモリ上に置くため，変数の値をレジスタに持ち続けることはない．  
式の値は，r0から順に割り当てて求める．式の複雑さの上限は，[pynesis/language/limit.md](../language/limit.md)の「式の複雑さ」を参照．  

コンパイラが生成するアセンブリでは，r0〜r15の値は，関数呼び出しをまたぐと保たれない．  
どの関数も，r0から順にレジスタを使うためである．  
式の途中で関数を呼ぶ場合は，呼び出しの後も使う値のレジスタを，呼び出しの前に自分のフレームの退避領域へ退避し，戻った後に復元する．
