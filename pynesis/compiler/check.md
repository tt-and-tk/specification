# 量的制限の検査
コンパイラは，プログラムが量的制限([pynesis/language/limit.md](../language/limit.md)を参照)に収まるかを検査し，収まらない場合はコンパイルエラーにする．量的制限の項目ごとに，次のように検査する．  

- 命令数: ROM用では，生成した命令の数を上限と比べる．実行ファイル用では，命令数を単独では比べない．代わりに，変数に使えるメモリの検査に，命令列の大きさを含める  
- 変数に使えるメモリ: グローバル変数の大きさにスタックの量の見積もり(「スタックの量の見積もり」を参照)を足し，実行ファイル用ではさらに命令列の大きさを足して，出力先ごとの置ける範囲と比べる  
- 式の複雑さ: 式ごとに，同時に使う汎用レジスタの本数を数え，16本と比べる  

# 検査に使う値
検査では，次の値を使う．いずれも「決まり方」の列のハードウェアとQosmosの値から決まるため，それらを変える場合は，検査に使う値も合わせて変える．  

| 値 | 内容 | 決まり方 |
|:-|:-|:-|
| 16384命令 | ROM用の命令数の上限 | ROMの容量([qurge/rom.md](../../qurge/rom.md)の「容量と命令数の上限」を参照) |
| 32768バイト | ROM用で，グローバル変数とスタックを置ける範囲 | メモリの前半の大きさ([qurge/memory.md](../../qurge/memory.md)の容量64KBの半分) |
| 32512バイト | 実行ファイル用で，命令列・グローバル変数・スタックを置ける範囲 | Qosmosが割り振れる最も大きい領域(メモリの後半全体の32768バイト)から，引数の置き場256バイトを引いた値([qosmos/kernel/memory.md](../../qosmos/kernel/memory.md)の「領域の大きさ」を参照) |
| 4096バイト | 実行ファイル用で，スタックの量を見積もらない場合に検査に使うスタックの量 | Qosmosが，スタックの量が未定の実行ファイルに割り振るスタックの量([qosmos/program/executable.md](../../qosmos/program/executable.md)の「使えるメモリ」を参照) |

# スタックの量の見積もり
変数に使えるメモリの検査のために，プログラムが使うスタックの最大の量を見積もる．見積もれないプログラムの条件は，「見積もらない場合」を参照．見積もりでは，`main`から呼び出しの経路をたどり，最も深い経路で積む量を求める．関数は，スタックフレーム([pynesis/compiler/call.md](call.md)の「スタックフレーム」を参照)の下へ，次の処理ごとにスタックを積む．  

- 関数の呼び出し: 戻り先の4バイトと，呼び出された関数が積む量  
- 組み込み関数`syscall`: システムコールの値を並べる24バイト([pynesis/compiler/call.md](call.md)の「システムコールの呼び出し」を参照)  

関数が積む量は，次の式で求める．各処理で積む量は合計せず，最も多い1つだけを使う．各処理を終えるとSPは処理を始める前の値に戻るため，2つの処理が同時に積むことはない．SPの動かし方は，[pynesis/compiler/call.md](call.md)の「スタックフレーム」と「システムコールの呼び出し」を参照．  

```
関数が積む量 = スタックフレームの大きさ + 関数の中の各処理で積む量の最大値
```

## 関数ポインタを通した呼び出し
呼び出し先は実行時に決まる．このため，番地を取得された関数のうち，呼び出す関数ポインタと型が一致するものをすべて呼びうるものとして見積もる．実際より多く見積もることがある．  

## asm文の入力に書いた関数
asm文の入力に書いた関数名([pynesis/language/asm.md](../language/asm.md)の「関数名」を参照)は，雛形の命令がその関数を呼ぶかどうかによらず，asm文を書いた関数からの呼び出しとして見積もる．入力に書いた関数は，番地を取得された関数でもあるため，「関数ポインタを通した呼び出し」の呼び出し先にも含める．  

## 見積もりから外れる呼び出し先
次の呼び出し先は，見積もりに含まない．  

- 整数からキャストで作った関数ポインタの呼び出し先(プログラムにない番地のコードを含む)  
- 整数を経由したキャストで，型の異なる関数ポインタとして呼び出す関数  
- `main`: 呼び出せないため，見積もりの対象にもしない([pynesis/language/function.md](../language/function.md)の「main関数」を参照)  
- asm文の雛形に関数名を直接書いた`call`の呼び出し先: コンパイラは雛形の命令の内容を調べないため([pynesis/language/asm.md](../language/asm.md)を参照)  
- KENTRY・EENTRYが示す番地へ飛ぶ先(システムコールハンドラ・例外ハンドラ．[pynesis/language/hardware.md](../language/hardware.md)を参照): 飛び先は，実行時にKENTRY・EENTRYへ書き込んだ値で決まるため．ハンドラを関数ポインタを通して呼ぶ場合は，「関数ポインタを通した呼び出し」のとおりに見積もる  

## 見積もらない場合
次の場合は，スタックの量を見積もらない．  

| 場合 | 出力先 | 理由 |
|:-|:-|:-|
| 再帰呼び出しがある | どちらも | スタックの深さが実行時にしか決まらない |
| 関数ポインタの呼び出し先やasm文の入力に書いた関数を含めてたどった呼び出しが，循環する(関数の中のasm文の入力にその関数自身を書いた場合を含む) | どちらも | スタックの深さが実行時にしか決まらない |
| asm文を含む | 実行ファイル用 | 雛形に関数名を直接書いた`call`の呼び出し先を，見積もりに含められない(「見積もりから外れる呼び出し先」を参照) |
| 整数と関数ポインタの間でキャストする式を含む | 実行ファイル用 | 整数を経由して作った関数ポインタの呼び出し先を，見積もりに含められない(「見積もりから外れる呼び出し先」を参照) |

実行ファイル用だけで見積もらない場合があるのは，実行ファイル用の見積もりが，Qosmosが実行ファイルに割り振るスタックの量になるためである．見積もりから外れる呼び出し先を含むと，見積もりを超えてスタックを積みうる．  

見積もらない場合は，変数に使えるメモリを，出力先によって次のように検査する．  

- ROM用: スタックを含めずに，グローバル変数の大きさだけを比べる  
- 実行ファイル用: スタックの量を未定とし，4096バイトをスタックの量として比べる  

## 実行ファイル用の見積もりの下限
実行ファイル用では，見積もりを24バイト以上にする．`main`の終了のシステムコール([pynesis/compiler/call.md](call.md)の「実行ファイルのmain」を参照)は，フレームを解放した後に，SPから24バイトの値を並べるためである．
