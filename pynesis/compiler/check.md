# 量的制限の検査
検査する量的制限そのものは，[pynesis/language/limit.md](../language/limit.md)を参照．  

# 検査に使う値
検査に使う次の値は，メモリの容量([qurge/memory.md](../../qurge/memory.md)を参照)から決まる．  
容量を変える場合は，これらの値で行う検査も合わせて変える．  

- メモリの前半の32768バイトと，その上端の`0x8000`  
- 実行ファイル用の32512バイト  

# スタックの量の見積もり
ROM用で再帰呼び出しのないプログラムは，`main`から呼び出しの経路をたどり，最も深い経路で積むスタックの量を見積もる．  
1回の呼び出しで積む量は，戻り先の4バイトと，呼び出された関数のスタックフレームの大きさ([pynesis/compiler/call.md](call.md)の「スタックフレーム」を参照)である．  

## 関数ポインタを通した呼び出し
呼び出し先は実行時に決まる．  
このため，番地を取得された関数のうち，呼び出す関数ポインタと型が一致するものをすべて呼びうるものとして見積もる．  
実際より多く見積もることがある．  

## 見積もりから外れる呼び出し先
次の呼び出し先は，見積もりに含まない．  

- 整数からキャストで作った関数ポインタの呼び出し先(プログラムにない番地のコードを含む)  
- 整数を経由したキャストで，型の異なる関数ポインタとして呼び出す関数  
- `main`: 呼び出せないため，見積もりの対象にもしない([pynesis/language/function.md](../language/function.md)の「main関数」を参照)  

## 見積もらない場合
再帰呼び出しがある場合と，この見積もりの中で呼び出しが循環する場合は，スタックの深さが実行時にしか決まらないため，見積もらない．
