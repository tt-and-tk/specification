# 変数の配置
言語として書ける変数の種類と規則は，[pynesis/language/variable.md](../language/variable.md)を参照．  
この文書の命令は，コンパイラが出力するアセンブリ言語Pyntaxisの命令で書く．  

| 対象 | 置く場所 | 番地の決まり方 |
|:-|:-|:-|
| グローバル変数・文字列リテラル | 絶対番地 | コンパイル時に決まり，命令のイミディエイトデータとして埋め込む |
| ローカル変数・引数 | 呼び出しごとに確保するスタックフレーム | フレームの中の位置はコンパイル時に，実際の番地は実行時のSPで決まる |
| const変数 | 置かない | 参照する箇所へ値を直接埋め込む |

# グローバル変数の番地
グローバル変数と文字列リテラルは，置き始める番地から上へ順に割り当てる．  
割り当てた番地は，そのまま命令のイミディエイトデータとして埋め込む．  
置き始める番地は，出力先によって次のように決める．  

- ROM: 0番地である．コード生成の前に決まる  
- 実行ファイル: 命令の並びの直後(命令数×8の番地)である．番地は，シェルが実行ファイルに割り振る領域の先頭を0とする番地である([qurge/cpu/mode.md](../../qurge/cpu/mode.md)の「番地の変換」を参照)  

## 実行ファイルのグローバル変数の番地の決め方
実行ファイルでは，グローバル変数を置き始める番地は命令の並びの直後のため，コード生成を終えて命令数が決まるまで分からない．  
このため，いったんグローバル変数を0番地から置いて生成して命令数を数え，命令の並びの直後を置き始める番地にして生成し直す．  
番地は常に32ビットのイミディエイトデータとして埋め込むため，置き始める番地を変えても命令数は変わらない．  

## 再配置をしない理由
一般的なコンパイラのように，読み込む位置に合わせて番地を書き換える再配置は行わない．  
ROMのプログラムは，常に0番地から置かれる．  
実行ファイルは，領域の先頭を0とする番地で動き，CPUがメモリの番地へ変換する．  
このため，どちらも番地を書き換えずに動く．  

# ローカル変数と引数の番地
ローカル変数と引数は，呼び出しごとに確保するスタックフレーム([pynesis/compiler/call.md](call.md)の「スタックフレーム」を参照)に置く．  
フレームの中の位置はコンパイル時に確定するが，実際の番地は実行時のSP(`6'h10`)に応じて決まる．  
このため，SPからの相対位置を指定するPyntaxisの`rmr`/`wmr`で読み書きする([pyntaxis/language/instruction.md](../../pyntaxis/language/instruction.md)の「メモリ系(M系)」を参照)．  
この方式により，同じ関数が呼び出しの途中で再び呼ばれても，値が上書きされない．  

スタックは，次の番地から下へ伸びる．  

- ROM用: メモリの前半の上端([qurge/cpu/mode.md](../../qurge/cpu/mode.md)の「メモリを読み書きできる範囲」を参照)  
- 実行ファイル用: シェルが引数の置き場の中に決めたSP([qosmos/kernel/memory.md](../../qosmos/kernel/memory.md)の「実行ファイルの領域」を参照)  

ローカル変数・引数の番地を`&`で取ると，SPにフレームの中の位置を足した，実行時の番地になる．  

# 番地の揃え方
- スカラー変数と構造体のメンバは，4の倍数の番地に置く  
- 配列の要素は，要素のバイト数の倍数の番地に置く  

このため，これらの番地を指すポインタを通した読み書きでは，maskが同一ワードに収まる([qurge/memory.md](../../qurge/memory.md)の制約に当たらない)．  
`char`へのポインタは奇数番地も指すが，1バイトの読み書きは常に同一ワードに収まる．  
整数からキャストで作ったポインタなど，型の境界に揃わない番地を指すポインタを通した読み書きは，この制約に当たりうる([pynesis/language/type.md](../language/type.md)の「境界に揃わない番地を指すポインタ」を参照)．  

# 8/16ビットの要素の読み書き
`char`・`unsigned char`(1ワードに4要素)と`short`・`unsigned short`(1ワードに2要素)の配列の要素は，Pyntaxisの`rm`・`rmr`・`wm`・`wmr`のmaskで，そのバイトの位置を直接指定して読み書きする．  

読み出しでは，命令の番地とmaskを次のように指定する．  

- 番地: 要素の先頭のバイトの番地  
- mask: ビット0から，要素のバイト数だけビットを立てた値(8ビットの型は`0001`，16ビットの型は`0011`)  

maskのビットの位置は，メモリの番地とレジスタのバイトの位置に直接対応する([qurge/cpu/isa.md](../../qurge/cpu/isa.md)の「番地とmaskの詳細動作」を参照)．  
このため，要素の値はレジスタの下位8/16ビットへ入り，バイトの位置を揃えるシフト系の命令は要らない．  

上位ビットは，読み込みの命令が0で埋める．  
その後の扱いは型によって分かれる([pynesis/language/type.md](../language/type.md)の「読み出しと格納」を参照)．  

- `unsigned char`/`unsigned short`: 読み出した値をそのまま使う  
- `char`/`short`: 読み出した後に，シフト系の命令で符号拡張する  

# nullptrの値
ヌルポインタ`nullptr`の値`0x80000000`は，アドレスバスの幅を超える番地である．  
このため，どの変数の番地とも一致しない([pynesis/language/pointer.md](../language/pointer.md)の「nullptrの値」を参照)．  

# グローバル変数の初期値
初期化子のあるグローバル変数と，式の中の文字列リテラルの内容は，`main`の本体を実行する前に書き込む命令を生成する([pynesis/language/function.md](../language/function.md)の「mainより前に行う書き込み」を参照)．  

初期化子のないグローバル変数は，初期化しない．
