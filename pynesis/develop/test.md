# テスト
コンパイラのテストは，`pn2asm.exe`がPynesisのソースを変換したアセンブリが，期待値と一致するかを確かめる．  
`pn2mc.exe`は，ビルドできることだけを確かめ，自動テストの対象にしない．  
アセンブリから先の変換は，アセンブラのテスト([pyntaxis/develop/test.md](../../pyntaxis/develop/test.md)を参照)で確かめるためである．  

# 期待値
- 正常系: 期待値のアセンブリを手で用意する．コンパイラの出力に合わせてLFとし，改行コードも含めて比較する  
- 異常系: 期待するエラーメッセージを，ソースの1行目に`// expect: <メッセージ>`の形で書く  

異常系のメッセージは，手で書かず，`test_err.py`が表示する実際の出力から作る．  
出力中のファイルパスは，`test/`からの相対パスに直す．  
作ったメッセージが，2行目以降のコメントに書いたテストの意図と合っているかを確かめる．  

# テストの置き場所
| パス | 内容 |
|:-|:-|
| `test/src/` | 正常系の入力のソース(`NN.pn`)．ROM用としてコンパイルする |
| `test/src/include/` | 正常系のソースが`#include`で取り込むファイル(`NN_<役割>.pn`)．単独ではコンパイルしない |
| `test/asm/` | コンパイラが出力したアセンブリ(`NN.pt`)．テストで自動生成する |
| `test/asm_ans/` | 期待値のアセンブリ(`NN.pt`)．手で作る |
| `test/src_bin/`・`test/asm_bin/`・`test/asm_bin_ans/` | Qosmosの実行ファイル用(`--bin-mode`)としてコンパイルする，正常系の入力・出力・期待値．役割は`src/`・`asm/`・`asm_ans/`と同じで，連番は独立 |
| `test/src_err/` | 異常系の入力のソース(`NN.pn`)．1行目に書いたメッセージのコンパイルエラーになることを確かめる．連番は正常系の`src/`と独立 |
| `test/src_err/include/` | 異常系のソースが`#include`で取り込むファイル(`NN_<役割>.pn`)．単独ではコンパイルしない |
| `test/src_err_bin/` | Qosmosの実行ファイル用(`--bin-mode`)としてコンパイルする，異常系の入力．役割は`src_err/`と同じで，連番は独立 |
| `test/test.py` | 正常系のテストスクリプト |
| `test/test_err.py` | 異常系のテストスクリプト |
| `test/compiler_build.py` | 正常系・異常系のテストスクリプトが共通で使う，`pn2asm.exe`のビルドの処理 |

# 実行の仕方
`test/`で，次のスクリプトを実行する．  
各スクリプトは，最初に`pn2asm.exe`をビルドしてからテストするため，事前のビルドは要らない．  

- `python test.py`(正常系): `src/`(ROM用)・`src_bin/`(実行ファイル用)の全`.pn`を，それぞれ`asm/`・`asm_bin/`へ変換して，`asm_ans/`・`asm_bin_ans/`の期待値と比べる  
- `python test_err.py`(異常系): `src_err/`(ROM用)・`src_err_bin/`(実行ファイル用)の全`.pn`をコンパイルし，次のように判定する  
    - 合格: 1行目に書いたメッセージと一致するコンパイルエラー(終了コード1)になる．出力中のファイルパスは，`test/`からの相対パスに直してから比べる  
    - 失敗: クラッシュなど他の理由で終了する，または期待と異なるエラーになる
