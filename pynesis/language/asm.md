# asm文
asm文は，関数の本体にアセンブリ言語Pyntaxisの命令を直接書く文である．  
書いた命令は，asm文を書いた位置に，書いた順に出力される．  
Pynesisでは名前を書けない汎用レジスタr0〜r15とRAXを読み書きする処理に使う．  
例えば，割り込まれた時点のレジスタの値を保存する処理と，保存した値を戻す処理である．  
書き方は，GCCの拡張asmにならう(異なる点は「GCCのasmと異なる点」を参照)．  

```c
int saved[2];

void entry(void) {
    asm("wm fh r0 r0 %0\n"      // r0の値をsaved[0]へ書き込む
        "wm fh r0 r1 %1"        // r1の値をsaved[1]へ書き込む
        : : "i"(&saved[0]), "i"(&saved[1]));
}
```

# 書き方
asm文は，次の3つの形のどれかで書く．  

```
asm(雛形);
asm(雛形 : );
asm(雛形 : : 入力, 入力, ...);
```

各部分の内容は，次のとおりである．  

| 部分 | 内容 |
|:-|:-|
| 雛形 | 出力する命令を書いた文字列リテラル．行は`\n`で区切る．隣り合う文字列リテラルは1つに連結されるため，1行ずつ分けて書ける |
| 出力欄 | 1つ目のコロンの後ろ．何も書けない |
| 入力欄 | 2つ目のコロンの後ろ．雛形へ埋め込む値を，`"i"(式)`の形でカンマで区切って並べる(「入力」を参照) |

asm文は，関数の本体の中で文を書ける位置に書ける．  
関数の外には書けない．  
ROM用・実行ファイル用のどちらのプログラムにも書ける．  
`asm`は予約語であり，同じ名前の変数・関数は宣言できない．  

# 雛形
## 書ける行
雛形の各行には，次のどれかを書く．  

| 行 | 例 | 出力のされ方 |
|:-|:-|:-|
| 命令 | `wm fh r0 r1 %0` | 字下げして出力する |
| 局所ラベル | `.loop%=:` | 行頭に出力する |
| コメントだけの行 | `; 説明` | 字下げして出力する |
| 空行 | | 出力しない |

- 各行の前後の半角空白を除いてから出力する．このため，雛形の中で字下げを揃える必要はない  
- `;`より前に`:`を含む行を，局所ラベルの行とみなす．アセンブラと同じ見分け方である  
- 命令の行と局所ラベルの行には，`;`以降にコメントを書ける  

コンパイラは，命令の名前と引数を検査しない．  
誤りは，アセンブラが検出する．  
各命令の書き方は，[pyntaxis/language/instruction.md](../../pyntaxis/language/instruction.md)を参照．  

## 書けないもの
次のものを雛形に書くと，コンパイルエラーになる．  

| 書けないもの | 理由 |
|:-|:-|
| 関数ラベル(名前が`.`で始まらないラベル) | asm文を書いた関数が，その位置で2つの関数に分かれるため |
| 局所ラベルの行の，ラベルの名前と`:`のほかの文字(`.a: nop`・`.a :`) | アセンブラは`:`より前を空白も含めてラベルの名前として読み，`:`より後ろを捨てるため．`:`の後ろに命令を続けて書くと，その命令が消える |
| `.global`宣言 | プログラムの先頭にだけ書けるため |
| `.L`の直後に数字か`%`が続く名前(`.L3`・`.L%=`) | コンパイラが生成する局所ラベル(`.L0`，`.L1`，…)と重なりうるため．定義だけでなく，参照もできない |
| 改行以外の制御文字(タブなど) | アセンブラはタブに対応せず，ほかの制御文字も行の中に置けないため |

## 置き換え
雛形の中の`%`で始まる部分は，次の表のとおりに置き換えてから出力する．  
それ以外の文字は，そのまま出力する．  

| 書き方 | 置き換える内容 |
|:-|:-|
| `%`に続く数字(`%0`・`%10`) | その番号の入力の値．番号は0から数える．数字は続く限り1つの番号として読む(`%10`は10番目の入力) |
| `%=` | asm文ごとに異なる番号(「%=の番号」を参照) |

- コメントの中の`%`も置き換える  
- 入力の数以上の番号を書くと，コンパイルエラーになる  
- 数字も`=`も続かない`%`(`%%`を含む)を書くと，コンパイルエラーになる  
- 入力の値は，10進で書く(負の値は`-4`)．ただし，`0x80000000`以上の値は，16進で`80000000h`の形に書く．10進で書くと，アセンブラが受け付ける範囲を超えるためである  

### %=の番号
`%=`は，局所ラベルの名前を一意にするために使う．  
局所ラベルは，関数が異なっても同じ名前を使えない([pyntaxis/language/label.md](../../pyntaxis/language/label.md)を参照)．  
このため，固定の名前を書くと，同じ名前のラベルを持つasm文を2つ以上書いたときに重なる．  

```c
void wait(void) {
    asm("mov fh r0 r1 100\n"    // r1に回数を入れる
        "mov fh r0 r2 1\n"      // r2に減らす量を入れる
        "mov fh r0 r3 0\n"      // r3に終わりの値を入れる
        ".loop%=:\n"            // asm文ごとに異なる名前(.loop5など)になる
        "sub r1 r2 r1\n"
        "ne r1 r3 .loop%=");    // r1が0になるまで.loop%=へ戻る
}
```

`%=`の番号は，次のように決まる．  

- 1つのasm文の中では，何度書いても同じ番号になる  
- 番号は，コンパイラが生成する局所ラベル(`.L0`，`.L1`，…)と同じ連番から取る．このため，asm文の間で連続した値になるとは限らない．プログラム全体で重ならないことだけを保証する  
- `%=`を含まないasm文は，番号を使わない  

# 入力
入力欄には，雛形へ埋め込む値を`"i"(式)`の形で書く．  
`"i"`は，コンパイル時に決まる値であることを表す制約である．  
式には，次のどちらかを書く．  

- 整数の定数式([pynesis/language/variable.md](variable.md)の「定数式」を参照)  
- グローバル変数の番地を表す式  

グローバル変数の番地を表す式は，次のとおりである．  

- グローバル変数・その配列の要素(添字は定数式)・メンバの番地(`&g`・`&table[2]`・`&pairs[1].second`)  
- グローバルの配列の名前・メンバの配列の名前(先頭要素の番地)  
- この一覧の式に整数の定数式を足し引きした式(`table + 1`・`&table[3] - 1`)．ポインタの演算と同じく，指す先1個分のバイト数を単位にする([pynesis/language/pointer.md](pointer.md)の「演算」を参照)  

次のものは，入力に書けない．  

- ローカル変数・引数の番地: 実行時のSPで決まるため  
- 変数の値・関数の番地・文字列リテラル  

関数のPCは，雛形に関数名を直接書いて表す([pyntaxis/language/program.md](../../pyntaxis/language/program.md)の「関数のPC」を参照)．  
実行ファイル用のプログラムでは，グローバル変数を命令の並びの直後から置く．  
このため，入力に書いた番地もその位置の番地になる([pynesis/compiler/memory.md](../compiler/memory.md)の「グローバル変数の番地」を参照)．  

# レジスタ
asm文の命令は，r0〜r15とRAXを自由に使える．  
コンパイラは，文と文の間でこれらのレジスタに値を残さないためである([pynesis/compiler/call.md](../compiler/call.md)の「レジスタの使い方」を参照)．  
このため，asm文がこれらのレジスタを書き換えても，前後の文の処理は壊れない．  
逆に，asm文がレジスタへ書き込んだ値は，後ろの文へ引き継がれない．  

## 呼ばれた時点のレジスタを扱う位置
asm文の前にコンパイラの命令が出力されなければ，asm文の命令は，関数へ飛んできた時点のレジスタの値をそのまま扱える．  
フレームを持たない関数([pynesis/compiler/call.md](../compiler/call.md)の「スタックフレーム」を参照)の本体の最初の文が，この位置に当たる．  
ただし，`main`では，グローバル変数の初期値を書き込む命令が，asm文より前に出力される([pynesis/language/function.md](function.md)の「mainより前に行う書き込み」を参照)．  

# 書く人が守ること
コンパイラは，雛形の命令の内容を検査しない．  
このため，次のことは，asm文を書く人が守る．  

| 守ること | 理由 |
|:-|:-|
| フレームを持つ関数では，SPを書き換えない | コンパイラは，フレームの中の変数をSPからの位置で読み書きするため([pynesis/language/hardware.md](hardware.md)の「SPへの書き込み」を参照) |
| フレームを持つ関数では，`ret`などで関数を抜けない | フレームを解放しないまま戻るため |
| 実行ファイル用のプログラムでは，ユーザーモードで読み書きできないレジスタを使わない | コンパイルエラーにはならず，実行時にCPUの例外になるため([qurge/cpu/register.md](../../qurge/cpu/register.md)の「ユーザーモードでの制限」を参照) |
| `static`を付けた関数を雛形から呼ぶ場合は，コンパイラが付ける関数ラベルの名前(`step.0`など)で書く | 雛形の中の名前は置き換えないため([pynesis/compiler/call.md](../compiler/call.md)の「関数ラベル」を参照) |

雛形に書いた`call`は，コンパイラがスタックの量を見積もる際の呼び出しの経路に含まれない([pynesis/compiler/check.md](../compiler/check.md)の「スタックの量の見積もり」を参照)．  

# GCCのasmと異なる点
| GCCの書き方 | Pynesisでの扱い | 理由 |
|:-|:-|:-|
| 出力(`"=r"(x)`など)・入力の制約`"r"`(レジスタ) | 書けない | 雛形へは，コンパイル時に決まる値だけを埋め込むため |
| 入力の制約`"m"`(メモリ) | 書けない | グローバル変数とローカル変数で読み書きの命令(`rm`と`rmr`)が異なり，雛形の命令を変えずに埋め込めないため |
| 破壊するもの(3つ目のコロンの後ろ) | 書けない | コンパイラは，文と文の間でレジスタに値を残さず，変数を常にメモリから読み書きするため，知らせる必要がない |
| `volatile` | 書けない | コンパイラは最適化をせず，asm文を消したり動かしたりしないため |
| 関数の外のasm | 書けない | Pyntaxisでは，命令を関数の中にだけ書けるため |
| `1:`・`1b`・`1f`による局所ラベル | 書けない．`%=`を使う | Pyntaxisの局所ラベルは`.`で始まり，プログラム全体で一意にする必要があるため |
| `%%`(`%`そのもの) | 書けない | Pyntaxisは`%`を使わないため |
| 名前を付けた入力(`[name]`・`%[name]`) | 書けない | 入力は番号で指せるため |
| `asm goto` | 書けない | Pynesisには，飛び先にするラベル文がないため |
| `__asm__` | 書けない．`asm`と書く | 同じ文を表す名前を1つにするため |
| 入力欄のない`asm(雛形)`の`%` | 置き換えの指定として読む(GCCは，そのまま出力する) | Pyntaxisは`%`を使わないため，入力欄の有無で読み方を変える必要がない |
