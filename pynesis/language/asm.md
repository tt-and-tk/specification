# asm文
asm文は，関数の本体にアセンブリ言語Pyntaxisの命令を直接書く文である．コンパイラは，書かれた命令を，asm文を書いた位置へそのまま出力する．命令には，コンパイル時に決まる値を埋め込める(「置き換え」を参照)．書き方は，GCCの拡張asmにならう(異なる点は「GCCのasmと異なる点」を参照)．次の例は，r0とr1の値をグローバル変数`saved`へ書き込む．`%0`と`%1`は，入力に書いた`&saved[0]`と`&saved[1]`の番地に置き換わる．  

```c
int saved[2];                   // グローバル変数(番地はコンパイル時に決まる)

void entry(void) {
    asm("wm fh r0 r0 %0\n"      // r0の値をsaved[0]へ書き込む
        "wm fh r0 r1 %1"        // r1の値をsaved[1]へ書き込む
        : : "i"(&saved[0]), "i"(&saved[1]));
}
```

# 書き方
asm文は，次の4つの形のどれかで書く．  

```
asm(雛形);
asm(雛形 : );
asm(雛形 : : );
asm(雛形 : : 入力, 入力, ...);
```

各部分の内容は，次のとおりである．  

| 部分 | 内容 |
|:-|:-|
| 雛形 | 出力する命令を書いた文字列リテラル．行は`\n`で区切る．隣り合う文字列リテラルは1つに連結されるため，1行ずつ分けて書ける |
| 出力欄 | 1つ目のコロンの後ろ．GCCでは，命令の結果を変数へ受け取る出力を書く欄である．Pynesisは出力に対応していないため，空にする(「GCCのasmと異なる点」を参照) |
| 入力欄 | 2つ目のコロンの後ろ．雛形へ埋め込む値を，`"i"(式)`の形でカンマで区切って並べる(「入力」を参照)．入力を1つも書かない場合は，空にする |

asm文は，関数の本体の中で文を書ける位置に書ける．関数の外には書けない．ROM用・実行ファイル用のどちらのプログラムにも書ける．  
`asm`は予約語であり，同じ名前の変数・関数は宣言できない．  

# 雛形
## 書ける行
雛形の各行には，次のどれかを書く．  

| 行 | 例 | 出力のされ方 |
|:-|:-|:-|
| 命令 | `wm fh r0 r1 %0` | 字下げして出力する |
| 局所ラベル | `.loop%=:` | 行頭に出力する |
| コメントだけの行 | `; 説明` | 字下げして出力する |
| 空行 | | 出力しない |

命令の行と局所ラベルの行には，`;`以降にコメントを書ける．コンパイラは，`;`より前に`:`を含む行を局所ラベルの行とみなす．この見分け方は，アセンブラと同じである．各行は，前後の半角空白を除いてから出力する．このため，雛形の中で字下げを揃える必要はない．  

コンパイラは，命令の名前と引数を検査しない．誤りは，アセンブラが検出する．各命令の書き方は，[pyntaxis/language/instruction.md](../../pyntaxis/language/instruction.md)を参照．  

## 書けないもの
次のものを雛形に書くと，コンパイルエラーになる．  

| 書けないもの | 理由 |
|:-|:-|
| 関数ラベル(名前が`.`で始まらないラベル) | asm文を書いた関数が，その位置で2つの関数に分かれるため |
| 局所ラベルの名前の中や，名前と`:`の間の空白(`.a :`) | アセンブラが，空白も含めてラベルの名前として読むため |
| 局所ラベルの`:`の後ろに続けた命令(`.a: nop`) | アセンブラが`:`より後ろを捨てるため，命令が消える．`;`以降のコメントは書ける |
| `.global`宣言 | プログラムの先頭にだけ書けるため |
| `.L`の直後に数字か`%`が続く名前(`.L3`・`.L%=`) | コンパイラが生成する局所ラベル(`.L0`，`.L1`，…)と重なりうるため．定義だけでなく，参照もできない |
| 改行以外の制御文字(タブなど) | アセンブラはタブに対応せず，ほかの制御文字も行の中に置けないため |

## 置き換え
雛形の中の`%`で始まる部分は，次の表のとおりに置き換えてから出力する．それ以外の文字は，そのまま出力する．  

| 書き方 | 置き換える内容 |
|:-|:-|
| `%`に続く数字(`%0`・`%10`) | その番号の入力の値．関数名の入力は，その関数の関数ラベルの名前(「関数名」を参照)．番号は0から数え，数字は続く限り1つの番号として読む(`%10`は番号10の入力) |
| `%=` | asm文ごとに異なる番号(「%=の番号」を参照) |

コメントの中の`%`も置き換える．整数の定数式の値と番地は10進で埋め込み，負の値には先頭に`-`を付ける(値が-4なら`-4`)．ただし，`0x80000000`以上の値は，16進で`80000000h`の形に埋め込む(10進で書くと，アセンブラが受け付ける範囲を超えるため)．  

次の場合は，コンパイルエラーになる．  

- 入力の数以上の番号を書いた場合  
- 数字も`=`も続かない`%`(`%%`を含む)を書いた場合  

雛形で使わない入力があっても，エラーにならない．  

### %=の番号
`%=`は，局所ラベルの名前を一意にするために使う．局所ラベルは，関数が異なっても同じ名前を使えない([pyntaxis/language/label.md](../../pyntaxis/language/label.md)を参照)．このため，固定の名前を書くと，同じ名前のラベルを持つasm文を2つ以上書いたときに重なる．  

```c
void wait(void) {
    asm("mov fh r0 r1 100\n"    // r1に回数を入れる
        "mov fh r0 r2 1\n"      // r2に減らす量を入れる
        "mov fh r0 r3 0\n"      // r3に終わりの値を入れる
        ".loop%=:\n"            // asm文ごとに異なる名前(.loop5など)になる
        "sub r1 r2 r1\n"
        "ne r1 r3 .loop%=");    // r1が0になるまで.loop%=へ戻る
}
```

`%=`の番号は，次のように決まる．  

- 1つのasm文の中では，何度書いても同じ番号になる  
- 番号は，コンパイラが生成する局所ラベル(`.L0`，`.L1`，…)と同じ連番から取る  
- `%=`を含まないasm文は，番号を使わない  

連番を局所ラベルと共有するため，番号はasm文の間で連続した値になるとは限らない．保証するのは，番号がプログラム全体で重ならないことだけである．  

# 入力
入力欄には，雛形へ埋め込む値を`"i"(式)`の形で書く．`"i"`は，コンパイル時に決まる値であることを表す制約である．式には，次のどれかを書く．  

- 整数の定数式([pynesis/language/variable.md](variable.md)の「定数式」を参照．const変数や乗除の演算子も使える)  
- グローバル変数の番地を表す式(「グローバル変数の番地」を参照)  
- 関数名(「関数名」を参照)  

## グローバル変数の番地
グローバル変数の番地は，ROM用・実行ファイル用のどちらでもコンパイル時に決まるため，入力に書ける([pynesis/compiler/memory.md](../compiler/memory.md)の「グローバル変数の番地」を参照)．番地を表す式は，次のとおりである．  

- グローバル変数・その配列の要素(添字は定数式)・メンバの番地(`&g`・`&table[2]`・`&pairs[1].second`)  
- グローバルの配列の名前・メンバの配列の名前(先頭要素の番地)  
- この一覧の式に整数の定数式を足し引きした式(`table + 1`・`&table[3] - 1`・`table + N * 2`)  

足し引きする整数は，ポインタの演算と同じく，指す先1個分のバイト数を単位にする([pynesis/language/pointer.md](pointer.md)の「演算」を参照)．  

## 関数名
入力に書いた関数名は，その関数の関数ラベルの名前に置き換える([pynesis/compiler/call.md](../compiler/call.md)の「関数ラベル」を参照)．関数ラベルの名前は，`call`の飛び先と，関数のPCを表すイミディエイトデータに書ける([pyntaxis/language/program.md](../../pyntaxis/language/program.md)の「関数のPC」を参照)．`static`を付けた関数は，関数ラベルの名前が関数名と異なる(`step.0`など)．このため，雛形から関数を呼ぶ場合や関数のPCを使う場合は，雛形に関数名を直接書かずに入力に書く．入力に書いた関数は，asm文を書いた関数から呼ばれうるものとして，スタックの量の見積もりに含める．このため，関数の中のasm文の入力にその関数自身を書くと，再帰呼び出しと同じく見積もりを行わなくなる([pynesis/compiler/check.md](../compiler/check.md)の「asm文の入力に書いた関数」を参照)．`main`は，番地を取れないため書けない([pynesis/language/function.md](function.md)の「main関数」を参照)．  

```c
static void step(void) {
}

void run(void) {
    asm("call %0" : : "i"(step));   // call step.0として出力する
}
```

## 書けない式
次のものは，入力に書けない．  

- ローカル変数・引数の番地(実行時のSPで決まるため)  
- 変数(const変数を除く)の値(実行時に決まるため)  
- 文字列リテラル  

# レジスタ
asm文の命令は，r0〜r15とRAXを自由に使える．コンパイラは，文と文の間でこれらのレジスタに値を残さず，各文で使うレジスタへ値を書き込んでから使うためである([pynesis/compiler/call.md](../compiler/call.md)の「レジスタの使い方」を参照)．このため，asm文がこれらのレジスタへ書き込んでも，前後の文の処理に影響を与えない．asm文で読んだレジスタの値をPynesisの処理で使うには，asm文の中でグローバル変数へ書き込む(「asm文」の見出しの直後の例を参照)．  
asm文でRAXへ書き込んだ値が関数の戻り値になることは，保証しない．戻り値は，`return`文で返す．  

## 呼ばれた時点のレジスタを扱う位置
asm文の前にコンパイラの命令が出力されなければ，asm文の命令は，関数へ飛んできた時点のレジスタの値をそのまま扱える．フレームを持たない関数([pynesis/compiler/call.md](../compiler/call.md)の「スタックフレーム」を参照)の本体の最初の文が，この位置に当たる．ただし，`main`では，初期化子を持つグローバル変数への書き込みと，式の中に現れる文字列リテラルの書き込みの命令が，asm文より前に出力される([pynesis/language/function.md](function.md)の「mainより前に行う書き込み」を参照)．この書き込みがある場合，`main`の最初のasm文では，呼ばれた時点のレジスタの値を扱えない．  

# 書く人が守ること
コンパイラは，雛形の命令の内容を検査しない．このため，次のことは，asm文を書く人が守る．  

| 守ること | 理由 |
|:-|:-|
| フレームを持つ関数では，SPを書き換えない | コンパイラは，フレームの中の変数をSPからの位置で読み書きするため([pynesis/language/hardware.md](hardware.md)の「SPへの書き込み」を参照) |
| フレームを持つ関数では，`ret`などで関数を抜けない | フレームを解放しないまま戻るため |
| 実行ファイル用のプログラムでは，ユーザーモードで読み書きできないレジスタを使わない | コンパイルエラーにはならず，実行時にCPUの例外になるため([qurge/cpu/register.md](../../qurge/cpu/register.md)の「ユーザーモードでの制限」を参照) |
| 実行ファイル用のプログラムでは，カーネルモードでだけ実行できる命令(`sysret`)を使わない | コンパイルエラーにはならず，実行時にCPUの例外になるため([qurge/cpu/mode.md](../../qurge/cpu/mode.md)の「ユーザーモードでの制限」を参照) |

雛形に関数名を直接書いた`call`の呼び出し先は，コンパイラがスタックの量を見積もる際の呼び出しの経路に含まれない([pynesis/compiler/check.md](../compiler/check.md)の「スタックの量の見積もり」を参照)．入力に書いた関数は含まれる(「関数名」を参照)．  

# GCCのasmと異なる点
| GCCの書き方 | Pynesisでの扱い | 理由 |
|:-|:-|:-|
| 出力(`"=r"(x)`など)・入力の制約`"r"`(レジスタ) | 書けない | 雛形へは，コンパイル時に決まる値だけを埋め込むため |
| 入力の制約`"m"`(メモリ) | 書けない | グローバル変数とローカル変数で読み書きの命令(`rm`と`rmr`)が異なり，雛形の命令を変えずに埋め込めないため |
| 破壊するもの(3つ目のコロンの後ろ) | 書けない | コンパイラは，文と文の間でレジスタに値を残さず，変数を常にメモリから読み書きするため，知らせる必要がない |
| `volatile` | 書けない | コンパイラは最適化をせず，asm文を消したり動かしたりしないため |
| 関数の外のasm | 書けない | Pyntaxisでは，命令を関数の中にだけ書けるため |
| `1:`・`1b`・`1f`による局所ラベル | 書けない．`%=`を使う | Pyntaxisの局所ラベルは`.`で始まり，プログラム全体で一意にする必要があるため |
| `%%`(`%`そのもの) | 書けない | Pyntaxisは`%`を使わないため |
| 名前を付けた入力(`[name]`・`%[name]`) | 書けない | 入力は番号で指せるため |
| `asm goto` | 書けない | Pynesisには，飛び先にするラベル文がないため |
| `__asm__` | 書けない．`asm`と書く | 同じ文を表す名前を1つにするため |
| 入力欄のない`asm(雛形)`の`%` | 置き換えの指定として読む(GCCは，そのまま出力する) | Pyntaxisは`%`を使わないため，入力欄の有無で読み方を変える必要がない |
