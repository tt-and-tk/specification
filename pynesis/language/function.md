# 関数
```c
int square(int x) {           // int型の引数を1つ取り，intを返す関数
    return x * x;
}

void clear(char *buf, int n) { // 戻り値のない関数．配列はポインタで受け取る
    for (int i = 0; i < n; i++) {
        buf[i] = 0;
    }
}

int fact(int n) {             // 再帰呼び出しもできる
    if (n <= 1) {
        return 1;
    }
    return n * fact(n - 1);
}
```

# 引数
- 引数は，スカラー型(整数型・ポインタ)をカンマで区切って並べる(`main`は「main関数」を参照)  
- 引数なしの宣言は，`(void)`と`()`の両方を書ける  
- 整数型の引数には，型の異なる整数の式も渡せる．渡す値は，引数の型で格納する([pynesis/language/type.md](type.md)の「読み出しと格納」を参照)  
- ポインタの引数には，指す先の型が符号も含めて同じポインタだけを渡せる([pynesis/language/pointer.md](pointer.md)の「型の一致」を参照)．配列を渡すと，先頭要素へのポインタが渡る(文字列リテラルは`char`の配列)  
- 配列の形の引数(`int arr[]`)は宣言できない．ポインタ(`int *arr`)で宣言する  

# 戻り値
- 戻り値型は，`void`とスカラー型(整数型・ポインタ)に対応する(`main`は「main関数」を参照)  
- `void`の関数は`return;`で，それ以外の関数は`return expr;`で呼び出し元へ戻る  
- `return`文の形が戻り値型と食い違う場合(`void`の関数の`return expr;`，それ以外の関数の`return;`)は，コンパイルエラーになる  

## 返せる値
- 戻り値型が整数の場合: 整数の式だけを返せる．ポインタ・`nullptr`を返すとコンパイルエラーになる  
- 戻り値型が整数の場合の幅: 整数どうしは型が異なっても返せ，戻り値型の幅への切り詰めも行わない(`char`の関数が`return 300;`と書けば，300がそのまま渡る)  
- 戻り値型がポインタの場合: 指す先の型が符号も含めて同じポインタ(配列は先頭要素へのポインタ)と`nullptr`だけを返せる．整数(`0`を含む)や，指す先の型が異なるポインタを返すと，コンパイルエラーになる([pynesis/language/pointer.md](pointer.md)の「型の一致」を参照)  

これらの検査は，すべての関数定義に対して行う．  
`main`から一度も呼ばれない関数も検査する．  

## returnを通らずに終わる場合
`return`文を通らずに関数の本体の終わりへ達した場合も，呼び出し元へ戻る．これはどの戻り値型の関数でも同じである．  

- 戻り値型が`void`以外の関数では，戻り値が設定されないため，呼び出し元が受け取る値は不定になる．`f();`のように戻り値を捨てる呼び出しであれば，そのまま使える  
- すべての経路で`return`文を通るかは，解析しない．このため，終わりへ達しうる関数もコンパイルでき，警告も出さない  
- `main`での`return`文と本体の終わりへの到達は，プログラムの終了を表す(「main関数」を参照)  

# 呼び出し
- 再帰呼び出しに対応する．直接の再帰も，`func1()`が`func2()`を呼び，その`func2()`が`func1()`を呼ぶような間接の再帰もできる  
- 呼び出しごとに引数・ローカル変数を別に確保するため，呼び出しの深さによらず値が保たれる([pynesis/language/variable.md](variable.md)の「ローカル変数の寿命」を参照)  
- 呼び出しの深さに固定の上限はなく，スタックの残り容量で決まる([pynesis/language/limit.md](limit.md)を参照)  
- 関数ポインタを通して呼び出すこともできる([pynesis/language/pointer.md](pointer.md)の「関数ポインタ」を参照)  
- 引数の受け渡しと戻り値の受け取りに使う命令は，[pynesis/compiler/call.md](../compiler/call.md)を参照  

# 関数に関する制限
- 関数のオーバーロードには対応しない．関数は関数名で一意に決まる  
- デフォルト引数には対応しない  

# main関数
`main`は，プログラムの開始点となる関数である．  
定義は必須であり，定義がない場合はコンパイルエラーになる．  

定義できる形は，出力先([pynesis/language/overview.md](overview.md)の「出力先」を参照)によって次のとおり決まる．  
これ以外の定義(ROMでの`int main(void)`，実行ファイルでの`void main(void)`・`int main(unsigned int argc, char **argv)`など)は，コンパイルエラーになる．  

| 出力先 | 定義できる形 | 理由 |
|:-|:-|:-|
| ROM | `void main(void)` | リセット後に実行が始まり，値を受け渡す呼び出し元が存在しないため |
| 実行ファイル | `int main(int argc, char **argv)`・`int main(void)` | シェルがコマンド名と引数を渡し，`main`の戻り値を終了状態として受け取るため(渡す値は[qosmos/program/executable.md](../../qosmos/program/executable.md)を参照)．シェルは常に引数を渡すが，使わないプログラムは`int main(void)`と書ける |

- 引数の名前は任意である．引数なしは，関数一般と同じく`(void)`・`()`のどちらでもよい  
- `argv`は，C言語のような配列の形(`char *argv[]`)では書けない．関数一般と同じく，配列の形の引数を宣言できないためである  
- `main`を直接呼び出すこと(`main();`)も，番地を取って関数ポインタから呼び出すことも，コンパイルエラーになる．`main`は開始点としてだけ実行する関数である  

## mainの終了
`main`での`return`文と，本体の終わりへの到達は，プログラムの終了を表す．  
終了したときの動作は，出力先によって異なる．  

- ROM: その場で止まる．CPUの停止とは異なり，同じ命令を実行し続けることで止まる([pyntaxis/language/target.md](../../pyntaxis/language/target.md)の「mainの終わり方」を参照)  
- 実行ファイル: 戻り値を終了状態としてシェルへ伝えて終わる([qosmos/user/shell.md](../../qosmos/user/shell.md)の「終了状態」を参照)．`return`文を通らずに本体の終わりへ達した場合は，シェルへ伝わる終了状態は不定になる  

## mainより前に行う書き込み
次の書き込みは，`main`の本体を実行する前に1回だけ行う．  

- 初期化子を持つグローバル変数への書き込み  
- 式の中に現れる文字列リテラル(名前のないグローバルの`char`の配列)の書き込み  

プログラムの中で`main`より前に実行されるコードはないため，これらの書き込みがプログラムの中で最初に実行される．
