# ハードウェア変数
CPUのレジスタと，ボード上の周辺機器を操作するレジスタを，あらかじめ定義した変数(ハードウェア変数)として提供する．  
通常の変数と同じく代入・参照でき，コンパイラが対応するレジスタへの読み書きの命令に変換する．  

```c
LED = 0x0f;                        // LEDのレジスタへの書き込み
int x = DIPSW;                     // DIPスイッチのレジスタからの読み込み
KENTRY = (unsigned int)handler;    // システムコールハンドラの番地(関数の番地)の書き込み
```

ハードウェア変数を読み書きするのは，カーネルモードで動くOSだけである．  
実行ファイルはユーザーモードで動かす前提のため，ハードウェア変数はどれも読み書きできない．  
読み書きする式を書くと，その時点でコンパイルエラーになる．  
型だけを使う`sizeof`は，読み書きに当たらない．  

# 変数の一覧
読み書きの可否は，カーネルモードでのものである．  
可否は[qurge/cpu/register.md](../../qurge/cpu/register.md)に従い，違反した場合はコンパイルエラーになる．

| `ECAUSE` | `6'h16` | 例外の原因 | 可 | 不可 |
| `BTN` | `6'h20` | タクトスイッチ×4 | 可 | 不可 |
| `DIPSW` | `6'h21` | DIPスイッチ×2 | 可 | 不可 |

- 型はすべて`unsigned int`として扱う．番地や周辺機器の状態を表すビット列として使うためである(演算の結果への影響は[pynesis/language/type.md](type.md)の「型変換」を参照)  
- 関数の番地をKENTRY・EENTRYへ書き込むには，`(unsigned int)handler`のようにキャストする([pynesis/language/type.md](type.md)の「キャスト」を参照)  
- レジスタに置かれ，メモリ上の番地を持たないため，`&`で番地を取ることはできない  
- 同じ名前の変数・関数は宣言できない([pynesis/language/variable.md](variable.md)の「スコープ」を参照)  

## 変数にしないレジスタ
次のレジスタは，変数として公開しない(各レジスタの制約は[qurge/cpu/register.md](../../qurge/cpu/register.md)を参照)．  

- CPUのレジスタ(`6'h00`〜`6'h1f`)のうち，次のもの  
    - r0〜r15・RAX: コンパイラが式の評価と戻り値の受け渡しに使う([pynesis/compiler/call.md](../compiler/call.md)の「レジスタの使い方」を参照)  
    - 空き番地(`6'h17`〜`6'h1b`): ハードウェア上で読み書きが禁止されている  
    - FLG・RSI: 名前が示す機能を持たず，使い道がない  
    - PC: 書き込みが禁止されている．読み出すとその命令自身の番地が返るが，関数の番地は関数名から得られるため使い道がない  
- 周辺機器の範囲(`6'h20`以降)の空き番地: ハードウェア上で読み書きが禁止されている  
- 使わない番地(`6'h2d`): ハードウェア上は書き込みを受け付けるが，どのピンにも出力せず使い道がない  

# SPへの書き込み
SPは，OSがスタックを切り替えるために使う．  

- SYSCALL・例外でカーネルモードへ入った直後: カーネルのスタックへ切り替える．`user_sp = SP; SP = kernel_sp;`のように書く  
- `sysret()`でユーザーモードへ移る前: 領域の中のスタックへ切り替える  

切り替えが要る理由は，[qurge/cpu/mode.md](../../qurge/cpu/mode.md)の「動作状態の切り替え」を参照．  

## SPへ書き込める関数
ROM用にコンパイルする場合，SPへ書き込める(代入・複合代入・`++`/`--`)のは，フレームを持たない関数だけである．  
それ以外の関数で書き込むと，コンパイルエラーになる．  
フレームを持たないのは，引数・ローカル変数を持たず，式の評価でレジスタを退避しない関数である([pynesis/compiler/call.md](../compiler/call.md)の「スタックフレーム」を参照)．  

フレームを持つ関数で禁止するのは，コンパイラもSPをフレームの確保と参照に使うためである．  
SPを書き換えた後も，コンパイラはフレーム上の変数をSPからの位置で読み書きし，戻る直前にはフレームの大きさだけSPを戻す．  
このため，書き換えた後のSPを基準にして，フレームとは別の領域を壊してしまう．
