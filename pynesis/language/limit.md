# 量的制限
プログラムの大きさには次の上限がある．  
上限を超えるとコンパイルエラーになるものと，コンパイラが検査せず実行時に誤った動作になるものがある．  

| 制限 | 上限 | 超えた場合 |
|:-|:-|:-|
| 命令数 | ROM用は16384命令，実行ファイル用は4064命令 | コンパイルエラー |
| 変数に使えるメモリ | 出力先によって異なる(「変数に使えるメモリ」を参照) | 検査できる範囲でコンパイルエラー |
| 関数呼び出しの深さ | 固定の上限はなく，スタックの残り容量で決まる | 検査できる範囲でコンパイルエラー |
| 式の複雑さ | 汎用レジスタ16本(r0〜r15)で評価できる範囲 | コンパイルエラー |

# 命令数
- ROM用: ROMの容量で決まる([qurge/rom.md](../../qurge/rom.md)の「容量と命令数の上限」を参照)  
- 実行ファイル用: 実行ファイルの領域に収まる命令数で決まる([pyntaxis/language/target.md](../../pyntaxis/language/target.md)の「命令数の上限」を参照)．グローバル変数と合わせた大きさも検査する(「変数に使えるメモリ」を参照)  

# 変数に使えるメモリ
グローバル変数とスタックを置ける範囲は，出力先によって異なる．  

- ROM用: グローバル変数は0番地から上へ，スタックはメモリの前半の上端(`0x8000`)から下へ伸びる．両者の合計が，メモリの前半(32768バイト)に収まる必要がある([qurge/cpu/mode.md](../../qurge/cpu/mode.md)の「メモリを読み書きできる範囲」を参照)  
- 実行ファイル用: 命令の並びは領域の先頭から，グローバル変数はその直後から上へ伸びる．両者の合計が，領域のうち引数の置き場より手前の32512バイトに収まる必要がある．スタックは，シェルが引数の置き場の中に決めたSPから，グローバル変数の手前までを使える([qosmos/kernel/memory.md](../../qosmos/kernel/memory.md)の「実行ファイルの領域」を参照)  

## コンパイルエラーになる場合
- グローバル変数だけで，置ける範囲(ROM用はメモリの前半の32768バイト，実行ファイル用は引数の置き場より手前の32512バイト)を超える場合  
- ROM用で，再帰呼び出しのないプログラムのグローバル変数とスタックの合計が，メモリの前半を超える場合  
- 実行ファイル用で，グローバル変数と命令の並び(1命令8バイト)の合計が，32512バイトを超える場合  

スタックの量は，呼び出しの経路から見積もる(見積もり方は[pynesis/compiler/check.md](../compiler/check.md)の「スタックの量の見積もり」を参照)．  

## 検査しない場合
次の場合は，コンパイラがスタックの量を検査しない．  
スタックが変数と重なっても，CPUは検出しない([qurge/cpu/stack.md](../../qurge/cpu/stack.md)の「深さの上限」を参照)．  

- ROM用で，再帰呼び出しがある場合: スタックの深さが実行時にしか決まらないため  
- ROM用で，見積もりの中で呼び出しが循環する場合: 関数ポインタの呼び出し先を見積もった結果，呼び出しが循環する場合も，同じ理由で検査しない  
- 実行ファイル用: スタックの空きは，シェルが置くコマンド名と引数の長さによって決まるため  

# 式の複雑さ
1つの式は，汎用レジスタ16本(r0〜r15)で評価できる範囲に収める必要がある．  
コンパイラが式ごとに検査し，超えるとコンパイルエラーになる．  

- 入れ子が深い式ほど，多くのレジスタを同時に使う  
- 入れ子が浅くても，組み込み関数のように評価に多くの作業用の値を使う構文を含むと，上限に達しうる  
- 評価の途中の値を，足りなくなった分だけメモリへ逃がして評価を続けることはしない([pynesis/compiler/call.md](../compiler/call.md)の「レジスタの使い方」を参照)
