# 量的制限
プログラムの大きさには次の上限がある．  
上限を超えるとコンパイルエラーになるものと，コンパイラが検査せず実行時に誤った動作になるものがある．  

| 制限 | 上限 | 超えた場合 |
|:-|:-|:-|
| 命令数 | ROM用は16384命令．実行ファイル用は，グローバル変数が無い場合に4064命令で，グローバル変数を置くほど少なくなる | コンパイルエラー |
| 変数に使えるメモリ | 出力先によって異なる(「変数に使えるメモリ」を参照) | 検査できる範囲でコンパイルエラー |
| 関数呼び出しの深さ | 固定の上限はなく，スタックの残り容量で決まる | 検査できる範囲でコンパイルエラー |
| 式の複雑さ | 汎用レジスタ16本(r0〜r15)で評価できる範囲 | コンパイルエラー |

# 命令数
命令数の上限は，出力先によって次のとおり決まる．  

- ROM用: ROMの容量で決まる([qurge/rom.md](../../qurge/rom.md)の「容量と命令数の上限」を参照)  
- 実行ファイル用: 命令の並びとグローバル変数の合計が，置ける範囲に収まる必要がある(「変数に使えるメモリ」を参照)．このため上限は，グローバル変数が無い場合に4064命令で，グローバル変数を置くほど少なくなる．4064命令は，アセンブラの上限と一致する([pyntaxis/language/target.md](../../pyntaxis/language/target.md)の「命令数の上限」を参照)  

# 変数に使えるメモリ
グローバル変数とスタックを置ける範囲は，出力先によって異なる．  
次の図は，出力先ごとのメモリ上の配置を，番地の大きい側を上にして示す．  

```
ROM用(メモリの番地)

0x8000 +-------+ <- SPの初期値
       |   |   |    スタック(下へ伸びる)
       |   v   |
       |       |    空き
       |   ^   |
       |   |   |    グローバル変数(上へ伸びる)
0x0000 +-------+
```

```
実行ファイル用(領域の中の番地)

0x8000 +-------+
       |       |    引数の置き場(コマンド名と引数)
       |-------| <- SPの初期値(シェルが引数の置き場の中に決める)
       |   |   |    スタック(下へ伸びる)
0x7F00 +---|---+
       |   v   |
       |       |    空き
       |   ^   |
       |   |   |    グローバル変数(上へ伸びる)
       +-------+
       |       |    命令の並び
0x0000 +-------+
```

出力先ごとの範囲は，次のとおりである．  

- ROM用: グローバル変数とスタックの合計が，メモリの前半(`0x0000`〜`0x7FFF`の32768バイト)に収まる必要がある([qurge/cpu/mode.md](../../qurge/cpu/mode.md)の「メモリを読み書きできる範囲」を参照)  
- 実行ファイル用: 命令の並びとグローバル変数の合計が，引数の置き場より下の32512バイト(`0x0000`〜`0x7EFF`)に収まる必要がある．スタックは，SPの初期値からグローバル変数の上端までを使える([qosmos/kernel/memory.md](../../qosmos/kernel/memory.md)の「実行ファイルの領域」を参照)  

## コンパイルエラーになる場合
次の場合は，コンパイルエラーになる．  

- グローバル変数だけで，置ける範囲(ROM用はメモリの前半の32768バイト，実行ファイル用は引数の置き場より下の32512バイト)を超える場合  
- ROM用で，再帰呼び出しのないプログラムのグローバル変数とスタックの合計が，メモリの前半を超える場合  
- 実行ファイル用で，グローバル変数と命令の並び(1命令8バイト)の合計が，32512バイトを超える場合  

スタックの量は，呼び出しの経路から見積もる．関数ポインタを通した呼び出しは，番地を取得された関数のうち型が一致するものを，すべて呼び出し先として見積もる．見積もり方と，見積もりに含めない呼び出し先は，[pynesis/compiler/check.md](../compiler/check.md)の「スタックの量の見積もり」を参照．  

## 検査しない場合
次の場合は，コンパイラがスタックの量を検査しない．  
スタックが変数と重なっても，CPUは検出しない([qurge/cpu/stack.md](../../qurge/cpu/stack.md)の「深さの上限」を参照)．  

- ROM用で，再帰呼び出しがある場合: スタックの深さが実行時にしか決まらないため  
- ROM用で，関数ポインタを通した呼び出しを含めてたどると，呼び出しが循環する場合: 再帰呼び出しと同じ理由である．番地を取得された関数のうち型が一致するものをすべて呼び出し先とみなすため，実際には起きない循環もこれに当たる  
- 実行ファイル用: スタックの空きは，シェルが置くコマンド名と引数の長さによって決まるため  

# 式の複雑さ
1つの式は，汎用レジスタ16本(r0〜r15)で評価できる範囲に収める必要がある．  
コンパイラが式ごとに検査し，超えるとコンパイルエラーになる．  
評価の途中の値を，足りなくなった分だけメモリへ逃がして評価を続けることはしない．  

入れ子が深い式ほど，多くのレジスタを同時に使う．  
入れ子が浅くても，組み込み関数のように評価に多くの作業用の値を使う構文を含むと，上限に達しうる．
