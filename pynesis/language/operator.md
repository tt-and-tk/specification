# 演算子
| 分類 | 演算子 |
|:-|:-|
| 算術 | `+`，`-`，`*`，`/`，`%` |
| ビット | `&`，`\|`，`^`，`~`，`<<`，`>>` |
| 論理 | `&&`，`\|\|`，`!` |
| 比較 | `==`，`!=`，`<`，`>`，`<=`，`>=` |
| 代入 | `=`，`+=`，`-=`，`*=`，`/=`，`%=`，`&=`，`\|=`，`^=`，`<<=`，`>>=` |
| 単項 | `-`(単項マイナス)，`+`(単項プラス)，`++`，`--`，`*`(間接参照)，`&`(番地の取得)，`(型名)`(キャスト) |
| メンバ | `.`，`->` |
| その他 | `()`(関数呼び出し)，`[]`(添字)，`?:`(三項演算子)，`sizeof` |

演算の結果の型と，符号によって結果が変わる演算は，[pynesis/language/type.md](type.md)の「型変換」を参照．  
ポインタに使える演算子とその意味は，[pynesis/language/pointer.md](pointer.md)の「演算」を参照．  

1つの式の複雑さには上限があり，超えるとコンパイルエラーになる([pynesis/language/limit.md](limit.md)の「式の複雑さ」を参照)．  
カンマ演算子には対応しない([pynesis/language/unsupported.md](unsupported.md)を参照)．  

## 優先順位と結合規則
1つの式に複数の演算子を書くと，順位の小さい演算子ほど先にオペランドと組になる(`a + b * c`は`a + (b * c)`)．  

| 順位 | 演算子 | 結合規則 |
|:-|:-|:-|
| 1 | `()`(関数呼び出し)，`[]`(添字)，`.`，`->`，後置の`++`・`--` | 左から |
| 2 | 前置の`++`・`--`，`-`(単項マイナス)，`+`(単項プラス)，`!`，`~`，`*`(間接参照)，`&`(番地の取得)，`(型名)`(キャスト)，`sizeof` | 右から |
| 3 | `*`，`/`，`%` | 左から |
| 4 | `+`，`-` | 左から |
| 5 | `<<`，`>>` | 左から |
| 6 | `<`，`>`，`<=`，`>=` | 左から |
| 7 | `==`，`!=` | 左から |
| 8 | `&` | 左から |
| 9 | `^` | 左から |
| 10 | `\|` | 左から |
| 11 | `&&` | 左から |
| 12 | `\|\|` | 左から |
| 13 | `?:` | 右から |
| 14 | 代入演算子 | 右から |

結合規則は，同じ順位の演算子が並んだときに，どちら側の演算子から先にオペランドと組になるかを表す．  

- 左から: `a - b - c`は`(a - b) - c`になる  
- 右から: `a = b = c`は`a = (b = c)`に，`!~x`は`!(~x)`になる  

優先順位と結合規則はC言語と同じである．ただし，次の2つの書き方はC言語と異なり，構文エラーになる．  

- `?:`の2番目のオペランドに，括弧で囲まない代入式を書く書き方(`a ? b = 1 : c`)．`a ? (b = 1) : c`と書く  
- 後置の`++`・`--`の後ろに，`()`・`[]`・`.`・`->`を続ける書き方(`p++->x`)．`(p++)->x`と書く  

## 評価順
オペランドは，原則として左から順に評価する．例えば次のとおりである．  

- 二項演算子(`f() + g()`): `f`を呼んだ後に`g`を呼ぶ  
- 複合代入(`x += f()`): `x`の現在の値を読んだ後に`f`を呼ぶ  
- 関数呼び出し(`fp(a(), b())`): 呼び出す関数ポインタの値を求めた後，引数を左から順に評価する．組み込み関数の引数も左から順に評価する  

`=`と`[]`だけは，オペランドを次の順に評価する．  

- `=`: 右辺の値を求めた後に，左辺の番地を求める(`a[f()] = g()`では，`g`を呼んだ後に`f`を呼ぶ)．構造体の代入で右辺の内容を読む時点は，[pynesis/language/struct.md](struct.md)の「写し方」を参照  
- `[]`: 添字を評価した後に，添字を付ける式を評価する  

`++`・`--`・代入による書き換えは，そのオペランドを評価した時点で反映される．後に評価するオペランドは，書き換えた後の値を読む(`i`が`1`のとき，`i++ + i`は`3`になる)．  

次の演算子は，一部のオペランドを評価しないことがある．定数式では，評価しないオペランドも計算する([pynesis/language/variable.md](variable.md)の「定数式の値」を参照)．  

| 演算子 | 評価しないオペランド |
|:-|:-|
| `&&` | 左のオペランドが偽の場合の，右のオペランド(短絡評価) |
| `\|\|` | 左のオペランドが真の場合の，右のオペランド(短絡評価) |
| `?:` | 2番目と3番目のオペランドのうち，条件で選ばなかった方 |

# sizeof
```c
int table[10];
int a = sizeof(int);          // 4
int b = sizeof(table);        // 40(要素数×要素の型のバイト数)
int c = sizeof(char *);       // 4
```

`sizeof`は，次の2つの形にだけ対応する．  

- `sizeof(型名)`: 整数型・整数型へのポインタ・その2種類の型のtypedef名．`sizeof(unsigned int)`・`sizeof(char *)`・`sizeof(enum Tag)`のように書ける  
- `sizeof(名前)`: スカラー変数・配列変数・構造体変数(構造体の配列を含む)・列挙子の名前  

結果は常に`int`型の，コンパイル時に決まる定数である．  

## 返す値
| 対象 | 返す値 |
|:-|:-|
| スカラー変数 | 型のバイト数．1ワードを占める`char`のスカラー変数でも`1` |
| 配列 | 要素数×要素の型のバイト数 |
| 構造体変数 | 実際に占める大きさ(構造体1個分のワード数×4．構造体の配列はさらに×要素数．[pynesis/language/struct.md](struct.md)の「メモリ上の大きさ」を参照)．`struct Tag { int x; char c; };`の変数は`5`ではなく`8` |
| ポインタ | 指す先の型によらず`4` |
| 列挙子 | 型が`int`のため`4` |

スカラー変数と配列は，ワード境界を考慮しない論理的な大きさを返す．引数で受け取ったポインタから，指す先の配列のサイズは求められない．  

## 対応しない形
次の形には対応しない．  

- `sizeof(1 + 2)`のような任意の式: 型名と，変数・列挙子の名前だけに対応する．将来対応する予定である  
- `sizeof(構造体変数.member)`(構造体のメンバ単体の大きさ)  
- `sizeof(struct Tag)`・`sizeof(struct Tag *)`(型名としての構造体名)  
- 構造体・構造体へのポインタ・関数ポインタのtypedef名
