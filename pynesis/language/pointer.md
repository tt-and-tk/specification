# ポインタ
ポインタは，変数・配列の要素・構造体のメンバ・関数の番地を値として扱う型である．  
番地を関数へ渡せば，構造体やバッファを値のコピーなしに受け渡せる．  

```c
int x = 1;
int *p = &x;                  // xの番地
*p = 2;                       // pが指す先(x)へ書き込む

int add(int a, int b) {
    return a + b;
}
int (*op)(int, int) = add;    // 関数ポインタ(addの番地)

void main(void) {
    int y = op(1, 2);         // opが指す関数を呼び出す
    if (p != nullptr) {       // どこも指していないかを調べる
        *p = y;
    }
}
```

# 宣言
型名の後ろに`*`を書くと，その型を指すポインタになる．  
`*`を重ねると，ポインタを指すポインタになる．  

```c
int *p;                   // intを指すポインタ
unsigned char *buf;       // unsigned charを指すポインタ
struct Node *head;        // 構造体を指すポインタ
char **names;             // charを指すポインタを指すポインタ
int (*handler)(int, int); // int型の引数を2つ取りintを返す関数を指すポインタ(関数ポインタ)
void (*callback)(void);   // 引数も戻り値もない関数を指すポインタ
```

- ポインタは1ワード(4バイト)のスカラーとして扱う．変数(グローバル・ローカル)・関数の引数・戻り値・構造体のメンバ・配列の要素(`char *names[4]`)のいずれにもなれる  
- 関数ポインタは，関数の戻り値・配列の要素にはできない([pynesis/language/unsupported.md](unsupported.md)を参照)  
- 関数ポインタは`戻り値型 (*名前)(引数の型の並び)`の形で宣言する  
    - 引数の並びには，型だけを書いても，型に続けて名前を書いてもよい(名前は無視する)  
    - 引数なしは，`(void)`・`()`のどちらでもよい  
    - 引数の型には関数ポインタの宣言子も書け，名前を省ける(`int (*runner)(int (*)(int), int)`)  
- ポインタの宣言で使えない型は，[pynesis/language/unsupported.md](unsupported.md)を参照  

# nullptr
`nullptr`は，どこも指していないことを表す組み込みの定数である．  
予約語であり，同じ名前の変数・関数は宣言できない．  

- どのポインタ型(関数ポインタを含む)へも，代入・初期化・引数・戻り値として格納できる  
- `==`・`!=`で比較できる．加減算・大小比較・間接参照・キャストはできない  
- 初期化子を持たないポインタ変数の値は，ほかの変数と同じく保証されない(`nullptr`になるとは限らない)  

## nullptrの値
`nullptr`の値は，最上位ビットだけが立った`0x80000000`である．  

- メモリのアドレスバスの幅を超えるため，どの変数の番地とも関数の番地とも一致しない  
- `nullptr`の指す先を読み書きすると，CPUが例外として検出する(カーネルモードでは停止し，ユーザーモードでは例外ハンドラへ飛ぶ．[qurge/cpu/exception.md](../../qurge/cpu/exception.md)を参照)．このため，誤った参照がほかの変数を黙って壊すことはない  
- 32ビットの範囲の中央にある値のため，メンバや添字で番地を前後にずらして参照しても，ずらす量が2^31に近くない限りアドレスバスの幅を超えたままになる．このため，同じく例外として検出される  

C言語と異なり，ビット列は`0`ではない．  

- `nullptr`を入れたポインタを整数へキャストした値は`0x80000000`になる．ほかのポインタとの差・大小比較の結果は意味を持たない  
- 整数の`0`はヌルポインタとして扱わず，ポインタへ代入・比較できない  
- `(int *)0`は番地0を指すポインタであり，`nullptr`と等しくない  

# 番地の取得と間接参照
| 式 | 意味 |
|:-|:-|
| `&x` | `x`の番地．`x`は，変数・構造体の変数・配列の要素・構造体の配列の要素(`&arr[i]`)・構造体のメンバ(すべての形)・`*p`・`p[i]` |
| `*p` | `p`が指す先．読み書きでき，読み書きの幅と符号拡張は指す先の型に従う([pynesis/language/type.md](type.md)の「読み出しと格納」を参照)．`p`は関数ポインタ以外のポインタ(関数ポインタは`*`を付けずに呼び出す) |
| `p[i]` | `*(p + i)`と同じ．配列の要素と同じ形で読み書きでき，要素が構造体なら`p[i].m`でメンバを読み書きできる．`p`はポインタ変数に限らず，ポインタの値を持つ式であればよい(`s.items[i].m`・`(*pp)[i].m`) |
| `p->m` | `(*p).m`と同じ．`p`は構造体へのポインタ．`p->array[i]`のように，配列のメンバの要素も読み書きできる |

## 番地を取れないもの
- ハードウェア変数・const変数: メモリ上の番地を持たないため  
- 配列そのもの(`&arr`): 配列へのポインタに対応しないため．配列の名前をそのまま書けば，先頭要素の番地になる  
- 演算・関数呼び出しの結果: 値を置いた番地を持たないため  
- 関数ポインタ変数: 関数ポインタへのポインタに対応しないため  
- 関数名(`&add`): 関数の番地は関数名だけで書くため(「関数ポインタ」を参照)  
- `main`: プログラムの開始点としてだけ実行する関数であるため([pynesis/language/function.md](function.md)の「main関数」を参照)  

# 演算
| 演算 | 結果 | 備考 |
|:-|:-|:-|
| `p + n`，`n + p`，`p - n` | ポインタ | `n`は整数．指す先の型のバイト数(`char`は1，`short`は2，`int`・ポインタは4，構造体は1個分のワード数×4)を単位にずらす |
| `p - q` | `int` | 同じ型のポインタどうし．間の要素数(番地の差を，指す先のバイト数で割った値) |
| `p == q`，`p != q` | `int`(0/1) | 同じ型のポインタどうし，またはポインタと`nullptr` |
| `p < q`などの大小比較 | `int`(0/1) | 同じ型のポインタどうし．番地を符号なしの値として比べる |
| `p += n`，`p -= n`，`++`，`--` | ポインタ | 加減算と同じく，指す先の型のバイト数を単位に動かす |
| 真偽として使う位置(`if`・`while`・`do-while`・`for`の条件，三項演算子`?:`の条件，`!`・`&&`・`\|\|`のオペランド) | `!`・`&&`・`\|\|`は`int`(0/1) | `nullptr`なら偽，それ以外なら真として扱う(整数が`0`なら偽，それ以外なら真になるのと同じ)．`!p`は，`p`が`nullptr`なら1，それ以外なら0 |
| `c ? p : q` | ポインタ | 両方の分岐が同じ型のポインタどうし，またはポインタと`nullptr`のとき，そのポインタの型 |

- 表とキャスト([pynesis/language/type.md](type.md)の「キャスト」を参照)以外の演算(乗除・ビット演算・シフト・単項の`-`・`+`・`~`・`switch`の条件・配列の添字)には，ポインタを使えない  
- 加減算で番地が同じ配列の外を指すようになることや，範囲外の要素の読み書きは，配列の添字と同じく検査しない  

# 型の一致
- ポインタと整数の間に，暗黙の変換はない．整数をポインタへ，ポインタを整数へ代入・初期化・引数・戻り値として格納すると，コンパイルエラーになる．ポインタへの`0`も同じである(ヌルポインタは`nullptr`と書く)  
- 変換するにはキャストを使う([pynesis/language/type.md](type.md)の「キャスト」を参照)  
- ポインタどうしは，指す先の型が符号も含めて一致する場合だけ，格納・比較・差の計算ができる(`char *`と`unsigned char *`は別の型)  
- 関数ポインタどうしは，戻り値型と引数の型の並びがすべて一致する場合だけ同じ型とみなし，格納・比較ができる  
- 型の異なるデータのポインタどうしはキャストで，型の異なる関数ポインタどうしは整数を経由したキャストで変換する  

# 関数ポインタ
関数名を，呼び出しの括弧を付けずに書くと，その関数の番地(関数ポインタ)になる．  
関数ポインタは，関数と同じ形で呼び出す．  

```c
int (*op)(int, int) = add;     // addの番地
int x = op(1, 2);              // opが指す関数を呼び出す
```

- 関数の番地は関数名だけで書き，`&add`とは書けない．関数ポインタの呼び出しも`op(1, 2)`とだけ書き，`(*op)(1, 2)`とは書けない．C言語ではどちらの書き方もできるが，同じ値・同じ呼び出しの書き方を1つにするため  
- 関数の番地は，関数の先頭の命令を指すPCの値である(プログラムの先頭の命令から数えた，関数の先頭の命令の順番．[pyntaxis/assembler/encoding.md](../../pyntaxis/assembler/encoding.md)の「名前の解決」を参照)  
- 呼び出しの引数の数・型の検査と，引数の受け渡し・戻り値の受け取りは，関数を直接呼び出す場合と同じである([pynesis/language/function.md](function.md)を参照)  
- 変数・構造体のメンバに入った関数ポインタを呼び出せる(`op(1, 2)`・`handlers.on_key(c)`・`p->callback()`・`ops[i].apply(x)`)  
- 呼び出しの名前`f(...)`は，関数名なら関数を直接呼び，変数名ならその変数(関数ポインタでなければエラー)を通して呼ぶ．関数と同じ名前のローカル変数・関数の引数は宣言できない([pynesis/language/variable.md](variable.md)の「スコープ」を参照)ため，名前がどちらを指すかは一意に決まる  

関数ポインタに使える演算は，`==`・`!=`・真偽として使う位置(「演算」の表を参照)・呼び出し・キャストだけである．  
関数の番地はメモリの番地とは別の空間のため，加減算・大小比較・`++`/`--`はできない．  

# グローバル変数の初期化子
ポインタ型のグローバル変数の初期化子には，次の式を書ける．  
いずれも，番地がコンパイル時に確定する．  

- `nullptr`  
- グローバル変数・その配列の要素(添字は定数式)・メンバの番地(`&g`・`&table[2]`・`&pairs[1].second`)  
- グローバルの配列の名前・文字列リテラル(先頭要素の番地)  
- 関数名(関数の番地)  
- 整数の定数式をポインタへキャストした式(`(unsigned int *)0x8000`・`(void (*)(void))0x4000`)  
- この一覧の式に，整数の定数式を足し引きすることと，ポインタへキャストすることを，任意の順に何度でも重ねた式(`&g + 1`・`(char *)&g`・`(char *)(&g + 1) + 1`)  

変数の値(ほかのポインタ変数を含む)・関数呼び出し・`*`は，キャストしても書けない．  
番地の値は，ほかの初期化子と同じく`main`の本体を実行する前に書き込む([pynesis/language/function.md](function.md)の「main関数」を参照)．  
後で宣言した変数・関数の番地も書ける．
