# 名前とスコープ
```c
struct Item { int value; };      // 構造体名Item
enum Color { RED, GREEN };       // 列挙型名Colorと，列挙子RED・GREEN
int Item;                        // 構造体名と別の名前空間にあるため，同じ名前にできる

int total(void) {
    return count;                // 後で宣言したグローバル変数も参照できる
}
int count = 0;

void main(void) {
    int RED = 1;                 // 同じ名前の列挙子とは別の変数になる(シャドーイング)
}
```

スコープは，宣言した名前を参照できる範囲である．スコープには，ファイルの直下のグローバルスコープと，関数の本体やその中のブロックが作るブロックスコープがあり，それぞれ置ける宣言と名前の規則が異なる．  

この文書で「ファイル」と書いた場合は，`#include`で取り込んだファイルを含めない，1つのソースファイルを指す．  

# グローバルスコープ
ファイルの直下をグローバルスコープと呼ぶ．  

## 置ける宣言
グローバルスコープには，次の宣言を置ける．  

| 宣言 | 宣言する名前 | 詳細 |
|:-|:-|:-|
| グローバル変数の宣言(const変数を含む) | 変数名 | [pynesis/language/variable.md](variable.md) |
| 関数の定義 | 関数名 | [pynesis/language/function.md](function.md) |
| 構造体の定義 | 構造体名 | [pynesis/language/struct.md](struct.md) |
| 列挙型の定義 | 列挙型名と列挙子 | [pynesis/language/enum.md](enum.md) |

## 参照できる範囲
グローバルスコープの宣言は，宣言の順序によらず参照でき，後で宣言した名前も参照できる．  

グローバル変数と関数は，`static`を付けていなければ，取り込み元のファイルを含め，プログラムのどのファイルからでも参照できる．`static`を付けると，宣言したファイルの中からだけ参照できる(「static」を参照)．  

宣言の値やサイズを求めるためにその宣言自身へ戻ってくる循環した依存は，コンパイルエラーになる(`const int A = B; const int B = A;`，`int buf[sizeof(buf)];`)．  

## 同じ名前にできるかどうか
グローバルスコープの名前は，次の2つの名前空間のどちらかに属する．構造体のメンバ名は，これらと別に構造体ごとの名前空間にある．  

| 名前空間 | 属する名前 |
|:-|:-|
| 値の名前空間 | 変数名(const変数を含む)・関数名・列挙子・ハードウェア変数 |
| 型の名前空間 | 構造体名・列挙型名 |

同じ名前空間にある名前どうしは，「static」で定める組み合わせを除き，同じ名前にできない(コンパイルエラー)．例えば，別の列挙型の列挙子どうしや，構造体名と列挙型名は，同じ名前にできない．別の名前空間にある名前どうしは，同じ名前にできる(構造体名`Item`と変数`Item`)．  

## ハードウェア変数
ハードウェア変数([pynesis/language/hardware.md](hardware.md)を参照)は，コンパイラがあらかじめグローバルスコープの値の名前空間に置く変数であり，宣言しなくても参照できる．  

ハードウェア変数と同じ名前の変数(ローカル変数・引数を含む)・関数・列挙子は，グローバルスコープ・ブロックスコープのどちらにも宣言できない(コンパイルエラー)．同じ名前の変数を宣言してレジスタを誤って上書きすることを防ぐためである．  

## static
グローバル変数(const変数を含む)の宣言または関数の定義の先頭に`static`を付けると，その宣言は，宣言したファイルの中からだけ参照できる．  

```c
// lib/counter.pn
#pragma once
static int count = 0;            // lib/counter.pnの中からだけ参照できる
static void step(void) {         // lib/counter.pnの中からだけ呼び出せる
    count++;
}
int next(void) {                 // どのファイルからも呼び出せる
    step();
    return count;
}
```

```c
// main.pn
#include "lib/counter.pn"
int count;                       // lib/counter.pnのcountとは別の変数
void main(void) {
    count = next();              // stepとlib/counter.pnのcountは参照できない
}
```

`static`を付けた宣言と同じ名前にできるかどうかは，相手によって次のとおり決まる．  

- 同じファイルの宣言: 同じ名前にできない(コンパイルエラー)  
- 取り込んだファイルにある，`static`を付けていない宣言: 同じ名前にできない(コンパイルエラー)  
- 同じファイルにも取り込んだファイルにもない宣言と，取り込んだファイルにある`static`を付けた宣言: 同じ名前にできる．`static`を付けた宣言のファイルの中では，`static`を付けた宣言を参照する  

取り込んだファイルには，別のファイルを経由して取り込んだファイルと，`#pragma once`で2回目の取り込みを無視したファイルも含める．  

例えば，`main.pn`が`lib/counter.pn`を取り込む場合，`lib/counter.pn`の`static int count`と`main.pn`の`int count`は，同じ名前にできる．逆に，`main.pn`の`static int count`と`lib/counter.pn`の`int count`は，コンパイルエラーになる．  

`static`を書ける位置は，次のとおりである．これ以外の位置に書くと，コンパイルエラーになる．  

- グローバル変数の宣言または関数の定義の先頭(`const`・型名より前)にだけ書ける．`const static int`とは書けない  
- 構造体・列挙型の定義には書けない．構造体名・列挙型名・列挙子はプログラム全体で共有する．構造体の定義と同時に宣言する変数に付ける場合は，定義と変数の宣言を分ける(`struct S {...}; static struct S v;`)  
- `main`には付けられない．`main`はプログラムの開始点であり，どのファイルに書いても見つけられる必要があるため  

### C言語と異なる点
- `static`が閉じる範囲は，1つのファイルである．C言語はヘッダファイルの内容を取り込み元へそのまま展開するため，ヘッダファイルの`static`は取り込み元からも参照できる．Pynesisでは，取り込んだファイルの`static`は取り込み元から参照できない  
- ローカル変数には付けられない([pynesis/language/unsupported.md](unsupported.md)を参照)  

# ブロックスコープ
関数の本体と，その中の`{`と`}`で囲んだブロックは，それぞれブロックスコープを作る．例えば，関数の引数は，関数の本体を外側から囲むブロックスコープに属する．for文の初期化部で宣言した変数は，for文の中だけを範囲とするブロックスコープに属する．  

## 置ける宣言
ブロックスコープには，次の宣言だけを置ける．関数・構造体・列挙型の定義は，グローバルスコープにだけ書ける．  

| 宣言 | 宣言する名前 | 詳細 |
|:-|:-|:-|
| ローカル変数の宣言(const変数を含む) | 変数名 | [pynesis/language/variable.md](variable.md) |
| 関数の引数 | 引数名 | [pynesis/language/function.md](function.md) |

## 参照できる範囲
ローカル変数は，宣言した位置から，宣言したブロックスコープの終わりまでの間で参照できる．引数は，関数の本体全体から参照できる．  

## 同じ名前にできるかどうか
同じブロックスコープの中では，ローカル変数どうしを同じ名前にできない(コンパイルエラー)．同じ関数の引数どうしも同じ名前にできない．  

内側のブロックスコープで，外側のブロックスコープやグローバルスコープにある名前と同じ名前の変数を宣言すると，外側の名前とは別の変数として扱われる(シャドーイング)．  

### ローカル変数に付けられない名前
次のものと同じ名前のローカル変数・関数の引数は，宣言できない(コンパイルエラー)．  

- ハードウェア変数: 「ハードウェア変数」を参照  
- そのファイルから参照できる関数: 呼び出し`f(...)`の名前が，関数と関数ポインタの変数のどちらを指すかを一意にするため([pynesis/language/pointer.md](pointer.md)の「関数ポインタ」を参照)
