# 構造体
```c
struct Node {                 // 構造体の定義
    int value;
    char name[8];             // メンバに配列を持てる
    struct Node *next;        // 自身の構造体を指すポインタも持てる
};
struct Node nodes[4];         // 構造体の配列

void main(void) {
    struct Node n;
    n.value = 1;              // メンバを読み書きする
    nodes[0].next = &n;       // 構造体の番地を取る
    struct Node *p = nodes[0].next;
    p->value = 2;             // ポインタから指す先のメンバを読み書きする
}
```

メンバの構成を固定した`struct`に対応する．  
メンバは，スカラー型(整数型・ポインタ)または固定長の配列だけで構成する．  

# 定義
構造体の定義は，次の3つの形に対応する．  
いずれも，グローバルスコープの直下にだけ書ける．  

```c
struct Tag { int x; char c; };       // 構造体名の定義だけ(この時点では変数を作らない)
struct Tag2 { int x; } v1;           // 定義と同時に変数v1を宣言する
struct { int x; } v2;                // 無名の構造体．再利用できないため，変数の宣言は必須
```

# 変数の宣言
- `struct Tag v;`(1つの変数)と`struct Tag arr[N];`(配列．要素数は定数式で書く)の両方に対応する  
- グローバル・ローカルのどちらでも，1つの`struct`文で宣言できる変数は1つである  
- カンマ区切りで複数の変数を宣言すること(`struct Tag v1, v2;`)には対応しない．スカラー型の変数の宣言と同じく，カンマ区切り自体に対応しないためである  

# メンバの読み書き
メンバは次の形で読み書きできる．  

| 形 | 対象 |
|:-|:-|
| `v.scalar` | スカラーのメンバ |
| `v.array[i]` | 配列のメンバの要素 |
| `arr[i].scalar` | 構造体の配列の要素の，スカラーのメンバ |
| `arr[i].array[j]` | 構造体の配列の要素の，配列のメンバの要素 |
| `p->scalar`・`p->array[i]`・`p[i].scalar` | 構造体へのポインタ`p`が指す先のメンバ([pynesis/language/pointer.md](pointer.md)を参照) |

- メンバは，どの形でも関数の引数に渡せる．スカラーのメンバはその値を，配列のメンバは先頭要素へのポインタを渡す(組み込み関数に渡す場合は[pynesis/language/builtin.md](builtin.md)を参照)  
- 構造体の変数・構造体の配列の要素そのもの(`v`・`arr[i]`)は，メンバを介さずに直接読み書きすることはできない．`&v`・`&arr[i]`で番地を取ることはできる  

# 構造体そのものの値
構造体そのものを値として使うこと(関数の引数・戻り値・代入の右辺・式文などに書くこと)には対応しない．  
全メンバの値をまとめて読み書きする仕組みがないためである．  
メンバを読み書きするか，構造体へのポインタを引数・戻り値にして受け渡す．  

# メモリ上の大きさ
- 各メンバは，配列を含めワード単位で確保する  
- `char`/`short`型のスカラーのメンバも，1ワード(4バイト)を占める．構造体に属さないスカラー変数と同じ割り当て方である([pynesis/language/variable.md](variable.md)を参照)  
- 構造体の配列は，構造体1個分のワード数×要素数の領域を連続して確保する  

# 対応しない書き方
次のものには対応しない．  
将来対応する予定もない．  

- 入れ子の構造体(メンバに別の構造体そのものを持つこと)．構造体へのポインタはメンバにできる  
- メンバの初期化子
