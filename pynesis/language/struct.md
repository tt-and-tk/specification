# 構造体
```c
struct Node {                 // 構造体の定義
    int value;
    char name[8];             // メンバに配列を持てる
    struct Node *next;        // 自身の構造体を指すポインタも持てる
};
struct Node nodes[4];         // 構造体の配列

void main(void) {
    struct Node n;
    n.value = 1;              // メンバを読み書きする
    nodes[0].next = &n;       // 構造体の番地を取る
    struct Node *p = nodes[0].next;
    p->value = 2;             // ポインタから指す先のメンバを読み書きする
    nodes[1] = n;             // 構造体の全メンバを写す
    struct Node m = nodes[1]; // 構造体で初期化する
}
```

メンバの構成を固定した`struct`に対応する．メンバは，スカラー型(整数型・ポインタ)または固定長の配列だけで構成する．  

# 定義
構造体の定義は，次の3つの形に対応する．いずれも，グローバルスコープの直下にだけ書ける．  

```c
struct Tag { int x; char c; };       // 構造体名の定義だけ(この時点では変数を作らない)
struct Tag2 { int x; } v1;           // 定義と同時に変数v1を宣言する
struct { int x; } v2;                // 無名の構造体．再利用できないため，変数の宣言は必須
```

構造体名の名前空間と参照できる範囲は，[pynesis/language/scope.md](scope.md)の「グローバルスコープ」を参照．  

# 変数の宣言
`struct Tag v;`(1つの変数)と`struct Tag arr[N];`(配列．要素数は定数式で書く)の両方に対応する．グローバル・ローカルのどちらでも，1つの`struct`文で宣言できる変数は1つである．カンマ区切りで複数の変数を宣言すること(`struct Tag v1, v2;`)には対応しない．スカラー型の変数の宣言と同じく，カンマ区切り自体に対応しないためである．  

# メンバの読み書き
メンバは次の形で読み書きできる．  

| 形 | 対象 |
|:-|:-|
| `v.scalar` | スカラーのメンバ |
| `v.array[i]` | 配列のメンバの要素 |
| `arr[i].scalar` | 構造体の配列の要素の，スカラーのメンバ |
| `arr[i].array[j]` | 構造体の配列の要素の，配列のメンバの要素 |
| `p->scalar`・`p->array[i]`・`p[i].scalar` | 構造体へのポインタ`p`が指す先のメンバ([pynesis/language/pointer.md](pointer.md)を参照) |

メンバは，どの形でも関数の引数に渡せる．スカラーのメンバはその値を，配列のメンバ(`v.array`など)は配列変数と同じく先頭要素へのポインタを渡す([pynesis/language/array.md](array.md)の「値として使う配列」を参照)．組み込み関数に渡す場合は，[pynesis/language/builtin.md](builtin.md)を参照．  

構造体の変数・構造体の配列の要素そのもの(`v`・`arr[i]`)は，メンバを通して読み書きするほか，構造体の代入で全メンバをまとめて写せる(「構造体の代入」を参照)．`&v`・`&arr[i]`で番地を取ることもできる．  

# 構造体の代入
`L = R`と書くと，構造体`R`の全メンバを構造体`L`へ写す．`L`と`R`には，構造体の変数・構造体の配列の要素・構造体へのポインタが指す先(`v`・`arr[i]`・`*p`・`p[i]`)を書ける．`L`と`R`は，同じ構造体名の構造体でなければならない．無名の構造体は，定義ごとに別の構造体として扱う．  

```c
struct Node a;
struct Node b;
struct Node c;

void main(void) {
    b = a;                    // aの全メンバをbへ写す
    c = b = a;                // 連続代入: aをbへ写し，そのbをcへ写す
    struct Node d = a;        // ローカル変数をaで初期化する
}
```

構造体の代入式の値は，左辺の構造体である．このため，右辺に構造体の代入式を書いて連続代入できる．構造体の代入式は，式文とfor文の初期化部・更新部にも書ける．それ以外の位置で値を使うことはできない(「構造体そのものの値」を参照)．  

次の代入はコンパイルエラーになる．  

- 構造体名の異なる構造体どうしの代入，構造体と構造体以外の間の代入  
- 複合代入(`+=`など)．構造体には演算を定めていないためである  
- 構造体の配列そのものの代入．ほかの配列と同じく，配列そのものは代入の対象にできない([pynesis/language/array.md](array.md)を参照)  
- 右辺が三項演算子の代入(`c = s ? a : b;`)．三項演算子の各分岐は値として使うためである  

## 初期化
配列でない構造体のローカル変数は，宣言と同時に初期化できる(`struct Node d = a;`)．for文の初期化部の宣言でも同じである．初期化子には，代入の右辺と同じものを書ける．  

次の変数には，初期化子を書けない．  

- グローバル変数: 初期化子に書けるのは，値がコンパイル時に確定する式だけのため([pynesis/language/variable.md](variable.md)の「初期化」を参照)  
- 構造体の配列: 要素ごとの初期値を書く仕組みがないため  

## 写し方
構造体の代入と初期化は，構造体1個分の全ワードを，先頭のワードから順に1ワードずつ写す(「メモリ上の大きさ」を参照)．写す処理はループで繰り返すため，命令数は構造体の大きさによらない．  

写す前に，右辺の番地，左辺の番地の順に求める．右辺の内容は，左辺の番地を求めた後に読む．このため，左辺の番地を求める途中で右辺の構造体を書き換えると，書き換えた後の内容が写る(`arr[a.n++] = a;`では，`a.n`を増やした後の`a`が写る)．スカラーの代入は右辺の値を先に読むため，結果が異なる．  

両辺が同じ構造体の場合(`a = a;`)，値は変わらない．キャストしたポインタで両辺の領域が一部だけ重なる場合，結果は保証しない．  

# 構造体そのものの値
構造体そのものを値として使うこと(関数の引数・戻り値・演算のオペランド・条件・式文などに書くこと)には対応しない．全メンバの値を1つのレジスタに読み込めないためである．構造体の代入式も，値として使うことはできない(`f(b = a)`・`(b = a).value`はエラー)．  
構造体を丸ごと写すには，構造体の代入を使う(「構造体の代入」を参照)．関数との間で受け渡すには，構造体へのポインタを引数・戻り値にする．  

# メモリ上の大きさ
構造体は，メモリ上に次のとおり確保する．  

- 各メンバは，配列を含めワード単位で確保する  
- `char`/`short`型のスカラーのメンバも，1ワード(4バイト)を占める．構造体に属さないスカラー変数と同じ割り当て方である([pynesis/language/variable.md](variable.md)を参照)  
- 構造体の配列は，構造体1個分のワード数×要素数の領域を連続して確保する  

# 対応しない書き方
次のものには対応しない．将来対応する予定もない．  

- 入れ子の構造体(メンバに別の構造体そのものを持つこと)．構造体へのポインタはメンバにできる  
- メンバの初期化子
