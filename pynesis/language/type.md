# 型
```c
int n = -1;                      // 32ビットの符号あり整数
unsigned char b = 200;           // 8ビットの符号なし整数
unsigned int u = (unsigned int)n; // キャストで型を変える(4294967295)
int *p = &n;                     // intを指すポインタ
```

# データ型
| 型 | ビット幅 | 値の範囲 | 備考 |
|:-|:-|:-|:-|
| `char` | 8ビット | -128〜127 | |
| `short` | 16ビット | -32768〜32767 | |
| `int` | 32ビット | -2147483648〜2147483647 | |
| `unsigned char` | 8ビット | 0〜255 | |
| `unsigned short` | 16ビット | 0〜65535 | |
| `unsigned int` | 32ビット | 0〜4294967295 | |
| ポインタ(`int *`など) | 32ビット | 番地 | 型名の後ろに`*`を付ける([pynesis/language/pointer.md](pointer.md)を参照) |
| `void` | - | - | 戻り値のない関数(関数ポインタを含む)の戻り値型と，引数なしの宣言`(void)`([pynesis/language/function.md](function.md)を参照)にだけ使う |

- `char`/`short`/`int`をまとめて，その符号なしの型も含めて整数型と呼ぶ  
- 整数型とポインタをまとめて，スカラー型と呼ぶ  
- `long`は将来対応する予定である．`float`/`double`は，CPUに浮動小数点の命令がないため対応しない  

## 符号修飾子
`char`/`short`/`int`の直前に，符号修飾子`signed`(符号あり)または`unsigned`(符号なし)を書ける．  
省略すると`signed`になる．  

- 符号修飾子は，`char`/`short`/`int`の直前にだけ書ける  
- 単独(`unsigned x`)・重ね書き(`signed unsigned int`)・`void`や構造体型への付与は，コンパイルエラーになる  
- `const`と組み合わせる場合は，`const unsigned int`の順に書く([pynesis/language/variable.md](variable.md)の「const変数」を参照)  

# 型変換
整数の式の値は，32ビットの`int`または`unsigned int`として扱う．  
どちらになるかと，演算を符号ありと符号なしのどちらで行うかは，C言語と同じ整数昇格の規則で決まる．  
ポインタの式の型は，[pynesis/language/pointer.md](pointer.md)を参照．  

- 整数昇格: 演算のオペランドが`char`/`short`/`unsigned char`/`unsigned short`の場合は，`int`に変換してから演算する．どの値も`int`で表せるためである．`unsigned int`だけが符号なしのまま残る  
- 二項演算(算術・ビット・比較): 昇格後のオペランドのどちらかが`unsigned int`なら符号なしで，そうでなければ符号ありで演算する．算術・ビット演算の結果の型は，符号なしで演算したなら`unsigned int`，符号ありなら`int`になる  
- 三項演算子`c ? a : b`: 値の型は，`a`・`b`の昇格後の型のどちらかが`unsigned int`なら`unsigned int`，そうでなければ`int`になる．条件`c`の型は影響しない  
- シフト`<<`・`>>`: 左オペランドの昇格後の型だけで決まる．右オペランドの型は影響しない  
- 単項演算子`-`・`+`・`~`: オペランドの昇格後の型になる(`unsigned int`の`-u`は`unsigned int`)  
- 結果が`int`で決まっているもの: 比較・`!`・`&&`・`||`の結果(`0`/`1`)と，`sizeof`の結果．`sizeof`はC言語の`size_t`と異なり符号ありである(`int i = -1;`のとき`i < sizeof(buf)`は真)  
- 複合代入`x op= e`は，`x = x op e`と同じ規則で演算する  
- 代入式の値の型は左辺の型，`++`/`--`の値の型はオペランドの型，関数呼び出しの値の型は戻り値型である．式の中で使うと整数昇格を受ける  

## 符号によって結果が変わる演算
次の表の演算は，演算の符号によって結果が変わる．  
表にない演算は，符号によらず同じ結果になる．  

| 演算 | 符号あり | 符号なし |
|:-|:-|:-|
| 右シフト`>>` | 空いた上位ビットを符号ビットで埋める算術シフト(`-8 >> 1`は`-4`) | 空いた上位ビットを0で埋める論理シフト |
| 大小比較`<`・`>`・`<=`・`>=` | 2の補数として比較する | 0〜4294967295の値として比較する(`unsigned int u = 0;`のとき`u < -1`は真．`-1`が`0xFFFFFFFF`として比較されるため) |
| 除算`/`・剰余`%` | 商は0の方向へ切り捨て，剰余の符号は被除数に従う | 0〜4294967295の値として除算する |

## 演算の幅
演算は32ビットで行い，結果は32ビットの範囲で折り返す．  
オペランドが`char`/`short`でも，演算結果をその型の幅に切り詰めることはない(`char a = 100;`のとき`a + a`は`200`)．  

シフトの右オペランド(シフト量)は，型によらず，32ビットのビット列を0〜4294967295の値とみなす．  
シフト量が32以上なら全ビットがあふれ，結果は次のとおりになる．  

- `<<`と符号なしの`>>`: `0`  
- 符号ありの`>>`: 左オペランドが負なら`-1`，そうでなければ`0`  

負のシフト量も32以上とみなされ，同じ結果になる(`1 << -1`は`0`，`-16 >> 40`は`-1`)．  
C言語では未定義動作だが，CPUのシフト命令の動作([qurge/cpu/isa.md](../../qurge/cpu/isa.md)の「シフト系(S系)」を参照)に合わせて定める．  

## 読み出しと格納
8/16ビットの型の変数・配列要素・構造体メンバ(ポインタの指す先を含む)は，読み出した時点で`int`に変換される．  

- `char`/`short`: 上位ビットを符号ビットで埋める(符号拡張)  
- `unsigned char`/`unsigned short`: 上位ビットを0で埋める(ゼロ拡張．`unsigned char c = 200;`の`c`は`200`)  

変数・配列要素・構造体メンバ(ポインタの指す先を含む)へ値を与える場合は，与える先がconst変数かどうかで扱いが分かれる．  

- 通常の変数・配列要素・構造体メンバ: 初期化・代入・`++`/`--`・整数型の引数への受け渡しなど，操作の種類によらず同じ扱いになる  
    - 8/16ビットの型へは，下位8/16ビットだけを格納し，上位ビットは捨てる(`char c = 300;`の`c`は`44`)  
    - 32ビットの型どうし(`int`と`unsigned int`)は，ビット列をそのまま格納する(`unsigned int u = -1;`の`u`は`4294967295`)  
    - いずれもエラー・警告は出ない  
    - 関数の戻り値は格納に当たらず，値をそのまま返す([pynesis/language/function.md](function.md)を参照)  
- const変数: 初期化子の値を，切り詰めずにそのまま定数の値とする．値が宣言した型の範囲を外れると，コンパイルエラーになる(`const char C = 300;`はエラー．[pynesis/language/variable.md](variable.md)の「const変数」を参照)  

変数の値を型の異なる整数型の引数へ渡す場合も，この読み出しと格納の規則が当てはまる(`char c = -1;`を`int`の引数へ渡すと`-1`，`int n = 300;`を`char`の引数へ渡すと`44`)．  

## 格納の前後で値が変わる場合
格納した値は，読み出すときに格納先の型で解釈される．  
このため，格納する前の値と一致しないことがある(`char c = 200;`のとき`c == 200`は偽になり，`case 200:`にも一致しない)．  

代入式・`++`/`--`の値は，格納時に切り詰める前の値である(`char c = 127;`のとき，`int`の変数`x`への`x = ++c;`で`x`は`128`，`c`は`-128`)．  
C言語では格納後の値になるため，8/16ビットの型では結果が食い違う．  

- `unsigned char c = 0;`のとき，`--c`の値は`-1`になる  
- 同じく，`(c = -1) > 0`は偽になる  
- `return -1;`する`unsigned char`の関数`f`で，`f() == 255`は偽になる  

# キャスト
`(型名)式`と書くと，式の値を型名の型へ変換する．  
前置の単項演算子と同じ優先順位で結合する(`(unsigned int)a / b`は`((unsigned int)a) / b`，`(int *)p[i]`は`(int *)(p[i])`)．  

| 変換 | 結果 |
|:-|:-|
| 整数→`char`/`short`/`unsigned char`/`unsigned short` | 下位8/16ビットへ切り詰めてから，その型の読み出しの規則(「読み出しと格納」を参照)で拡張した値(`(char)300`は`44`，`(char)200`は`-56`，`(unsigned char)-1`は`255`) |
| 整数→`int`/`unsigned int` | ビット列を変えず，型だけを変えた値(`(unsigned int)-1`は`4294967295`，`(int)0x80000000`は`-2147483648`) |
| 整数→ポインタ | 整数のビット列を番地とするポインタ(`(unsigned int *)0x8000`)．関数ポインタでは，関数の先頭の命令を指すPCの値とする([pynesis/language/pointer.md](pointer.md)の「関数ポインタ」を参照) |
| ポインタ→整数 | 番地のビット列を値とする整数(関数ポインタは関数の先頭の命令を指すPCの値)．8/16ビットの型へは，上と同じく切り詰める |
| データのポインタ(関数ポインタ以外のポインタ)どうし | 番地を変えず，指す先の型だけを変えたポインタ(`(unsigned char *)words`) |
| 同じ型の関数ポインタどうし | 値を変えない関数ポインタ |

- 結果は，書いた型名の型の値として扱う．8/16ビットの型へのキャストの結果は，演算のオペランドになると整数昇格で`int`へ変換される(`(unsigned char)x + 1`は`int`どうしの演算)  
- 関数ポインタの型名は，宣言から名前を除いた`戻り値型 (*)(引数の型の並び)`の形で書く(`(void (*)(void))0x4000`)  
- 結果は左辺値ではないため，代入・`++`/`--`・`&`の対象にできない(`(int)x = 1`はエラー)．ポインタへキャストした結果の指す先は，読み書きできる(`*(unsigned int *)0x8000 = 1`)  
- 結果に続けて，添字・`->`・呼び出しを書ける(`((unsigned char *)words)[1]`・`((struct Pair *)p)->second`・`((void (*)(void))0x4000)()`)  
- 整数から整数へのキャストは，定数式に書ける([pynesis/language/variable.md](variable.md)の「定数式」を参照)  
- ポインタへのキャストとポインタから整数へのキャストは，定数式に書けない．ただし，ポインタのグローバル変数の初期化子には，ポインタへキャストした式を書ける([pynesis/language/pointer.md](pointer.md)の「グローバル変数の初期化子」を参照)  

## コンパイルエラーになるキャスト
- `void`・構造体そのもの・`const`を付けた型・宣言できない型([pynesis/language/unsupported.md](unsupported.md)を参照)へのキャスト  
- データのポインタと関数ポインタの間の直接のキャスト: データの番地はメモリのバイト単位，関数の番地はPCの値であり，指す空間が異なるため．整数を経由して書く(`(void (*)(void))(int)p`)  
- 型の異なる関数ポインタどうしのキャスト: 変換した関数ポインタを呼ぶと，呼び出す関数と引数・戻り値の型が食い違うため．整数を経由すれば書けるが，型が食い違う呼び出しの結果は保証しない  
- `nullptr`のキャスト: どのポインタへもキャストせずに格納でき，整数へ変換しても`nullptr`を表すビット列(`0x80000000`)を得るだけのため  
- 1つの値として読めない式のキャスト: 構造体変数そのもの(`(int)s`)は値をまとめて読む仕組みがないため，戻り値のない関数の呼び出し(`void f(void)`に対する`(int)f()`)は値を持たないため  

## 境界に揃わない番地を指すポインタ
キャストで作ったポインタは，指す先の型の境界に揃わない番地も指せる．  
`short`・`int`・ポインタを4バイト境界をまたいで読み書きすると，同じワードの中で折り返した番地を読み書きする([qurge/memory.md](../../qurge/memory.md)を参照)．  
コンパイラはこれを検査しない．  

## 見積もりから外れる関数ポインタ
キャストで作った関数ポインタの呼び出しは，スタックの使用量の見積もりから外れることがある([pynesis/language/limit.md](limit.md)の「変数に使えるメモリ」を参照)．
