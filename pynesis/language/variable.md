# 変数
```c
const int CAP = 4;           // const変数(コンパイル時に決まる定数)
int count = 0;               // グローバル変数(初期化子は定数式)
int table[CAP * 2];          // 配列のサイズにも定数式を書ける

void main(void) {
    int x = count + 1;       // ローカル変数
    {
        int x = 10;          // 内側のブロックでは別の変数(シャドーイング)
    }
}
```

- グローバル変数・ローカル変数の両方に対応する  
- const変数を除くすべての変数は，メモリ上に置く．レジスタへは割り当てない  
- スカラー変数は，宣言した場所と型によらず1ワード(4バイト)を占める．`char`/`short`も，値をワードの下位バイトに置き，ほかの変数と1ワードを共有しない  
- 配列は[pynesis/language/array.md](array.md)，構造体は[pynesis/language/struct.md](struct.md)，ポインタは[pynesis/language/pointer.md](pointer.md)を参照  

# 初期化
宣言と同時に初期化できる(`int x = 0;`)．  

- 初期化子のない変数の値は保証されない．C言語と異なり，グローバル変数も0で初期化されない．メモリはCPUのリセットで初期化されず([qurge/memory.md](../../qurge/memory.md)を参照)，前回の実行で書き込まれた値が残りうる  
- 0から始める変数は初期化子を明示する．初期化子を持てない変数(配列など)には，実行時に0を書き込む  
- グローバル変数の初期化子は，定数式(「定数式」を参照)だけを書ける．通常の変数や関数呼び出しは，初期化の実行順序が決まらないため書けない  
- ポインタのグローバル変数の初期化子には，定数式の代わりに，番地がコンパイル時に確定する式を書く([pynesis/language/pointer.md](pointer.md)の「グローバル変数の初期化子」を参照)  
- グローバル変数の初期化子の値は，`main`の本体を実行する前に書き込む([pynesis/language/function.md](function.md)の「main関数」を参照)  

# スコープ
- ブロックスコープに対応する  
- スコープが異なれば，同じ名前の変数を別の変数として扱う(シャドーイング)  
- グローバル変数(const変数を含む)・関数・ハードウェア変数([pynesis/language/hardware.md](hardware.md)を参照)は同じ名前空間にあり，互いに同じ名前のものは宣言できない(コンパイルエラー)  
- 構造体名はこれらと別の名前空間にあり，同じ名前にできる  

## ローカル変数に付けられない名前
次のものと同じ名前のローカル変数・関数の引数は，宣言できない(コンパイルエラー)．  

- ハードウェア変数: レジスタを誤って上書きしないため  
- 関数: 呼び出し`f(...)`の名前が，関数と関数ポインタの変数のどちらを指すかを一意にするため([pynesis/language/pointer.md](pointer.md)の「関数ポインタ」を参照)  

## グローバルスコープ
ファイルの直下(グローバルスコープ)に置いた宣言は，プログラム全体のどこからでも，順序を問わず参照できる．  
取り込んだファイル([pynesis/language/include.md](include.md)を参照)の宣言も同じである．  
関数定義とグローバル変数宣言(const変数を含む)の両方に当てはまり，定数式から参照する場合も同じである．  

ただし，宣言の値やサイズを求めるためにその宣言自身へ戻ってくる循環した依存は，コンパイルエラーになる(`const int A = B; const int B = A;`，`int buf[sizeof(buf)];`)．  

# ローカル変数の寿命
ローカル変数と引数は，関数の呼び出しごとに確保し，関数から戻るときに解放する．  
同じ関数が呼び出しの途中で再び呼ばれても，それぞれの呼び出しの値は別に保たれる．  

ローカル変数・引数の番地を`&`で取った場合，その番地は関数から戻った後に別の呼び出しで再利用される．  
このため，戻った後にその番地を参照した場合の値は保証されない(C言語と同じ)．  

# const変数
`const`を付けて宣言した整数型のスカラー変数は，値がコンパイル時に確定する定数になる．  
メモリを確保せず，参照する箇所へ値を直接埋め込む(`#define`による置換と同等)．  
このため，定数式の中でも使える．  

```c
const int CAP = 4;
int table[CAP];                  // 配列のサイズに使える
void main(void) {
    for (int i = 0; i < CAP; i++) {
        table[i] = 0;
    }
}
```

- グローバル・ローカル(for文の初期化部を含む)のどちらでも宣言でき，初期化子は必須である  
- 値を書き換える操作(代入・`++`/`--`・組み込み関数の書き込み先への指定など)の対象にすると，コンパイルエラーになる  
- 式の中では，宣言した型の値として扱う(`const unsigned int U = 1;`の`U`は`unsigned int`)  
- `sizeof(const変数)`は，宣言した型のバイト数を返す  
- 名前の重複・シャドーイング・ハードウェア変数や関数と同じ名前の禁止は，通常の変数と同じ規則に従う  
- 初期化子では，後で宣言したconst変数の参照や，後で宣言した変数の`sizeof`も使える(循環する場合は「グローバルスコープ」を参照)  
- `const`は，符号修飾子・型名より前にだけ書ける(`int const x`・`unsigned const int x`は不可)  

## 値の範囲
値が宣言した型の範囲([pynesis/language/type.md](type.md)の「データ型」を参照)を外れる場合は，コンパイルエラーになる．  
通常の変数への格納と異なり，下位ビットへの切り詰めは行わない([pynesis/language/type.md](type.md)の「読み出しと格納」を参照)．  

初期化子の値は，定数式の型に従って判定する．  
このため，次の初期化子はエラーになる．  

| 誤った書き方 | エラーになる理由 | 正しい書き方 |
|:-|:-|:-|
| `const unsigned int A = -1;` | 初期化子は`int`の`-1` | `0xFFFFFFFF`または`(unsigned int)-1` |
| `const unsigned int B = ~0;` | 初期化子は`int`の`-1` | `0xFFFFFFFF`または`(unsigned int)-1` |
| `const int C = 0xFFFFFFFF;` | 初期化子は`unsigned int`の4294967295 | `-1` |

## const変数にできないもの
- 配列・構造体(メンバを含む)・関数の引数・関数の戻り値型: 配列・構造体は初期値リストに対応せず，値を与える手段がないため  
- ポインタ(`const int *p`・`int *const p`はいずれも不可): constは参照する箇所へ値を埋め込む整数の定数を表し，指す先を書き換えられないポインタの意味は持たないため  

# 定数式
コンパイル時に値を計算する式である．  
次のものだけで構成する．  

- 整数リテラル・文字リテラル([pynesis/language/lexical.md](lexical.md)を参照)  
- const変数  
- `sizeof`  
- 代入・`++`/`--`以外の演算子  
- 整数から整数へのキャスト([pynesis/language/type.md](type.md)の「キャスト」を参照)  

通常の変数の参照や関数呼び出しは含められない．  
ポインタへのキャストとポインタから整数へのキャストは，番地を値とするため含められない(グローバル変数の初期化子`int a = (int)&g;`はエラー)．  

定数式を書く必要がある箇所は，次のとおりである．  

- グローバル変数の初期化子  
- 配列のサイズ(構造体のメンバの配列・構造体の配列を含む)  
- `case`の値  
- const変数の初期化子  

## 定数式の値
定数式は，同じ式を実行時に計算した場合と同じ値になるよう，型変換の規則([pynesis/language/type.md](type.md)を参照)に従って計算する(`2147483647 + 1`は`-2147483648`，`0xFFFFFFF0 / 2`は`2147483640`，`1 << 33`は`0`)．  

次の計算はコンパイルエラーになる．  
実行時にCPUが例外として検出するか，結果が定まらないためである([qurge/cpu/exception.md](../../qurge/cpu/exception.md)を参照)．  

- 0での除算・剰余  
- `int`の最小値を`-1`で割る除算・剰余  

`case`の値は，条件の値とビット列が一致するかで比較する．  
このため，ビット列が同じ値(`-1`と`0xFFFFFFFF`)を複数の`case`に書くと，重複としてコンパイルエラーになる．
