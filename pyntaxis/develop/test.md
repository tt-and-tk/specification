# テスト
アセンブラのテストは，入力したアセンブリを変換した結果が，期待値と一致するかを確かめる．  

# 期待値
- 正常系: 期待値を`test/sv_ans/`(LF．改行コードも含めて比較する)と`test/bin_ans/`(実行ファイルと同じ形式のバイナリ)に置く  
- 異常系: 期待するエラーメッセージを，入力ファイルの1行目に`; expect: <メッセージ>`の形で書く  

異常系のメッセージは，入力の行をタブ文字ごと引用することがある．  
このため，メッセージは手で書かず，アセンブラの出力から作る．  
作ったメッセージが，2行目以降のコメントに書いたテストの意図と合っているかを確かめる．  

# 実行の仕方
`test/`で，次のスクリプトを実行する．  
各スクリプトは，最初に`test/asm_build.py`(共通のビルド処理)で[pyntaxis/develop/source.md](source.md)と同じビルドを行ってからテストする．  
このため，事前のビルドは要らない．  

- `python test.py`(正常系): `test/asm/`の全`.pt`をROMへ変換して`test/sv/`へ出力し，期待値と比べる  
- `python test_err.py`(異常系): `test/asm_err/`の全`.pt`が，期待どおりのエラーになることを確かめる  
- `python test_bin.py`(実行ファイル): 次の3つを確かめる  
    - `test/asm_bin/`の全`.pt`を`test/bin/`へ出力し，期待値と一致する  
    - `test/asm_bin_err/`の全`.pt`が，期待どおりのエラーになる  
    - 起動引数の誤りが，エラーになる  

これらのスクリプトは，コンパイラの`pn2mc.exe`をビルドしない．  
`pn2mc.exe`が取り込む本処理を変えたときは，コンパイラ側でビルドできることも確かめる([pynesis/develop/test.md](../../pynesis/develop/test.md)を参照)．
