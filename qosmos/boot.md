# Qosmos
Qosmosは，Pynthesisの自作OSである(名称の由来は[README.md](../README.md#名称について)を参照)．CPUのROM上で動き，起動時にハードウェアを初期化してストレージとネットワークを使える状態にした後，シェルとしてコンソールから1行ずつコマンドを受け取り，対応する処理を実行する．\
コンソールは，LANを通してtelnetで接続した端末と，USBのシリアル通信(UART)で接続した端末の2つから成る([qosmos/user/console.md](user/console.md)を参照)．

`qosmos/`配下の各文書がQosmosの仕様であり，実装(`qurge`の`mypc.srcs/pn/qosmos.pn`と，そこから取り込むファイル)はこれに従う．

# 起動時の動作
ハードウェアの初期化として，次の項目を順に行う．各項目は互いに依存しないため，前の項目が失敗しても後の項目は実行する．

1. ストレージ: SDカードを初期化し，続いてカード上のFAT32ファイルシステムをマウントする([qosmos/resource/filesystem.md](resource/filesystem.md)を参照)
2. ネットワーク: Ethernetモジュールをリセットし，続いてネットワークの設定を書き込む([qosmos/resource/network.md](resource/network.md)を参照)

いずれも機器とのやり取りの段階ごとに(マウントは1つの段階として)，成否を1行ずつコンソールへ出力する．失敗した段階では理由を出力し，同じ項目の以降の段階は実行しない．SDカードの段階とEthernetモジュールのリセットの段階の理由には，判定に使った機器の応答値を添える．\
電源を入れたときは，telnetで接続した端末が無いため，これらの行はUARTで接続した端末にだけ届く([qosmos/user/console.md](user/console.md)を参照)．`reboot`でやり直した場合は，ストレージの項目の行は両方の端末に届き，ネットワークの項目の行はUARTで接続した端末にだけ届く([qosmos/user/console.md](user/console.md)の「telnetでの接続」を参照)．ストレージの項目の成否は終了状態として保持されるため，telnetで接続した端末からも`status`で確かめられる([qosmos/user/command.md](user/command.md)の「終了状態」を参照)．\
UARTで接続した端末には，PSが最初に実行するプログラム(FSBL)の出力も届く．FSBLはCPUが動き出した後も出力しうるため，その出力が起動時の行と混ざることがある．

その後，成否によらずOS名Qosmosを大きな文字(アスキーアート)で出力し，副題を添えてからプロンプトを表示し，コマンドを受け付け始める．ストレージの項目が失敗していた場合は，OS名の後に，`reboot`でやり直せることを伝える行を出力する．この場合，失敗の原因を取り除いてから起動をやり直す．やり直し方は原因の取り除き方によって異なり，カードを差し直さずに済めば`reboot`を実行し，カードを差し直す場合は電源を入れ直す(実機の構成では，電源を切ってからカードを差し直すため．[qurge/board.md](../qurge/board.md)の「構成から生じる操作上の制約」を参照)．\
telnetでの接続は，起動時の動作を終えてプロンプトを表示した後に受け付ける．ネットワークの項目が失敗していた場合は，接続を待ち受けられるようになるまでネットワークの項目をやり直す([qosmos/user/console.md](user/console.md)の「telnetでの接続」を参照)．
