# 起動の手順
起動時に出力される行と，失敗したときの対処は，[qosmos/user/boot.md](../user/boot.md)を参照．  

Qosmosが起動するきっかけは次の2つで，起動の手順を実行し始めるまでが異なる．  

- 電源を入れたとき(SRSTのボタンを押したときを含む): CPUがリセットを受けてROMの先頭から実行を始め，グローバル変数に初期値を書き込んでから，`main`が起動の手順を実行する([pynesis/language/variable.md](../../pynesis/language/variable.md)の「初期化」を参照)  
- `reboot`を実行したとき: CPUはリセットを受けず，シェルがコマンドとして起動の手順を実行する．グローバル変数への初期値の書き込みも行わないため，メモリの内容とレジスタのうち，起動の手順が書き込むものだけが変わる．例えば，現在のディレクトリは，マウントの段階でルートディレクトリに戻る  

起動の手順は，次の順に行う．  

1. プロセスを動かすための設定: システムコールハンドラ・例外ハンドラ・割り込みハンドラの番地と割り込み周期をCPUへ書き込み，タイマー割り込みを有効にする([qosmos/kernel/exec.md](exec.md)の「割り込みで止めたとき」を参照)  
2. ストレージの項目: SDカードを初期化し，続いてカード上のFAT32ファイルシステムをマウントする(「ストレージの項目」を参照)  
3. telnetでの接続を閉じる(`reboot`のとき．[qosmos/kernel/console.md](console.md)の「コマンドが接続を閉じる場合」を参照)  
4. ネットワークの項目: Ethernetモジュールをリセットし，続いてネットワークの設定を書き込む(「ネットワークの項目」を参照)  
5. Qosmosの名前を出力する．ストレージの項目が失敗していれば，`reboot`でやり直せることを伝える行も出力する  
6. プロンプトを表示し，コマンドを受け付け始める．telnetでの接続も受け付け始める  

2つの項目は互いに依存しないため，前の項目が失敗しても後の項目は実行する．同じ項目の中では，失敗した段階より後の段階は実行しない．  

## 段階の成否の出力
機器とのやり取りの段階ごとに(マウントは1つの段階として)，成否を1行ずつコンソールへ出力する．失敗した段階では，理由も出力する．SDカードの段階と，Ethernetモジュールのリセットの段階の理由には，判定に使った機器の応答値を添える．  

## 起動の終了状態
ストレージの項目の成否は，終了状態として保持する([qosmos/user/shell.md](../user/shell.md)の「終了状態」を参照)．ネットワークの項目の成否は含めない．失敗しても，接続を受け付けられるまでやり直すためである([qosmos/kernel/console.md](console.md)の「設定のやり直し」を参照)．  

# ストレージの項目
SDカードは，Arduino互換ヘッダのSPIのピンをソフトウェアで駆動して読み書きする([board.md](../../board.md)の「SDカードのシールド」を参照)．次の段階を順に行う．  

1. リセット(CMD0): カードをSPIモードへ切り替えてリセットする  
    - 失敗: アイドル状態を表す応答(`0x01`)が返らない場合．カードが差さっていない場合は，無応答(`0xff`)になる  
2. 電圧確認(CMD8): 2.7〜3.6Vで動くかを問い合わせる  
    - 成功: 応答が`0x01`で，問い合わせた電圧範囲とチェックパターン(`0x01`・`0xaa`)がそのまま戻る場合  
    - 失敗: それ以外の場合．SD v1のカードはこの問い合わせを拒否するため，ここで失敗する  
    - 理由に添える値: パターンが戻らない場合は，戻った電圧範囲とチェックパターンの2バイト  
3. 初期化完了待ち(ACMD41): カードに内部の初期化を始めさせる  
    - 失敗: 初期化中を表す応答(`0x01`)と完了を表す応答(`0x00`)以外が返った場合と，規格上の上限である1秒を過ぎても完了が返らない場合  
4. カード種別(CMD58): カードの種別を読み出す  
    - 失敗: 応答が`0x00`以外の場合と，SDSCである場合  
    - 理由に添える値: SDSCである場合は，種別を表すOCRの最上位バイト  
    - 成功の行: SDSCでないことを表す種別名`SDHC/SDXC`を添える  
5. マウント: カード上のFAT32ファイルシステムを読む([qosmos/kernel/filesystem.md](filesystem.md)を参照)  
    - 失敗: カードから読み出せない場合と，FAT32ファイルシステムが見つからない場合  

初期化を始める前に，それまでマウントしていたファイルシステムを外す．初期化に失敗したときに，前のカードのファイルシステムを使い続けないためである．  

# ネットワークの項目
Ethernetモジュール(W5100S)は，SPIで制御する([qosmos/kernel/network.md](network.md)を参照)．次の段階を順に行う．  

1. リセット: モジュールをハードウェアリセットし，動き出すまで待ってからバージョンを読み出す  
    - 失敗: W5100Sの値(`0x51`)でない場合．モジュールが接続されていない場合は，無応答(`0xff`)になる  
2. ネットワークの設定: 設定の値([qosmos/kernel/network.md](network.md)の「設定」を参照)を書き込み，読み戻す  
    - 失敗: 読み戻した値が1つでも異なる場合  
    - 成功の行: 設定したIPアドレスを添える  

成功は設定を書き込めたことを表し，ケーブルの接続やリンクの確立は確かめない．  

# 起動の行が届く端末
電源を入れたときは，telnetで接続した端末が無いため，起動の行はUARTで接続した端末にだけ届く．`reboot`のときは，ネットワークの項目の前に接続を閉じるため，ストレージの項目の行は両方の端末に届き，ネットワークの項目の行とQosmosの名前はUARTで接続した端末にだけ届く．
