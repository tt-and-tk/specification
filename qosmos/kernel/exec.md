# プロセス
実行ファイルを作る人から見た動作は，[qosmos/program/executable.md](../program/executable.md)を参照．  

QosmosはROM上のプログラムとしてカーネルモードで動き，シェルもその一部である．プロセスは，Qosmosが割り振ったメモリの範囲(以下，領域．[qosmos/kernel/memory.md](memory.md)の「実行ファイルの領域」を参照)の中で，ユーザーモードで動く．  

実行ファイルを起動するのは，シェルとプロセスの2つである．起動した側は，コマンド名と引数を半角空白で区切った1行(以下，起動を求める1行)をQosmosへ渡す．  

| 起動する側 | 起動の方法 | 起動を求める1行 |
|:-|:-|:-|
| シェル | 入力したコマンド名と同じ名前の実行ファイルを起動する([qosmos/user/shell.md](../user/shell.md)の「入力の解析」を参照) | 入力した1行 |
| プロセス | システムコール`spawn`で起動する([qosmos/program/syscall.md](../program/syscall.md)の「実行ファイルを起動する」を参照) | `spawn`に指定した1行 |

プロセスが別の実行ファイルを起動した場合，起動した側のプロセスを親，起動された側のプロセスを子と呼ぶ．起動した側は，起動された側のプロセスが終わるまで止まる．このため，同時に動くプロセスは1つだけである．子の終了を待つ親は，領域をメモリに残したまま止まる．  

# プロセステーブル
Qosmosは，メモリに置いたプロセスを，プロセステーブルに記録する．プロセステーブルは，プロセスごとに次の値を持つQosmosの変数の配列である．要素数は16で，同時にメモリに置けるプロセスの数の上限になる([qosmos/kernel/memory.md](memory.md)の「プロセスの数の上限」を参照)．  

| 値 | 内容 |
|:-|:-|
| 親 | 親のプロセステーブルでの位置．シェルが起動したプロセスは，親を持たない |
| 領域 | 領域の先頭のメモリの番地と，大きさ |
| 再開するための値 | 子の終了を待つ間，このプロセスを再開するために控えておく値(「親の値の控えと戻し」を参照) |

各要素は，プロセスが終わるまで位置を変えない．親をプロセステーブルでの位置で指すためである．  
Qosmosは，実行中のプロセスのプロセステーブルでの位置も持つ．シェルが動いている間は，実行中のプロセスは無い．  

# 起動と終了の手順
Qosmosは，起動した側がシェルとプロセスのどちらでも，次の順に実行ファイルを起動し，終わった後を処理する．起動した側がプロセスの場合にだけ行う処理は，その旨を書く．  

## 読み込み
1. 起動を求める1行の先頭をコマンド名とし，`/bin`から同じ名前の実行ファイルを探す．大きさが，ヘッダと1命令を合わせた24バイト以上かを確かめる  
2. 実行ファイルの先頭のセクタを読み出し，ヘッダが条件([qosmos/program/executable.md](../program/executable.md)の「形式」を参照)に合うかを確かめる  
3. プロセステーブルに要素を加え，ヘッダに書かれた大きさから決まる領域を空きから割り振る([qosmos/kernel/memory.md](memory.md)の「領域の割り振り」を参照)．実行中のプロセスがあれば，そのプロセスを親とする  
4. ヘッダの後ろの命令列を，領域の先頭から書き写す  

実行ファイルが条件に合わない場合と，読み出しに失敗した場合は，実行しない([qosmos/program/executable.md](../program/executable.md)の「実行できない場合」を参照)．要素を加えた後に命令列の読み出しに失敗した場合は，加えた要素をプロセステーブルから外す．  

## プロセスへ入る
1. それまでの出力のうち，telnetで接続した端末へまだ送っていないものを送る．シェルは端末への出力をためておき，次に入力を待つときにまとめて送る．プロセスが動いている間はシェルが入力を待たないため，ここで送っておく  
2. 起動した側がプロセスの場合は，そのプロセス(親)を再開するための値をプロセステーブルへ控える(「親の値の控えと戻し」を参照)  
3. 起動するプロセスを，実行中のプロセスにする  
4. UBASE・USIZEに領域を，KENTRYにシステムコールハンドラの番地を，EENTRYに例外ハンドラの番地を書き込む([qurge/cpu/register.md](../../qurge/cpu/register.md)を参照)  
5. KRETに0(実行ファイルの先頭の命令のPC)を書き込む  
6. コマンド名と引数を，領域の末尾の256バイト(以下，引数の置き場)に置く．置いた結果から，プロセスが使い始めるSPの値が決まる(「引数の置き方」を参照)  
7. プロセスへ入る関数を呼ぶ．この関数は，今のSPをQosmosの変数に控える．控えるSPは，カーネルモードのスタックで，この関数の戻り先を指している  
8. プロセスへ入る関数が，SPを，プロセスが使い始めるSPの値に変える  
9. プロセスへ入る関数が，組み込み関数`sysret`でユーザーモードへ移る．CPUは，実行ファイルの先頭の命令から実行を始める  

## 終わった後
プロセスが終わると，システムコールハンドラか例外ハンドラが，プロセスへ入る関数の呼び出し元へ直接戻る(「プロセスが終わったとき」を参照)．このため，プロセスへ入る関数は，自身の末尾まで実行されることがない．呼び出し元は，戻った直後に次の順に処理する．  

1. 終わり方を受け取る(「終わり方の見分け方」を参照)  
2. 起動した側がプロセスの場合は，控えた値を戻し，そのプロセス(親)を実行中のプロセスに戻す(「親の値の控えと戻し」を参照)．起動した側がシェルの場合は，実行中のプロセスが無い状態に戻す  
3. 終わったプロセスの要素を，プロセステーブルから外す．領域は，空きに戻る  
4. 起動した側へ，終わり方を伝える  
    - シェル: 例外で終わった場合は，エラーメッセージを1行出力する([qosmos/program/executable.md](../program/executable.md)の「例外を起こした場合」を参照)．終了状態と例外の番号の扱いは，[qosmos/user/shell.md](../user/shell.md)の「終了状態」を参照  
    - プロセス: `spawn`の結果として返し，親の`spawn`の続きへ戻る([qosmos/program/syscall.md](../program/syscall.md)の「実行ファイルを起動する」を参照)．Qosmosはメッセージを出力しない  

## 親の値の控えと戻し
プロセスは，`spawn`のシステムコールでカーネルモードへ入り，Qosmosはその処理の中から子を起動する．親を再開するのに要る値のうち，次の値は子を動かすと子のものに変わる．このため，Qosmosは子を実行中のプロセスにする前に，これらの値をプロセステーブルの親の要素へ控え，子が終わった後に戻す．  

| 控える値 | 親の再開での使い道 |
|:-|:-|
| 親がシステムコールの命令を実行した時点のSP(領域の中の番地) | `spawn`の処理を終えて，親のスタックへ戻す |
| KRETの値(親のシステムコールの命令の次の命令のPC) | 組み込み関数`sysret`で，親の続きへ戻る |
| プロセスへ入る関数が控えたカーネルモードのSP | 親がシステムコールを実行したときにカーネルモードのスタックへ切り替える先と，親が終わったときに親を起動した側へ戻る先 |

次の値は控えない．  

- UBASE・USIZE: 子のものに変わるが，プロセステーブルの親の領域から戻せる  
- r0〜r15とRAX: システムコールで値を保たない取り決めである([qosmos/kernel/syscall.md](syscall.md)の「受け付けの手順」を参照)  

子を実行する関数のフレームは，親の`spawn`を処理している途中のカーネルモードのスタックの上に積む．子がさらに子を起動するたびに，カーネルモードのスタックは1段ずつ深くなる．  

# 引数の置き方
コマンド名と引数は，シェルの入力の解析([qosmos/user/shell.md](../user/shell.md)の「入力の解析」を参照)と同じく，1行を半角空白で区切ったものである．区切りの空白は，文字列に含めない．プロセスが始まる時点の引数の置き場は，次のとおりである．  

| 位置 | 内容 |
|:-|:-|
| 領域の末尾 | コマンド名と各引数の文字列(ヌル終端)．1行の中の順に，番地の小さい側から置く |
| 文字列より番地の小さい側(4バイト境界に揃える) | `argv`の配列．各文字列の先頭の領域の中の番地を並べ，最後に`nullptr`を置く．`argv[0]`はコマンド名(1行に書かれたとおりの綴り)である |
| 配列より番地の小さい側の，隣の4バイト | SPが指す位置．Pyntaxisの`call`が戻り先を積む位置にあたるが，値は不定で，戻り先としては使えない |
| SP-8 | `argc`(`int`)．コマンド名と引数を合わせた数(1以上) |
| SP-4 | `argv`(`char **`)．`argv`の配列の先頭の領域の中の番地 |

`argc`・`argv`の位置は，2つの引数を渡す関数へPyntaxisの`call`で入った直後の，引数の位置と同じである．このため，Pynesisの`main`は，ほかの関数と同じ呼び出し規約で引数を読める([pynesis/compiler/call.md](../../pynesis/compiler/call.md)の「実行ファイルのmain」を参照)．  

# プロセスが終わったとき
プロセスの終わり方は，次の2通りである．  

- 終了のシステムコールで終わる: プロセスが終了のシステムコールを実行した場合である．Pynesisでは，`main`から戻ると終了のシステムコールを実行する  
- 例外で終わる: プロセスが例外を起こした場合である．例外が実行ファイルのどの関数の中で起きても，同じように終わる  

## 終了のシステムコールで終わる場合
CPUは，カーネルモードへ移り，システムコールハンドラ([qosmos/kernel/syscall.md](syscall.md)を参照)へ飛ぶ．システムコールハンドラは，次の順に処理する．  

1. SPを，プロセスへ入る関数が控えた値に戻す  
2. プロセスが渡した値(終了状態)を戻り値として，プロセスへ入る関数の呼び出し元へ戻る  

## 例外で終わる場合
CPUは，カーネルモードへ移り，例外ハンドラへ飛ぶ([qurge/cpu/mode.md](../../qurge/cpu/mode.md)の「ユーザーモードの例外」を参照)．例外ハンドラは，次の順に処理する．  

1. SPを，プロセスへ入る関数が控えた値に戻す  
2. ECAUSEの値(例外の原因)を，例外の原因を控える変数へ書き写す  
3. KRETの値(例外を起こした命令のPC)を，Qosmosの別の変数へ控える  
4. プロセスへ入る関数の呼び出し元へ戻る．このときの戻り値は，意味のある値にならない  

## 終わり方の見分け方
プロセスへ入る関数の呼び出し元は，例外の原因を控える変数を見て，終わり方を見分ける．  

| 変数の値 | 終わり方 | 受け取る値 |
|:-|:-|:-|
| 0 | 終了のシステムコールで終わった | 戻り値(終了状態) |
| 0以外 | 例外で終わった | 例外の原因と，例外を起こした命令のPC．戻り値は使わない |

例外の番号は1以上のため，0は例外で終わっていないことを表す．呼び出し元は，終わり方を受け取った直後に，この変数を0へ戻す．後で終わるプロセスが，前に例外で終わったプロセスの例外を，自分のものと取り違えないためである．  

# SPを書き換える関数
プロセスへ入る関数と，システムコールハンドラ・例外ハンドラは，SPを書き換える．これらの関数は，フレームの大きさを0にするため，引数・ローカル変数を持たず，値はグローバル変数に置く([pynesis/language/hardware.md](../../pynesis/language/hardware.md)の「SPへ書き込める関数」を参照)．システムコールハンドラと例外ハンドラは，SPを戻すまで関数を呼ばない．飛んできた直後のSPは領域の中の番地のままであり，カーネルモードではそのまま使えないためである．
