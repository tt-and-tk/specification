# 実行ファイルを動かす仕組み
実行ファイルから見た動作は，[qosmos/program/executable.md](../program/executable.md)を参照．  

シェルはOSの一部であり，ROM上のプログラムとしてカーネルモードで動く．  
実行ファイルは，OSが割り振ったメモリの領域([qosmos/kernel/memory.md](memory.md)の「実行ファイルの領域」を参照．以下，領域と書く)の中で，ユーザーモードで動く．  

# 実行の手順
シェルは，次の順に実行ファイルを動かす．  

1. `/bin`から実行ファイルを探し，大きさを確かめる．条件に合わなければ実行しない([qosmos/program/executable.md](../program/executable.md)の「実行できない場合」を参照)  
2. 実行ファイルの内容を，領域の先頭から書き写す．読み込みの途中で読み出しに失敗した場合は，書き写した内容が途中のまま残り，実行しない  
3. シェルがそれまでに出力した内容のうち，telnetで接続した端末へまだ送っていないものを送る．シェルは端末への出力をためておき，次に入力を待つときにまとめて送る．実行ファイルが動いている間はシェルが入力を待たないため，ここで送っておく  
4. 例外の原因を控えるOSの変数を0にする．例外の番号は1以上のため，0は例外で終わっていないことを表す(「終わり方の見分け方」を参照)  
5. UBASE・USIZEに領域を，KENTRYにシステムコールハンドラの番地を，EENTRYに例外ハンドラの番地を書き込む([qurge/cpu/register.md](../../qurge/cpu/register.md)を参照)  
6. KRETに0(実行ファイルの先頭の命令のPC)を書き込む  
7. コマンド名と引数を，領域の末尾の256バイト(以下，引数の置き場と書く)に置く．置いた結果から，実行ファイルが使い始めるSPの値が決まる(「引数の置き方」を参照)  
8. 実行ファイルへ入る関数を呼ぶ．この関数は，今のSPをOSの変数に控える．今のSPは，カーネルモードのスタックで，この関数の戻り先を指している  
9. 実行ファイルへ入る関数が，SPを手順7で決めた値に変える  
10. 実行ファイルへ入る関数が，組み込み関数`sysret`でユーザーモードへ移る．CPUは，実行ファイルの先頭の命令から実行を始める  

実行ファイルへ入る関数は，自身の末尾まで実行されることがない．  
実行ファイルが終わると，システムコールハンドラか例外ハンドラが，この関数の呼び出し元(シェル)へ戻る(「実行ファイルが終わったとき」を参照)．  

# 引数の置き方
コマンド名と引数は，シェルの入力の解析([qosmos/user/shell.md](../user/shell.md)の「入力の解析」を参照)と同じく半角空白で区切り，区切りの空白は文字列に含めない．  
実行ファイルが始まる時点の引数の置き場は，次のとおりである．  

| 位置 | 内容 |
|:-|:-|
| 領域の末尾 | コマンド名と各引数の文字列(ヌル終端)を，入力した順に並べたもの |
| 文字列より番地の小さい側(4バイト境界に揃える) | `argv`の配列．各文字列の先頭の領域の中の番地を並べ，最後に`nullptr`を置く．`argv[0]`はコマンド名(入力したとおりの綴り)である |
| 配列より番地の小さい側の，隣の4バイト | SPが指す位置．Pyntaxisの`call`が戻り先を積む位置にあたるが，値は不定で，戻り先としては使えない |
| SP-8 | `argc`(`int`)．コマンド名と引数を合わせた数(1以上) |
| SP-4 | `argv`(`char **`)．`argv`の配列の先頭の領域の中の番地 |

`argc`・`argv`の位置は，2つの引数を渡す関数へPyntaxisの`call`で入った直後の，引数の位置と同じである．  
このため，Pynesisの`main`は，ほかの関数と同じ呼び出し規約で引数を読める([pynesis/compiler/call.md](../../pynesis/compiler/call.md)の「実行ファイルのmain」を参照)．  

# 実行ファイルが終わったとき
実行ファイルの終わり方は，次の2通りである．  
どちらの場合も，実行ファイルへは戻らない．  

- 終了のシステムコールで終わる: 実行ファイルが終了のシステムコールを実行した場合である．Pynesisでは，`main`から戻ると終了のシステムコールを実行する  
- 例外で終わる: 実行ファイルが例外を起こした場合である．例外が実行ファイルのどの関数の中で起きても，同じように終わる  

## 終了のシステムコールで終わる場合
CPUは，カーネルモードでシステムコールハンドラ([qosmos/kernel/syscall.md](syscall.md)を参照)へ飛ぶ．  
システムコールハンドラは，次の順に処理する．  

1. SPを，実行の手順の手順8で控えた値に戻す  
2. 実行ファイルが渡した値(終了状態)を戻り値として，実行ファイルへ入る関数の呼び出し元へ戻る  

## 例外で終わる場合
CPUは，カーネルモードで例外ハンドラへ飛ぶ([qurge/cpu/mode.md](../../qurge/cpu/mode.md)の「ユーザーモードの例外」を参照)．  
例外ハンドラは，次の順に処理する．  

1. SPを，実行の手順の手順8で控えた値に戻す  
2. ECAUSEの値(例外の原因)を，実行の手順の手順4で0にした変数へ控える  
3. KRETの値(例外を起こした命令のPC)を，別のOSの変数へ控える  
4. 実行ファイルへ入る関数の呼び出し元へ戻る．このときの戻り値は，意味のある値にならない  

## 終わり方の見分け方
シェルは，実行の手順の手順4で0にした変数を見て，終わり方を見分ける．  
見分けた後は，終わり方ごとに次のように処理し，プロンプトを表示して次の入力を待つ．  

| 変数の値 | 終わり方 | シェルの処理 |
|:-|:-|:-|
| 0のまま | 終了のシステムコールで終わった | 戻り値を終了状態にする |
| 0以外 | 例外で終わった | 戻り値は使わない．控えた原因とPCから，エラーメッセージを1行出力する([qosmos/program/executable.md](../program/executable.md)の「例外を起こした場合」を参照)．終了状態を1にし，例外の番号を覚える |

終了状態と例外の番号は，[qosmos/user/shell.md](../user/shell.md)の「終了状態」を参照．  

# SPを書き換える関数
実行ファイルへ入る関数と，システムコールハンドラ・例外ハンドラは，SPを書き換える．  
これらの関数は，フレームの大きさを0にするため，引数・ローカル変数を持たず，値はグローバル変数に置く([pynesis/language/hardware.md](../../pynesis/language/hardware.md)の「SPへ書き込める関数」を参照)．  
システムコールハンドラと例外ハンドラは，SPを戻すまで関数を呼ばない．  
飛んできた直後のSPは領域の中の番地のままであり，カーネルモードではそのまま使えないためである．
