# 実行ファイルを動かす仕組み
実行ファイルから見た動作は，[qosmos/program/executable.md](../program/executable.md)を参照．  

# 実行の手順
シェルは，次の順に実行ファイルを動かす．  

1. `/bin`から実行ファイルを探し，大きさを確かめる([qosmos/program/executable.md](../program/executable.md)の「実行できない場合」を参照)  
2. 実行ファイルの内容を，領域([qosmos/kernel/memory.md](memory.md)の「実行ファイルの領域」を参照)の先頭から書き写す  
3. telnetで接続した端末へ，ためた出力を送る  
4. 例外の原因を控えるOSの変数を，例外で終わっていないことを表す0にする(「例外を起こした場合」を参照)  
5. 領域をUBASE・USIZEに，システムコールハンドラの番地をKENTRYに，例外ハンドラの番地をEENTRYに書き込む([qurge/cpu/register.md](../../qurge/cpu/register.md)を参照)  
6. 実行ファイルへ入る先として，領域の先頭の命令(領域の中のPC 0)をKRETに書き込む  
7. コマンド名と引数を引数の置き場に置き，SPを決める(「引数の置き方」を参照)  
8. カーネルモードのSPを控えてから，SPを引数を置いて決めた値にし，組み込み関数`sysret`でユーザーモードへ移る  
9. 実行ファイルが終わると，終わり方に応じて次のことを行い，プロンプトを表示して次の入力を待つ(終わり方の見分け方は「例外を起こした場合」を参照)  
    - 終了のシステムコールを実行した: 渡された値を終了状態とする(「終了の手順」を参照)  
    - 例外を起こした: 例外の原因をエラーメッセージで出力し，例外の番号を終了状態とする(「例外を起こした場合」を参照)  

終了状態は，[qosmos/user/shell.md](../user/shell.md)の「終了状態」を参照．  

読み込みの途中で読み出しに失敗した場合は，領域に書き写した内容は途中のまま残り，実行はしない．  

# 引数の置き方
コマンド名と引数は，シェルの入力の解析([qosmos/user/shell.md](../user/shell.md)の「入力の解析」を参照)と同じく半角空白で区切り，区切りの空白は文字列に含めない．  
実行ファイルが始まる時点の引数の置き場は，次のとおりである．  

| 位置 | 内容 |
|:-|:-|
| 領域の末尾 | コマンド名と各引数の文字列(ヌル終端)を，入力した順に並べたもの |
| 文字列より番地の小さい側(4バイト境界に揃える) | `argv`の配列．各文字列の先頭の領域の中の番地を並べ，最後に`nullptr`を置く．`argv[0]`はコマンド名(入力したとおりの綴り)である |
| 配列より番地の小さい側の，隣の4バイト | SPが指す位置．Pyntaxisの`call`が戻り先を積む位置にあたるが，値は不定で，戻り先としては使えない |
| SP-8 | `argc`(`int`)．コマンド名と引数を合わせた数(1以上) |
| SP-4 | `argv`(`char **`)．`argv`の配列の先頭の領域の中の番地 |

`argc`・`argv`の位置は，2つの引数を渡す関数へPyntaxisの`call`で入った直後の，引数の位置と同じである．  
このため，Pynesisの`main`は，ほかの関数と同じ呼び出し規約で引数を読める([pynesis/compiler/call.md](../../pynesis/compiler/call.md)の「実行ファイルのmain」を参照)．  

# 終了の手順
実行ファイルが終了のシステムコールを実行すると，システムコールハンドラ([qosmos/kernel/syscall.md](syscall.md)を参照)は次のように戻る．  

1. SPを，実行ファイルへ入る前に控えたカーネルモードのSPに戻す  
2. 渡された値を終了状態として，実行ファイルへ入る処理の呼び出し元へ戻る  

実行ファイルへは戻らない．  

# 例外を起こした場合
実行ファイルが例外を起こすと，CPUはカーネルモードで例外ハンドラへ飛ぶ([qurge/cpu/mode.md](../../qurge/cpu/mode.md)の「ユーザーモードの例外」を参照)．  
例外ハンドラは，次のように戻る．  
1と3は，終了の手順と同じである．  

1. SPを，実行ファイルへ入る前に控えたカーネルモードのSPに戻す  
2. 例外の原因(ECAUSEの値)と，例外を起こした命令のPC(KRETの値)を，OSの変数へ控える  
3. 実行ファイルへ入る処理の呼び出し元へ戻る  

実行ファイルへは戻らない．  
終了の手順と異なり，実行ファイルへ入る処理の戻り値は不定である．  

シェルは，例外の原因を控えた変数が0以外であることで，例外で終わったと見分ける．  
実行の手順で，実行ファイルへ入る前にこの変数を0にしておくためである．  
例外で終わった場合は，実行ファイルへ入る処理の戻り値を使わない．  
控えた原因とPCをエラーメッセージで出力し([qosmos/program/executable.md](../program/executable.md)の「例外を起こした場合」を参照)，例外の番号を終了状態とする([qosmos/user/shell.md](../user/shell.md)の「終了状態」を参照)．  

# SPを書き換える関数
実行ファイルへ入る処理と，システムコールハンドラ・例外ハンドラは，SPを書き換える．  
これらの関数は，フレームの大きさを0にするため，引数・ローカル変数を持たず，値はグローバル変数に置く([pynesis/language/hardware.md](../../pynesis/language/hardware.md)の「SPへ書き込める関数」を参照)．
