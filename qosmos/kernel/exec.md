# 実行ファイルを動かす仕組み
実行ファイルから見た動作は，[qosmos/program/executable.md](../program/executable.md)を参照．  

QosmosはROM上のプログラムとしてカーネルモードで動き，シェルもその一部である．実行ファイルは，Qosmosが割り振ったメモリの領域([qosmos/kernel/memory.md](memory.md)の「実行ファイルの領域」と「領域の割り振り」を参照．以下，領域と書く)の中で，ユーザーモードで動く．メモリに置いた実行ファイルを，プロセスと呼ぶ．  

実行ファイルを起動するのは，次の2つである．どちらも同じ手順で起動し(「起動の手順」を参照)，起動した実行ファイルが終わるまで待つ．  

- シェル: 入力したコマンド名と同じ名前の実行ファイルを起動する([qosmos/user/shell.md](../user/shell.md)の「入力の解析」を参照)  
- 実行ファイル: 子を起動するシステムコール([qosmos/program/syscall.md](../program/syscall.md)の「実行ファイルを起動する」を参照)で，別の実行ファイルを起動する．起動した側のプロセスを親，起動された側のプロセスを子と呼ぶ  

同時に動くプロセスは1つだけである．子が動いている間，親は止まったまま，領域をメモリに残す．  

# プロセスの表
Qosmosは，プロセスごとに次の値を記録した表(以下，プロセスの表)をOSの変数に持つ．表の要素数は16で，同時にメモリに置けるプロセスの数の上限になる．上限を16とした理由は，[qosmos/kernel/memory.md](memory.md)の「プロセスの数の上限」を参照．  

| 値 | 内容 |
|:-|:-|
| 親 | 親の表の位置．シェルが起動したプロセスは，親を持たない |
| 領域 | 領域の先頭のメモリの番地と，大きさ |
| 子の終了を待つ間の値 | 親を再開するために控える値(「子の起動」を参照)．子が動いている間だけ意味を持つ |

表の要素は，プロセスが終わるまで位置を変えない．親を表の位置で指すためである．Qosmosは，実行中のプロセスの表の位置も持つ．シェルが動いている間は，実行中のプロセスは無い．  

# 起動の手順
Qosmosは，次の順に実行ファイルを起動する．起動を求める1行は，コマンド名と引数を半角空白で区切ったものである．  

1. 1行の先頭をコマンド名とし，`/bin`から同じ名前の実行ファイルを探す．大きさがヘッダと1命令を合わせた24バイト以上かを確かめる．条件に合わなければ実行しない([qosmos/program/executable.md](../program/executable.md)の「実行できない場合」を参照)  
2. 実行ファイルの先頭のセクタを読み出し，ヘッダが条件([qosmos/program/executable.md](../program/executable.md)の「形式」を参照)に合うかを確かめる．条件に合わなければ実行しない  
3. プロセスの表に，実行中のプロセスを親として要素を加え，ヘッダに書かれた大きさの領域を空きから割り振る([qosmos/kernel/memory.md](memory.md)の「領域の割り振り」を参照)．加えられなければ実行しない  
4. ヘッダの後ろの命令列を，領域の先頭から書き写す．読み込みの途中で読み出しに失敗した場合は，要素を表から外し，実行しない  
5. それまでの出力のうち，telnetで接続した端末へまだ送っていないものを送る．シェルは端末への出力をためておき，次に入力を待つときにまとめて送る．実行ファイルが動いている間はシェルが入力を待たないため，ここで送っておく  
6. 親があれば，親を再開するための値をプロセスの表へ控える(「子の起動」を参照)  
7. 起動するプロセスを，実行中のプロセスにする  
8. UBASE・USIZEに領域を，KENTRYにシステムコールハンドラの番地を，EENTRYに例外ハンドラの番地を書き込む([qurge/cpu/register.md](../../qurge/cpu/register.md)を参照)  
9. KRETに0(実行ファイルの先頭の命令のPC)を書き込む  
10. コマンド名と引数を，領域の末尾の256バイト(以下，引数の置き場と書く)に置く．置いた結果から，実行ファイルが使い始めるSPの値が決まる(「引数の置き方」を参照)  
11. 実行ファイルへ入る関数を呼ぶ．この関数は，今のSPをOSの変数に控える．ここで控えるSPは，カーネルモードのスタックで，この関数の戻り先を指している  
12. 実行ファイルへ入る関数が，SPを，実行ファイルが使い始めるSPの値に変える  
13. 実行ファイルへ入る関数が，組み込み関数`sysret`でユーザーモードへ移る．CPUは，実行ファイルの先頭の命令から実行を始める  

実行ファイルが終わると，システムコールハンドラか例外ハンドラが，実行ファイルへ入る関数の呼び出し元へ直接戻る(「実行ファイルが終わったとき」を参照)．このため，実行ファイルへ入る関数は，自身の末尾まで実行されることがない．呼び出し元は，戻った直後に次の順に処理する．  

1. 終わり方(終了状態，例外の原因とPC)を受け取り，例外の原因を控える変数を0に戻す(「終わり方の見分け方」を参照)  
2. 親を実行中のプロセスに戻す．親があれば，控えた値から親を再開できる状態に戻す(「子の起動」を参照)  
3. 終わったプロセスの要素を表から外す．領域は，空きに戻る  

# 引数の置き方
コマンド名と引数は，シェルの入力の解析([qosmos/user/shell.md](../user/shell.md)の「入力の解析」を参照)と同じく半角空白で区切り，区切りの空白は文字列に含めない．実行ファイルが始まる時点の引数の置き場は，次のとおりである．  

| 位置 | 内容 |
|:-|:-|
| 領域の末尾 | コマンド名と各引数の文字列(ヌル終端)を，並んでいた順に並べたもの |
| 文字列より番地の小さい側(4バイト境界に揃える) | `argv`の配列．各文字列の先頭の領域の中の番地を並べ，最後に`nullptr`を置く．`argv[0]`はコマンド名(起動を求めた1行のとおりの綴り)である |
| 配列より番地の小さい側の，隣の4バイト | SPが指す位置．Pyntaxisの`call`が戻り先を積む位置にあたるが，値は不定で，戻り先としては使えない |
| SP-8 | `argc`(`int`)．コマンド名と引数を合わせた数(1以上) |
| SP-4 | `argv`(`char **`)．`argv`の配列の先頭の領域の中の番地 |

`argc`・`argv`の位置は，2つの引数を渡す関数へPyntaxisの`call`で入った直後の，引数の位置と同じである．このため，Pynesisの`main`は，ほかの関数と同じ呼び出し規約で引数を読める([pynesis/compiler/call.md](../../pynesis/compiler/call.md)の「実行ファイルのmain」を参照)．  

# 実行ファイルが終わったとき
実行ファイルの終わり方は，次の2通りである．  

- 終了のシステムコールで終わる: 実行ファイルが終了のシステムコールを実行した場合である．Pynesisでは，`main`から戻ると終了のシステムコールを実行する  
- 例外で終わる: 実行ファイルが例外を起こした場合である．例外が実行ファイルのどの関数の中で起きても，同じように終わる  

## 終了のシステムコールで終わる場合
CPUは，カーネルモードへ移り，システムコールハンドラ([qosmos/kernel/syscall.md](syscall.md)を参照)へ飛ぶ．システムコールハンドラは，次の順に処理する．  

1. SPを，実行ファイルへ入る関数が控えた値に戻す  
2. 実行ファイルが渡した値(終了状態)を戻り値として，実行ファイルへ入る関数の呼び出し元へ戻る  

## 例外で終わる場合
CPUは，カーネルモードへ移り，例外ハンドラへ飛ぶ([qurge/cpu/mode.md](../../qurge/cpu/mode.md)の「ユーザーモードの例外」を参照)．例外ハンドラは，次の順に処理する．  

1. SPを，実行ファイルへ入る関数が控えた値に戻す  
2. ECAUSEの値(例外の原因)を，例外の原因を控える変数へ書き写す  
3. KRETの値(例外を起こした命令のPC)を，別のOSの変数へ控える  
4. 実行ファイルへ入る関数の呼び出し元へ戻る．このときの戻り値は，意味のある値にならない  

## 終わり方の見分け方
実行ファイルへ入る関数の呼び出し元は，例外の原因を控える変数を見て，終わり方を見分ける．この変数は，例外ハンドラが書き写してから呼び出し元が終わり方を受け取るまでの間だけ0以外になる．例外の番号は1以上のため，0は例外で終わっていないことを表す．受け取った直後に0へ戻すのは，子が例外で終わった後に親が終了のシステムコールで終わった場合に，子の例外の原因を親のものと取り違えないためである．  

| 変数の値 | 終わり方 | 受け取る値 |
|:-|:-|:-|
| 0のまま | 終了のシステムコールで終わった | 戻り値(終了状態) |
| 0以外 | 例外で終わった | 例外の原因と，例外を起こした命令のPC．戻り値は使わない |

受け取った終わり方は，起動を求めた側が次のように扱う．  

- シェル: 例外で終わった場合は，控えた原因とPCから，エラーメッセージを1行出力する([qosmos/program/executable.md](../program/executable.md)の「例外を起こした場合」を参照)．終了状態と例外の番号は，[qosmos/user/shell.md](../user/shell.md)の「終了状態」を参照  
- 実行ファイル: 子を起動するシステムコールの結果として親へ返す([qosmos/program/syscall.md](../program/syscall.md)の「実行ファイルを起動する」を参照)．Qosmosはメッセージを出力しない  

# 子の起動
親は，子を起動するシステムコールでカーネルモードへ入る．Qosmosは，そのシステムコールの処理の中から，「起動の手順」で子を起動する．子が終わると，システムコールの処理の続きへ戻り，結果を親へ返す．  

子を動かすと，UBASE・USIZE・KRETと，システムコールハンドラが控えるSPが子の値に変わる．このため，子を実行中のプロセスにする前に，親を再開するための次の値をプロセスの表の親の要素へ控え，子が終わった後に戻す．r0〜r15とRAXは，システムコールで値を保たない取り決めのため控えない([qosmos/kernel/syscall.md](syscall.md)の「受け付けの手順」を参照)．  

| 控える値 | 戻した後の使い道 |
|:-|:-|
| 親がシステムコールの命令を実行した時点のSP(領域の中の番地) | システムコールの処理を終えて，親のスタックへ戻す |
| KRETの値(親のシステムコールの命令の次の命令のPC) | 組み込み関数`sysret`で，親の続きへ戻る |
| 親へ入る関数が控えたカーネルモードのSP | 親が終わったときに，親を起動した関数へ戻る |

UBASE・USIZEは，表の親の領域から戻す．  

子を実行する関数のフレームは，親のシステムコールを処理している途中のカーネルモードのスタックの上に積む．子がさらに子を起動するたびに，カーネルモードのスタックは1段ずつ深くなる．  

# SPを書き換える関数
実行ファイルへ入る関数と，システムコールハンドラ・例外ハンドラは，SPを書き換える．これらの関数は，フレームの大きさを0にするため，引数・ローカル変数を持たず，値はグローバル変数に置く([pynesis/language/hardware.md](../../pynesis/language/hardware.md)の「SPへ書き込める関数」を参照)．システムコールハンドラと例外ハンドラは，SPを戻すまで関数を呼ばない．飛んできた直後のSPは領域の中の番地のままであり，カーネルモードではそのまま使えないためである．
