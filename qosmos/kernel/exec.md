# プロセス
実行ファイルを作る人から見た動作は，[qosmos/program/executable.md](../program/executable.md)を参照．  

QosmosはROM上のプログラムとしてカーネルモードで動き，シェルもその一部である．プロセスは，Qosmosが割り振ったメモリの範囲(以下，領域．[qosmos/kernel/memory.md](memory.md)の「プロセスの領域」を参照)の中で，ユーザーモードで動く．  

実行ファイルを起動するのは，シェルとプロセスの2つである．起動した側は，コマンド名と引数を半角空白で区切った1行(以下，起動を求める1行)をQosmosへ渡す．  

| 起動する側 | 起動の方法 | 起動を求める1行 |
|:-|:-|:-|
| シェル | 入力したコマンド名と同じ名前の実行ファイルを起動する([qosmos/user/shell.md](../user/shell.md)の「入力の解析」を参照) | 入力した1行 |
| プロセス | システムコール`spawn`で起動する([qosmos/program/syscall.md](../program/syscall.md)の「実行ファイルを起動する」を参照) | `spawn`に指定した1行 |

プロセスが別の実行ファイルを起動した場合，起動した側のプロセスを親，起動された側のプロセスを子と呼ぶ．起動した側は，起動された側のプロセスが終わるまで止まる．このため，同時に動くプロセスは1つだけである．子の終了を待つ親は，領域をメモリに残したまま止まる．  

# プロセステーブル
Qosmosは，メモリに置いたプロセスを，プロセステーブルに記録する．プロセステーブルは，プロセスごとに次の値を持つQosmosの変数の配列である．要素数は16で，同時にメモリに置けるプロセスの数の上限になる([qosmos/kernel/memory.md](memory.md)の「プロセスの数の上限」を参照)．  

| 値 | 内容 |
|:-|:-|
| 親 | 親のプロセステーブルでの位置．シェルが起動したプロセスは，親を持たない |
| 領域 | 領域の先頭のメモリの番地と，大きさ |
| 再開するための値 | プロセスがカーネルモードへ入った時点のレジスタなど，止めたプロセスを再開するのに要る値(「カーネルモードへ入るときと戻るとき」を参照) |

各要素は，プロセスが終わるまで位置を変えない．親をプロセステーブルでの位置で指すためである．  
Qosmosは，実行中のプロセスのプロセステーブルでの位置も持つ．シェルが動いている間は，実行中のプロセスは無い．  

# 起動と終了の手順
Qosmosは，起動した側がシェルとプロセスのどちらでも，次の順に実行ファイルを起動し，終わった後を処理する．起動した側がプロセスの場合にだけ行う処理は，その旨を書く．  

## 読み込み
1. 起動を求める1行の先頭をコマンド名とし，`/bin`から同じ名前の実行ファイルを探す．大きさが，ヘッダと1命令を合わせた24バイト以上かを確かめる  
2. 実行ファイルの先頭のセクタを読み出し，ヘッダが条件([qosmos/program/executable.md](../program/executable.md)の「形式」を参照)に合うかを確かめる  
3. プロセステーブルに要素を加え，ヘッダに書かれた大きさから決まる領域を空きから割り振る([qosmos/kernel/memory.md](memory.md)の「領域の割り振り」を参照)．実行中のプロセスがあれば，そのプロセスを親とする．再開するための値のうち，再開する命令のPCを0(実行ファイルの先頭の命令)に，r0〜r15・RSI・RAXを0にする．SPとカーネルモードのSPは，プロセスへ入るときに決める  
4. ヘッダの後ろの命令列を，領域の先頭から書き写す  

実行ファイルが条件に合わない場合と，読み出しに失敗した場合は，実行しない([qosmos/program/executable.md](../program/executable.md)の「実行できない場合」を参照)．要素を加えた後に命令列の読み出しに失敗した場合は，加えた要素をプロセステーブルから外す．  

## プロセスへ入る
1. それまでの出力のうち，telnetで接続した端末へまだ送っていないものを送る．シェルは端末への出力をためておき，次に入力を待つときにまとめて送る．プロセスが動いている間はシェルが入力を待たないため，ここで送っておく  
2. 起動するプロセスを，実行中のプロセスにする  
3. 起動するプロセスの再開するための値を，プロセステーブルから戻す(「カーネルモードへ入るときと戻るとき」の「戻る手順」を参照)．UBASE・USIZEに領域が，KRETに0(実行ファイルの先頭の命令のPC)が入る  
4. コマンド名と引数を，領域の末尾の256バイト(以下，引数の置き場)に置く．置いた位置から決まる値(「引数の置き方」を参照)を，再開するための値のSPにする  
5. プロセスへ入る関数を呼ぶ．この関数は，今のSPを，再開するための値のカーネルモードのSPとして控える．控えるSPは，カーネルモードのスタックで，この関数の戻り先を指している  
6. プロセスへ入る関数が，プロセスへ戻る関数を呼ぶ(「戻る手順」を参照)．CPUは，実行ファイルの先頭の命令から，r0〜r15・RSI・RAXを0として実行を始める  

## 終わった後
プロセスが終わると，システムコールハンドラか例外ハンドラが，プロセスへ入る関数の呼び出し元へ直接戻る(「プロセスが終わったとき」を参照)．このため，プロセスへ入る関数は，自身の末尾まで実行されることがない．呼び出し元は，戻った直後に次の順に処理する．  

1. 終わり方を受け取る(「終わり方の見分け方」を参照)  
2. 起動した側がプロセスの場合は，そのプロセス(親)を実行中のプロセスに戻し，親の再開するための値をプロセステーブルから戻す(「子の終了を待つ親」を参照)．起動した側がシェルの場合は，実行中のプロセスが無い状態に戻す  
3. 終わったプロセスの要素を，プロセステーブルから外す．領域は，空きに戻る  
4. 起動した側へ，終わり方を伝える  
    - シェル: 例外で終わった場合は，エラーメッセージを1行出力する([qosmos/program/executable.md](../program/executable.md)の「例外を起こした場合」を参照)．終了状態と例外の番号の扱いは，[qosmos/user/shell.md](../user/shell.md)の「終了状態」を参照  
    - プロセス: `spawn`の結果として返し，親の`spawn`の続きへ戻る([qosmos/program/syscall.md](../program/syscall.md)の「実行ファイルを起動する」を参照)．Qosmosはメッセージを出力しない  

## 子の終了を待つ親
プロセスは，`spawn`のシステムコールでカーネルモードへ入り，Qosmosはその処理の中から子を起動する．親の再開するための値は，カーネルモードへ入ったときにプロセステーブルの親の要素へ控えてある(「カーネルモードへ入るときと戻るとき」を参照)．子を動かすと，CPUのレジスタと，再開するための値を置くQosmosの変数は，子の値に変わる．このため，Qosmosは子が終わった後に，親の要素から再開するための値を戻してから，親の`spawn`の処理を続ける．  

子を実行する関数のフレームは，親の`spawn`を処理している途中のカーネルモードのスタックの上に積む．子がさらに子を起動するたびに，カーネルモードのスタックは1段ずつ深くなる．  

# 引数の置き方
コマンド名と引数は，シェルの入力の解析([qosmos/user/shell.md](../user/shell.md)の「入力の解析」を参照)と同じく，1行を半角空白で区切ったものである．区切りの空白は，文字列に含めない．プロセスが始まる時点の引数の置き場は，次のとおりである．  

| 位置 | 内容 |
|:-|:-|
| 領域の末尾 | コマンド名と各引数の文字列(ヌル終端)．1行の中の順に，番地の小さい側から置く |
| 文字列より番地の小さい側(4バイト境界に揃える) | `argv`の配列．各文字列の先頭の領域の中の番地を並べ，最後に`nullptr`を置く．`argv[0]`はコマンド名(1行に書かれたとおりの綴り)である |
| 配列より番地の小さい側の，隣の4バイト | SPが指す位置．Pyntaxisの`call`が戻り先を積む位置にあたるが，値は不定で，戻り先としては使えない |
| SP-8 | `argc`(`int`)．コマンド名と引数を合わせた数(1以上) |
| SP-4 | `argv`(`char **`)．`argv`の配列の先頭の領域の中の番地 |

`argc`・`argv`の位置は，2つの引数を渡す関数へPyntaxisの`call`で入った直後の，引数の位置と同じである．このため，Pynesisの`main`は，ほかの関数と同じ呼び出し規約で引数を読める([pynesis/compiler/call.md](../../pynesis/compiler/call.md)の「実行ファイルのmain」を参照)．  

# カーネルモードへ入るときと戻るとき
プロセスは，システムコールの命令・タイマー割り込み・例外で，カーネルモードへ入る([qurge/cpu/mode.md](../../qurge/cpu/mode.md)の「動作状態の切り替え」を参照)．Qosmosは，次のように扱う．  

- システムコールの命令とタイマー割り込み: 同じ手順で再開するための値を控え，同じ手順でプロセスへ戻る  
- 例外: 再開するための値を控えず，プロセスを終わらせる(「例外で終わる場合」を参照)  

## 再開するための値
| 値 | 内容 |
|:-|:-|
| SP(領域の中の番地) | カーネルモードへ入った時点のSP |
| 再開する命令のPC | KRET．CPUが，システムコールではシステムコールの命令の次の命令，タイマー割り込みでは割り込みで止めた命令のPCを書き込む |
| r0〜r15・RSI・RAX | カーネルモードへ入った時点の各レジスタ |
| カーネルモードのSP | プロセスへ入る関数が控えたSP．このプロセスが終わったときに，ハンドラがプロセスへ入る関数の呼び出し元へ戻るために使う |

次のレジスタは控えない．  

- FLG: どの命令も書き換えないため([qurge/cpu/register.md](../../qurge/cpu/register.md)の「フラグについて」を参照)  
- UBASE・USIZE: プロセステーブルの領域から戻せるため  
- KENTRY・EENTRY・IENTRY・TINTERVAL: 起動の手順で書き込んだ後は，どのプロセスでも同じ値のため([qosmos/kernel/boot.md](boot.md)の「起動の手順」を参照)  

## 控える手順
システムコールハンドラと割り込みハンドラは，飛んできた直後に次の順に処理する．  

1. SPを，再開するための値を置くQosmosの変数に控え，SPを，プロセスへ入る関数が控えたカーネルモードのSPに切り替える．両方のハンドラに同じ命令を書く  
2. r0〜r15・RSI・RAXを，再開するための値を置くQosmosの変数に控える．両方のハンドラが呼ぶ，レジスタを控える共通の関数で行う  
3. 変数に控えた値・KRET・カーネルモードのSPを，プロセステーブルの実行中のプロセスの要素へ写す  

各手順の書き方には，次の制約がある．  

- SPとレジスタの控え: Pynesisの文がレジスタを書き換える前に行うため，asm文で書く([pynesis/language/asm.md](../../pynesis/language/asm.md)の「呼ばれた時点のレジスタを扱う位置」を参照)  
- SPの切り替え: 切り替えるまでは，関数を呼ばない．SPが領域の中の番地のままであり，カーネルモードのCALLは戻り先を積めないためである([qurge/cpu/mode.md](../../qurge/cpu/mode.md)の「メモリを読み書きできる範囲」を参照)．このため，SPの控えと切り替えは関数に切り出さず，各ハンドラに書く  
- 要素へ写す前に変数へ控えること: asm文に埋め込めるのはコンパイル時に決まる番地だけで，実行中のプロセスの要素の番地を埋め込めないためである  

## 戻る手順
プロセスへ戻る関数は，再開するための値を置くQosmosの変数から，SP・r0〜r15・RSI・RAXを各レジスタへ読み込み，組み込み関数`sysret`と同じ命令でユーザーモードへ移る．CPUは，KRETの命令から実行を続ける．読み込みと`sysret`は，Pynesisの文がレジスタを書き換えないよう，1つのasm文で書く．  
システムコールから戻る場合も，r0〜r15・RSI・RAXは控えた値に戻る．ただし，プロセスとの取り決めでは，システムコールの後のr0〜r15とRAXの値を保たない([qosmos/program/syscall.md](../program/syscall.md)を参照)．このため，プロセスはこの値に頼らない．  

Qosmosの変数には，控える手順の後は，実行中のプロセスの値が残っている．次の場合は，プロセスへ戻る関数を呼ぶ前に，プロセステーブルの要素から，UBASE・USIZE・KRETとQosmosの変数へ再開するための値を戻す．  

- プロセスを起動するとき: 起動するプロセスの要素から戻す(「プロセスへ入る」を参照)  
- 子が終わった後: 親の要素から戻す(「子の終了を待つ親」を参照)  
- タイマー割り込みで止めた後: 止めたプロセスの要素から戻す(「タイマー割り込み」を参照)  

# タイマー割り込み
Qosmosは，起動の手順でタイマー割り込みを有効にし，割り込み周期を1000000サイクル(10ms)にする([qurge/cpu/timer-interrupt.md](../../qurge/cpu/timer-interrupt.md)を参照)．タイマーは止めず，カーネルモードの間もサイクル数を数える．  

カーネルモードの間は，CPUは割り込みハンドラへ飛ばない．その間にタイマーが割り込み周期に達した場合，CPUは，次にプロセスへ移った直後，プロセスの次の命令を取り出す前に割り込みハンドラへ飛ぶ([qurge/cpu/timer-interrupt.md](../../qurge/cpu/timer-interrupt.md)の「割り込みハンドラへ飛ぶ時点」を参照)．このため，割り込まれるのはプロセスが動いている間だけだが，起動されたプロセスが先頭の命令を実行する前や，システムコールから戻った直後にも割り込まれうる．どの場合も，同じ手順でプロセスへ戻る．  

CPUは，割り込みハンドラへ飛ぶとカーネルモードへ移る．割り込みハンドラは，次の順に処理する．  

1. 再開するための値を控える(「カーネルモードへ入るときと戻るとき」の「控える手順」を参照)  
2. 同じプロセスの要素から，再開するための値を戻す．プロセスを切り替えないため，戻す値は控えた値と同じである．要素から戻すのは，起動するときや親へ戻るときと同じく，要素の値から再開するためである  
3. プロセスへ戻る関数を呼ぶ．プロセスは，割り込みで止めた命令から続きを実行する  

プロセスから見ると，止められる前と後で，レジスタ・メモリの値は変わらない．このため，プロセスの動作と結果は，割り込まれない場合と同じである．  

# プロセスが終わったとき
プロセスの終わり方は，次の2通りである．  

- 終了のシステムコールで終わる: プロセスが終了のシステムコールを実行した場合である．Pynesisでは，`main`から戻ると終了のシステムコールを実行する  
- 例外で終わる: プロセスが例外を起こした場合である．例外が実行ファイルのどの関数の中で起きても，同じように終わる  

## 終了のシステムコールで終わる場合
CPUは，カーネルモードへ移り，システムコールハンドラ([qosmos/kernel/syscall.md](syscall.md)を参照)へ飛ぶ．システムコールハンドラは，ほかのシステムコールと同じく再開するための値を控える(「控える手順」を参照)．このとき，SPは，プロセスへ入る関数が控えた値に切り替わっている．その後，プロセスが渡した値(終了状態)を戻り値として，プロセスへ入る関数の呼び出し元へ戻る．  

## 例外で終わる場合
CPUは，カーネルモードへ移り，例外ハンドラへ飛ぶ([qurge/cpu/exception.md](../../qurge/cpu/exception.md)の「例外ハンドラへ飛ぶ処理」を参照)．例外ハンドラは，次の順に処理する．  

1. SPを，プロセスへ入る関数が控えた値に戻す  
2. ECAUSEの値(例外の原因)を，例外の原因を控える変数へ書き写す  
3. KRETの値(例外を起こした命令のPC)を，Qosmosの別の変数へ控える  
4. プロセスへ入る関数の呼び出し元へ戻る．このときの戻り値は，意味のある値にならない  

## 終わり方の見分け方
プロセスへ入る関数の呼び出し元は，例外の原因を控える変数を見て，終わり方を見分ける．  

| 変数の値 | 終わり方 | 受け取る値 |
|:-|:-|:-|
| 0 | 終了のシステムコールで終わった | 戻り値(終了状態) |
| 0以外 | 例外で終わった | 例外の原因と，例外を起こした命令のPC．戻り値は使わない |

例外の番号は1以上のため，0は例外で終わっていないことを表す．呼び出し元は，終わり方を受け取った直後に，この変数を0へ戻す．後で終わるプロセスが，前に例外で終わったプロセスの例外を，自分のものと取り違えないためである．

# フレームの大きさを0にする関数
次の関数は，フレームの大きさを0にする．引数・ローカル変数を持たず，値はグローバル変数に置く．  

| 関数 | 理由 |
|:-|:-|
| プロセスへ入る関数 | 控えるSPが，この関数の戻り先を指すようにするため．プロセスが終わると，ハンドラはSPをこの値に戻してから戻る |
| システムコールハンドラ・割り込みハンドラ・例外ハンドラ・プロセスへ戻る関数 | SPを書き換えるため．フレームを持つ関数は，書き換えた後のSPを基準にフレームを読み書きしてしまう([pynesis/language/hardware.md](../../pynesis/language/hardware.md)の「SPへ書き込める関数」を参照) |
| システムコールハンドラ・割り込みハンドラ・レジスタを控える共通の関数 | カーネルモードへ入った時点のレジスタをasm文で扱うため．フレームを持つ関数では，フレームを確保する命令が，asm文より前にレジスタを書き換える([pynesis/language/asm.md](../../pynesis/language/asm.md)の「呼ばれた時点のレジスタを扱う位置」を参照) |

コンパイラがフレームの有無を検査するのは，SPへ値を書き込む式を書いた関数だけである([pynesis/language/hardware.md](../../pynesis/language/hardware.md)の「SPへ書き込める関数」を参照)．asm文でSPを書き換える関数と，SPを読むだけの関数は検査されない．このため，表のどの関数も，引数・ローカル変数を持たず，式の評価でレジスタを退避しないよう，書く人が守る．
