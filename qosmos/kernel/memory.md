# メモリの割り振り
Qosmosは，メインメモリ([qurge/memory.md](../../qurge/memory.md)を参照)を前半と後半に分けて，次のように割り振る．  
前半・後半の範囲と，動作状態ごとにCPUが読み書きできる範囲は，[qurge/cpu/mode.md](../../qurge/cpu/mode.md)の「メモリを読み書きできる範囲」を参照．  

| 番地 | 用途 |
|:-|:-|
| メモリの前半(`0x0000`〜`0x7FFF`) | Qosmos自身の変数とスタック．ROMのプログラムとして，グローバル変数を0番地から上へ置き，カーネルモードのスタックを前半の末尾から下へ伸ばす([pynesis/language/limit.md](../../pynesis/language/limit.md)の「変数に使えるメモリ」を参照) |
| メモリの後半(`0x8000`〜`0xFFFF`の32768バイト) | 実行ファイルに割り振る領域(「実行ファイルの領域」を参照) |

メモリの後半は，カーネルモードで実行したPyntaxisの`call`・`ret`が戻り先を積み下ろししない範囲である．  
このため，Qosmosのスタックが実行ファイルの領域を書き換えることはない．  

## メモリの容量を変える場合
領域の位置と大きさは，メモリの容量の半分から決まる．  
容量を変える場合は，次のものも合わせて変える．  

- 領域の位置と大きさ  
- 領域の大きさから決まる，アセンブラの実行ファイルの命令数の上限([pyntaxis/language/target.md](../../pyntaxis/language/target.md)の「命令数の上限」を参照)  
- 領域の大きさから決まる，コンパイラの検査の上限([pynesis/compiler/check.md](../../pynesis/compiler/check.md)の「検査に使う値」を参照)  

# 実行ファイルの領域
シェルは，どの実行ファイルにも同じ位置・大きさの領域を割り振る．  
実行ファイルは，領域の先頭を0とする番地(以下，領域の中の番地)で，ユーザーモードとして動く([qurge/cpu/mode.md](../../qurge/cpu/mode.md)の「番地の変換」を参照)．  
領域は，先頭から次のように使う．  

| 領域の中の番地 | 用途 |
|:-|:-|
| `0x0000`から | 実行ファイルの内容(命令の並び．[qosmos/program/executable.md](../program/executable.md)の「形式」を参照) |
| 実行ファイルの内容の直後から，引数の置き場まで | 実行ファイルが自由に使う範囲．スタックは，シェルが引数の置き場の中に決めたSP([qosmos/kernel/exec.md](exec.md)の「引数の置き方」を参照)から下へ伸びる．Pynesisのコンパイラの使い方は，[pynesis/language/limit.md](../../pynesis/language/limit.md)の「変数に使えるメモリ」を参照 |
| `0x7F00`〜`0x7FFF` | 引数の置き場．シェルが実行ファイルへ渡すコマンド名と引数を置く，領域の末尾の256バイト |

実行ファイルの内容とグローバル変数は，合わせて引数の置き場より手前の32512バイトに収まる必要がある．  
使えるスタックの量は保証しない．  
スタックがグローバル変数と重なっても，CPUは検出しない([qurge/cpu/exception.md](../../qurge/cpu/exception.md)の「検出しない不正」を参照)．  

## 引数の置き場の大きさ
引数の置き場の256バイトは，1行の入力([qosmos/user/console.md](../user/console.md)の「1行の入力」を参照)から作るコマンド名と引数を，最も大きくなる場合(211バイト)でも収められる大きさである．  
211バイトは，次の合計である．  

| 内容 | バイト数 |
|:-|:-|
| 文字列(1行分) | 64 |
| 4バイト境界への揃え | 3 |
| `argv`の配列(引数が最も多い32個と`nullptr`の33要素×4バイト) | 132 |
| SPが指す4バイトと，`argc`・`argv`の8バイト | 12 |
