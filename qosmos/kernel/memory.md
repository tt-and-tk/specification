# メモリの割り振り
Qosmosは，メインメモリ([qurge/memory.md](../../qurge/memory.md)を参照)を前半と後半に分けて，次のように割り振る．前半・後半の範囲と，動作状態ごとにCPUが読み書きできる範囲は，[qurge/cpu/mode.md](../../qurge/cpu/mode.md)の「メモリを読み書きできる範囲」を参照．  

| 番地 | 用途 |
|:-|:-|
| メモリの前半(`0x0000`〜`0x7FFF`) | Qosmos自身の変数とスタック．ROMのプログラムとして，グローバル変数を0番地から上へ置き，カーネルモードのスタックを前半の末尾から下へ伸ばす([pynesis/language/limit.md](../../pynesis/language/limit.md)の「変数に使えるメモリ」を参照) |
| メモリの後半(`0x8000`〜`0xFFFF`の32768バイト) | 実行ファイルの領域(「実行ファイルの領域」を参照)を割り振る範囲．このうち，どの実行ファイルにも割り振っていない範囲を空きと呼ぶ |

メモリの後半は，カーネルモードで実行したPyntaxisの`call`・`ret`が戻り先を積み下ろししない範囲である．このため，Qosmosのスタックが実行ファイルの領域を書き換えることはない．  

## メモリの容量を変える場合
実行ファイルの領域を割り振る範囲は，メモリの容量の半分から決まる．容量を変える場合は，次のものも合わせて変える．  

- 実行ファイルの領域を割り振る範囲  
- 割り振れる最も大きい領域(「領域の大きさ」を参照)から決まる，アセンブラの実行ファイルの命令数の上限と大きさの検査([pyntaxis/language/target.md](../../pyntaxis/language/target.md)の「命令数の上限」と「領域の大きさの指令」を参照)  
- 割り振れる最も大きい領域から決まる，コンパイラの検査の上限([pynesis/compiler/check.md](../../pynesis/compiler/check.md)の「検査に使う値」を参照)  

# 実行ファイルの領域
Qosmosは，プロセス([terms.md](../../terms.md)の「実行ファイルとプロセス」を参照)ごとに，必要な大きさのメモリの範囲(以下，領域)を空きから割り振る(「領域の割り振り」を参照)．実行ファイルは，領域の先頭を0とする番地(以下，領域の中の番地)で，ユーザーモードとして動く([qurge/cpu/mode.md](../../qurge/cpu/mode.md)の「番地の変換」を参照)．領域の大きさをSとすると，領域は先頭から次のように使う．  

| 領域の中の番地 | 用途 |
|:-|:-|
| `0x0000`から | 実行ファイルの命令列(ヘッダの後ろの内容．[qosmos/program/executable.md](../program/executable.md)の「形式」を参照) |
| 命令列の直後から，引数の置き場まで | 実行ファイルが自由に使う範囲．命令列の直後に確保する範囲と，スタックを置く．スタックは，Qosmosが引数の置き場の中に決めたSP([qosmos/kernel/exec.md](exec.md)の「引数の置き方」を参照)から下へ伸びる．Pynesisのコンパイラの使い方は，[pynesis/language/limit.md](../../pynesis/language/limit.md)の「変数に使えるメモリ」を参照 |
| S-256〜S-1 | 引数の置き場．Qosmosが実行ファイルへ渡すコマンド名と引数を置く，領域の末尾の256バイト |

スタックが，ヘッダに書いた量を超えて命令列の直後に確保する範囲と重なっても，CPUは検出しない([qurge/cpu/exception.md](../../qurge/cpu/exception.md)の「検出しない不正」を参照)．  

## 領域の大きさ
領域の大きさは，ヘッダ([qosmos/program/executable.md](../program/executable.md)の「形式」を参照)に書かれた次の3つの合計を8の倍数へ切り上げ，引数の置き場の256バイトを足したものである．8の倍数へ切り上げるのは，USIZEが8の倍数しか持てないためである([qurge/cpu/mode.md](../../qurge/cpu/mode.md)の「番地の変換」を参照)．  

- 命令列のバイト数  
- 命令列の直後に確保する範囲のバイト数  
- スタックの量のバイト数．スタックの量が未定の実行ファイルには，4096バイトを割り振る．このため，その実行ファイルが使えるスタックも4096バイトである  

割り振れる最も大きい領域は，メモリの後半全体の32768バイトである．このため，3つの合計の上限は，32768バイトから引数の置き場を除いた32512バイトである．  

スタックの量が未定の実行ファイルに割り振る4096バイトを変える場合は，アセンブラとコンパイラの検査に使う値([pyntaxis/language/target.md](../../pyntaxis/language/target.md)の「領域の大きさの指令」，[pynesis/compiler/check.md](../../pynesis/compiler/check.md)の「検査に使う値」を参照)も合わせて変える．  

## 引数の置き場の大きさ
引数の置き場の256バイトは，起動を求める1行から作るコマンド名と引数を，最も大きくなる場合(211バイト)でも収められる大きさである．起動を求める1行は，シェルでは1行の入力([qosmos/user/console.md](../user/console.md)の「1行の入力」を参照)，`spawn`では渡された1行で，どちらも63文字以内である．211バイトは，次の合計である．  

| 内容 | バイト数 |
|:-|:-|
| 文字列(1行分) | 64 |
| 4バイト境界への揃え | 3 |
| `argv`の配列(引数が最も多い32個と`nullptr`の33要素×4バイト) | 132 |
| SPが指す4バイトと，`argc`・`argv`の8バイト | 12 |

# 領域の割り振り
Qosmosは，実行ファイルを起動するたびに，プロセステーブル([qosmos/kernel/exec.md](exec.md)の「プロセステーブル」を参照)に要素を加え，その要素に領域を割り振る．プロセスが終わると，終了のシステムコールと例外のどちらで終わっても，要素をプロセステーブルから外す([qosmos/kernel/exec.md](exec.md)の「起動と終了の手順」を参照)．  

割り振った領域(先頭の番地と大きさ)は，プロセステーブルの各要素が持つ．どの要素の領域にも含まれない範囲が空きである．領域の中には管理のための値を置かないため，実行ファイルが自身の領域を書き換えても，プロセステーブルは壊れない．  

割り振るときは，必要な大きさが収まる空きのうち，番地の最も小さい位置を選ぶ．その位置は，メモリの後半の先頭か，いずれかの領域の直後になる．このため，それらを候補とし，候補ごとに，どの領域とも重ならずメモリの後半に収まるかを調べる．プロセステーブルの要素は番地の順に並ばないため，候補ごとにすべての領域と比べる．要素数は16のため，比べる組み合わせは多くない．  

次の場合は，領域を割り振れない．割り振れなければ，Qosmosは実行ファイルを実行しない([qosmos/program/executable.md](../program/executable.md)の「実行できない場合」を参照)．  

- 3つの合計(「領域の大きさ」を参照)が32512バイトを超える  
- 必要な大きさが収まる空きが無い  
- プロセステーブルに空いている要素が無い(同時にメモリに置けるプロセスの数が，上限の16に達している)  

## プロセスの数の上限
同時にメモリに置けるプロセスの数の上限(プロセステーブルの要素数)は16である．16は，次の2つから決めた．  

- Qosmosのスタック: 子を起動するたびに，Qosmosのスタックが約180バイトずつ深くなる([qosmos/kernel/exec.md](exec.md)の「親の値の控えと戻し」を参照)．16段でも約3KBで，メモリの前半のうちQosmosの変数(約5KB)を除いた残りに収まる  
- 入れ子の深さ: 親は子が終わるまで動かないため，同時にメモリに置くプロセスの数は，子・孫と順に起動した深さと同じになる．16段を超える深さの入れ子は想定しない  

入れ子の深さで増えるQosmosのスタックの量は，コンパイラの見積もりに含まれない([pynesis/compiler/check.md](../../pynesis/compiler/check.md)の「見積もりから外れる呼び出し先」を参照)．あふれてもCPUは検出せず，Qosmosの変数を壊す．このため，上限を変える場合や，子を起動する経路の関数を変える場合は，1段あたりの量と上限の積がメモリの前半の残りに収まることを確かめる．
