# システムコールの受け付け
実行ファイルを作る人から見た使い方は，[qosmos/program/syscall.md](../program/syscall.md)を参照．  

# 受け付けの手順
プロセスがPyntaxisの`syscall`を実行すると，CPUはカーネルモードにして，KENTRYが示すシステムコールハンドラへ飛ぶ([qurge/cpu/mode.md](../../qurge/cpu/mode.md)の「動作状態の切り替え」を参照)．システムコールハンドラは，次の順に処理する．  

1. プロセスを再開するための値(SP・PC・r0〜r15・RSI・RAXなど)を控え，SPをカーネルモードのスタックへ切り替える([qosmos/kernel/exec.md](exec.md)の「控える手順」を参照)  
2. 控えたSPから並べた値を読む(「並べた値の読み出し」を参照)  
3. 番号に対応する機能を実行し，戻り値を戻り値の置き場へ書き込む  
4. 控えた値をレジスタへ戻し，プロセスが実行したPyntaxisの`syscall`の次の命令へ戻る([qosmos/kernel/exec.md](exec.md)の「戻る手順」を参照)．r0〜r15とRAXも，システムコールの前の値に戻る．ただし，プロセスとの取り決めでは，システムコールの後のr0〜r15とRAXの値を保たない([qosmos/program/syscall.md](../program/syscall.md)を参照)  

次の2つの機能は，この手順と異なる動きをする．  

- プロセスの終了(Pynesisでは`main`の終了で呼ばれる): 戻り値を書き込まず，プロセスへも戻らない([qosmos/kernel/exec.md](exec.md)の「終了のシステムコールで終わる場合」を参照)  
- 実行ファイルの起動(`spawn`): 機能を実行する中で子を起動し，子が終わってから戻り値を書き込む．子を動かすと，CPUのレジスタとQosmosの変数は子の値に変わる．このため，子が終わった後に，プロセステーブルの親の要素に控えた値から戻す([qosmos/kernel/exec.md](exec.md)の「子の終了を待つ親」を参照)  

Qosmosは，カーネルモードのスタックで機能を実行するため，プロセスのスタックを使わない．  

# 並べた値の読み出し
プロセスが並べた値は，控えたSPが指す領域の中の番地から読む．並べた値が次の場合は，番号に対応する機能を実行しない．  

- SPが4の倍数でない場合と，並べた24バイトが領域に収まらない場合は，値を読むことも戻り値を書き込むこともできない．このため，どの機能も実行せずにプロセスへ戻る  
- 未定義の番号であれば，エラー`-1`を戻り値とする  

# 番地の変換と検査
プロセスが渡す番地は，領域の中の番地である．カーネルモードでは番地が変換されないため，Qosmosが自分で変換する．  

1. 番地から，機能が読み書きする範囲が領域に収まるかを確かめる  
2. 収まれば，領域の先頭の番地を足して，メモリの番地へ変換してから読み書きする  
3. 領域の外へはみ出す場合は，読み書きを行わずにエラー`-2`を返す  

領域の外をカーネルモードで読み書きすると，Qosmosのデータを壊すか，CPUが停止するためである．プロセスが`int`で渡した負の番地と`nullptr`は，符号なしの値として領域の大きさを超えるため，領域の外として扱う．  

# エラーの値への変換
ファイルを扱う機能と`spawn`の失敗は，プロセスへ返すエラーの値([qosmos/program/syscall.md](../program/syscall.md)の「エラー」を参照)へ変換する．プロセスへは，ファイルシステムの内部の区別を見せず，プロセスが対処を変えうる種類だけに分けて返す．
