# 実行ファイル
SDカードの`/bin`に置いた実行ファイルは，その名前をシェルにコマンド名として入力するか，プロセスから`spawn`で指定すれば実行できる(`spawn`は[qosmos/program/syscall.md](syscall.md)の「実行ファイルを起動する」を参照)．  

```c
// hello.pn: 引数を1つずつ出力する実行ファイル
#include "lib/syscall.pn"             // qurgeのmypc.srcs/pn/lib/syscall.pn(パスは置き場所に合わせる)

int main(int argc, char **argv) {
    for (int i = 0; i < argc; i++) {
        console_print(argv[i]);      // コンソールへ出力する
        console_print("\n");
    }
    return 0;                        // 終了状態として起動した側へ伝わる
}
```

```
> hello a b
hello
a
b
> status
0
```

# 作り方
Pynesisのソースを，コンパイラで実行ファイルにする([pynesis/compiler/usage.md](../../pynesis/compiler/usage.md)を参照)．  

```
pn2mc.exe -pn hello.pn -pt hello.pt -bin HELLO
```

Pyntaxisで書いたアセンブリは，アセンブラで実行ファイルにする([pyntaxis/assembler/usage.md](../../pyntaxis/assembler/usage.md)を参照)．アセンブリで書く場合は，「アセンブリで書く場合の取り決め」を守る．  

Qosmosの機能は，システムコールで呼び出す([qosmos/program/syscall.md](syscall.md)を参照)．  
実行ファイルの名前は，拡張子を持たない8.3形式の名前にする([qosmos/user/file.md](../user/file.md)の「名前の規則」を参照)．できた実行ファイルを，SDカードの`/bin`へ置く([operation.md](../../operation.md)の「実行ファイルを置く方法」を参照)．  

# 置き場所と探し方
Qosmosは，ルートディレクトリ直下の`bin`ディレクトリから実行ファイルを探す．現在のディレクトリによらず同じ場所を探し，現在のディレクトリは変えない．  

実行ファイルは，拡張子の無いファイルに限る．`.`を含むコマンド名は探さない．`README.TXT`などのデータファイルを，名前の打ち間違いで命令として実行しないためである．  

## 組み込みコマンドと同じ名前の場合
組み込みコマンドと同じ名前の実行ファイル(`/bin/echo`など)の扱いは，起動する側によって次のように異なる．  

- シェル: 組み込みコマンドを優先する．組み込みコマンド名の照合は大文字・小文字を区別し，実行ファイル名の照合はほかのファイルと同じく区別しない([qosmos/user/file.md](../user/file.md)の「名前の規則」を参照)．このため，組み込みコマンド名のとおりに入力すれば(`echo`)組み込みコマンドを，大文字・小文字を変えて入力すれば(`ECHO`)実行ファイルを実行する  
- プロセス: `spawn`は組み込みコマンドを起動できないため，常に実行ファイルを起動する  

# 引数
Qosmosは，起動を求める1行(シェルでは入力した1行)を半角空白で区切り，コマンド名と引数としてプロセスへ渡す([qosmos/user/shell.md](../user/shell.md)の「入力の解析」を参照)．区切りの空白は，文字列に含めない．プロセスは，渡された文字列と配列を書き換えてもよい．  

Pynesisでは，`main`の`argc`・`argv`で受け取る([pynesis/language/function.md](../../pynesis/language/function.md)の「main関数」を参照)．それぞれの内容は，次のとおりである．  

- `argc`: コマンド名と引数を合わせた数(1以上)  
- `argv`: 各文字列(ヌル終端)へのポインタの配列．`argv[0]`はコマンド名(起動を求める1行のとおりの綴り)で，最後の要素の次に`nullptr`を置く  

引数の置き場の詳細は，[qosmos/kernel/exec.md](../kernel/exec.md)の「引数の置き方」を参照．  

# 始まる時点のレジスタ
プロセスが始まる時点のレジスタは，次のとおりである．  

| レジスタ | 値 |
|:-|:-|
| PC | 0(実行ファイルの先頭の命令) |
| SP | 引数の置き場に決めた値(「引数」を参照) |
| r0〜r15・RSI・RAX | 0 |

# 動いている間の割り込み
Qosmosは，プロセスが動いている間，10msごとにタイマー割り込みでプロセスを止め，止めた命令から続きを実行させる([qosmos/kernel/exec.md](../kernel/exec.md)の「割り込みで止めたとき」を参照)．止める前と後で，プロセスのレジスタとメモリの値は変わらない．このため，プロセスは，止められることを考えずに書いてよい．アセンブリやasm文でレジスタを使う場合も同じである．  

# 終了状態
プロセスは，終了のシステムコールで終える([qosmos/program/syscall.md](syscall.md)の「プロセスの終了」を参照)．渡した値が終了状態になり，起動した側へ伝わる．シェルから起動した場合はシェルの終了状態になり([qosmos/user/shell.md](../user/shell.md)の「終了状態」を参照)，プロセスから起動した場合は親へ返る([qosmos/program/syscall.md](syscall.md)の「実行ファイルを起動する」を参照)．  

Pynesisでは，`main`の戻り値が終了状態になる．`main`が`return`文を通らずに本体を閉じる`}`まで進んだ場合，終了状態は不定になる．  

# 使えるメモリ
プロセスは，Qosmosが割り振る領域の中で動く．領域の外のメモリと，カーネルモードでだけ読み書きできるレジスタ(周辺機器のレジスタを含む)は，読み書きできない([qurge/cpu/register.md](../../qurge/cpu/register.md)の「ユーザーモードでの制限」を参照)．  

プロセスの領域には，次の3つが要る．それぞれの大きさを，実行ファイルのヘッダに書く(「形式」を参照)．Qosmosは，3つの合計を8の倍数へ切り上げ，引数の置き場の256バイトを足した大きさの領域を割り振る．3つの合計の上限は98048バイトである．  

- 命令列  
- 命令列の直後に確保する範囲: 固定の番地で読み書きする値(Pynesisではグローバル変数と文字列リテラル)を置く  
- スタック: ヘッダに書いた量を使える．量を未定とした場合は，4096バイトを使える．使える量を超えて使っても，CPUは検出しない  

領域の大きさの決め方と中の配置は，[qosmos/kernel/memory.md](../kernel/memory.md)の「領域の割り振り」と「プロセスの領域」を参照．Pynesisで書く場合の量的制限は，[pynesis/language/limit.md](../../pynesis/language/limit.md)を参照．  

# 実行できない場合
次の場合は，実行ファイルを実行しない．シェルから起動した場合は，コマンド名を前置したエラーメッセージを出力する．プロセスから起動した場合は，メッセージを出力せずにエラーを返す([qosmos/program/syscall.md](syscall.md)の「エラー」を参照)．  

| 条件 | シェルのメッセージ | プロセスへ返すエラー |
|:-|:-|:-|
| コマンド名が`.`を含む，`/bin`が無い，`/bin`に同じ名前のファイルが無い | `unknown command`(組み込みコマンドとも一致しない場合と同じ) | `-4` |
| 名前が規則に合わない | `unknown command` | `-6` |
| ファイルシステムをマウントしていない，カードから読み出せない，ファイルシステムの記録が壊れている | 各原因のメッセージ(ファイルを扱うコマンドと同じ) | `-8` |
| 同じ名前がディレクトリを指す | `is a directory` | `-5` |
| 大きさかヘッダの内容が条件に合わない(「形式」を参照) | `invalid executable` | `-9` |
| 必要な大きさの領域が空きに収まらない([qosmos/kernel/memory.md](../kernel/memory.md)の「領域の割り振り」を参照) | `not enough memory` | `-10` |
| 同時にメモリに置けるプロセスの数が上限に達している([qosmos/kernel/memory.md](../kernel/memory.md)の「プロセスの数の上限」を参照) | `too many processes` | `-11` |
| 起動を求める1行が63文字を超えるか，コマンド名を含まない | なし(シェルの入力では起きない) | `-12` |

`.`を含むコマンド名は，カードを読まずにエラーにする．それ以外のコマンド名は，`/bin`を探してから，名前が規則に合うかを確かめる．このため，ファイルシステムをマウントしていない場合や`/bin`の読み出しに失敗した場合は，組み込みコマンド以外の入力がすべて，その原因のエラーになる(`.`を含むものを除く)．実行ファイルが無いかどうかを確かめられないためである．  

# 例外を起こした場合
プロセスは，CPUが実行できない命令や不正な操作(0で割るなど)を行うと，例外を起こす．例外の種類と番号は，[qurge/cpu/exception.md](../../qurge/cpu/exception.md)の「例外の種類」を参照．  

プロセスが例外を起こすと，Qosmosはそのプロセスを終わらせる．例外を起こした命令から先は実行しない．プロセスが例外を起こすまでに行ったファイルの書き込みやコンソールへの出力は，そのまま残る．Qosmosがプロセスを終わらせる仕組みは，[qosmos/kernel/exec.md](../kernel/exec.md)の「プロセスが終わったとき」を参照．  

例外で終わったことの伝え方は，プロセスを起動した側によって異なる．  

## シェルから起動した場合
シェルは，エラーメッセージを1行出力してから，プロンプトを表示して次の入力を待つ．直後に`status`を実行すると，`exception <例外の番号>`を出力する([qosmos/user/shell.md](../user/shell.md)の「終了状態」を参照)．  

### 例
`/bin`に置いた実行ファイル`crash`を実行し，そのプロセスが領域の外の番地を読み込んで，番号5の例外を起こすとする．例外を起こした命令のPCは`0x2a`とする．このとき，端末には次のように表示される(`> `はシェルのプロンプト)．  

```
> crash
crash: memory access out of range (pc 0x0000002a)
> status
exception 5
```

### エラーメッセージ
エラーメッセージの形は，次のとおりである．  

```
<コマンド名>: <原因のメッセージ> (pc 0x<PC>)
```

原因のメッセージは，例外の番号ごとに次のとおり決まっている．  

| 番号 | 例外 | メッセージ |
|:-|:-|:-|
| 1 | 範囲外の番地からの命令の取り出し | `instruction fetch out of range` |
| 2 | 不正な命令 | `invalid instruction` |
| 3 | カーネルモードでだけ許される操作 | `privileged operation` |
| 4 | 除数が0の割り算 | `division by zero` |
| 5 | 範囲外の番地の読み書き | `memory access out of range` |

PCは，例外を起こした命令のPCを，16進数8桁で表したものである．PCは，実行ファイルの先頭の命令を0として数える([qurge/cpu/mode.md](../../qurge/cpu/mode.md)の「番地の変換」を参照)．命令を取り出す番地が範囲外の場合は，取り出そうとした命令のPCになる．  

エラーメッセージは，プロセスが最後に出力した内容の直後に続く．プロセスの出力が改行で終わっていない場合は，その出力と同じ行に続く．  

## プロセスから起動した場合
Qosmosはメッセージを出力せず，例外の番号を`spawn`の戻り値として親へ返す([qosmos/program/syscall.md](syscall.md)の「実行ファイルを起動する」を参照)．例外を起こした命令のPCは，親へ返さない．  

# 形式
実行ファイルは，16バイトのヘッダの後ろに，命令を8バイトずつ並べたもの(命令列)である．各命令のバイトの並びは，[qurge/cpu/isa.md](../../qurge/cpu/isa.md)の「基本構成」を参照．Qosmosは，ヘッダを領域へ書き写さず，命令列を領域の先頭から書き写す．  

## ヘッダ
ヘッダは，4バイトのワードを次の順に4つ並べたものである．各ワードは，リトルエンディアンの符号なし整数である．  

| 位置 | 内容 |
|:-|:-|
| 0〜3バイト目 | ファイルシグネチャ．ファイル上で`0x7F`・`'Q'`・`'S'`・版数の順に並ぶ4バイト |
| 4〜7バイト目 | 命令列のバイト数 |
| 8〜11バイト目 | 命令列の直後に確保する範囲のバイト数 |
| 12〜15バイト目 | スタックの量のバイト数．`0xFFFFFFFF`は量が未定であることを表す |

ファイルシグネチャの先頭の`0x7F`はテキストに現れないため，テキストファイルを実行ファイルと取り違えない．版数は形式の版を表し，今の版は0である．形式を変えたら版数を上げる．Qosmosは，今の版の実行ファイルだけを実行する．  

## 条件
Qosmosは，次の条件をすべて満たす実行ファイルだけを実行する．  

- ファイルの大きさが，ヘッダと1命令を合わせた24バイト以上である  
- ファイルシグネチャが，今の版のものと一致する  
- 命令列のバイト数が，ファイルの大きさからヘッダの16バイトを引いた値と一致し，8の倍数である  

# アセンブリで書く場合の取り決め
Pynesisのコンパイラは，次の取り決めを満たす実行ファイルを作る([pynesis/compiler/call.md](../../pynesis/compiler/call.md)の「実行ファイルのmain」を参照)．アセンブリで書く場合は，自分で守る．  

- 領域に必要な大きさを，Pyntaxisの`.reserve`・`.stack`の指令で書く([pyntaxis/language/target.md](../../pyntaxis/language/target.md)の「領域の大きさの指令」を参照)．`.reserve`には，命令列の直後から固定の番地で読み書きする範囲の大きさを書く．`.stack`には，スタックを最も深く積んだときの量を書く．量を求められなければ，`.stack`を省略する  
- 終了のシステムコールで終える．Qosmosは領域の先頭の命令からPyntaxisの`call`を使わずに実行を始め，戻り先を積まないため，Pyntaxisの`ret`では終えられない([pyntaxis/language/target.md](../../pyntaxis/language/target.md)の「mainの終わり方」を参照)  
- 固定の番地(グローバル変数など)は，領域の中の番地(領域の先頭を0とする番地)で指定する  
- Qosmosの機能は，システムコールを通して呼び出す．システムコールの後のレジスタの値は，[qosmos/program/syscall.md](syscall.md)の取り決めに従う  
- SPは，スタックの確保と参照にだけ使う
