# 実行ファイル
SDカード上に置いた機械語のプログラム(実行ファイル)を，その名前をコマンド名として入力すれば実行できる．起動専用のコマンドは無い．

## 探し方
- ルートディレクトリ直下の`bin`ディレクトリ(既定のディレクトリ)から探す．現在のディレクトリによらず同じ場所を探し，現在のディレクトリは変えない
- 組み込みコマンドを優先する．組み込みコマンド名の照合は大文字・小文字を区別し，実行ファイル名の照合は他のファイルと同じく区別しない([qosmos/resource/filesystem.md](../resource/filesystem.md)の「ファイル・ディレクトリの名前」を参照)．このため，組み込みコマンドと同じ名前の実行ファイル(`/bin/echo`など)は，組み込みコマンド名のとおりに入力すると(`echo`)組み込みコマンドが実行され，大文字・小文字を変えて入力すると(`ECHO`)実行ファイルが実行される
- 実行ファイルは拡張子の無いファイルに限る．`.`を含むコマンド名は探さない(`README.TXT`などのデータファイルを，名前の打ち間違いで命令として実行しないため)

## 領域
シェルは，メモリの後半(`0x8000`〜`0xFFFF`の32768バイト)を，実行ファイルに割り振る領域とする．どの実行ファイルにも同じ位置・大きさの領域を割り振る．実行ファイルは，領域の先頭を0とする番地(以下，領域の中の番地)でユーザーモードとして動く([qurge/cpu/mode.md](../../qurge/cpu/mode.md)の「番地の変換」を参照)．領域の外のメモリと，OS用のレジスタ・周辺機器のレジスタは読み書きできない([qurge/cpu/mode.md](../../qurge/cpu/mode.md)の「ユーザーモードでの制限」を参照)．

領域は，先頭から次のように使う．

| 領域の中の番地 | 用途 |
|:-|:-|
| `0x0000`から | 命令列(実行ファイルの内容．下記「形式」を参照) |
| 命令列の直後から | グローバル変数と文字列リテラル．Pynesisのコンパイラが，上へ順に置く([pynesis/compiler.md](../../pynesis/compiler.md)の「アドレッシング方式」を参照) |
| グローバル変数の後ろから引数の置き場まで | スタック．シェルが引数の置き場の中に決めたSP(下記「実行の仕方」を参照)から，下へ伸びる |
| `0x7F00`〜`0x7FFF` | 引数の置き場．シェルが，実行ファイルへ渡すコマンド名と引数を置く，領域の末尾の256バイト |

命令列とグローバル変数は，合わせて引数の置き場より手前の32512バイトに収まる必要がある．引数の置き場の256バイトは，1行の入力([qosmos/user/console.md](../user/console.md)の「1行の入力」を参照)から作るコマンド名と引数を，最も大きくなる場合(211バイト)でも収められる大きさである．211バイトは，文字列が1行分の64バイト，4バイト境界への揃えが3バイト，`argv`の配列が33要素(引数が最も多い32個と`nullptr`)×4バイト，SPが指す4バイトと`argc`・`argv`の8バイトの合計である．\
使えるスタックの量は保証しない．スタックがグローバル変数と重なっても，CPUは検出しない([qurge/cpu/exception.md](../../qurge/cpu/exception.md)の「検出しない不正」を参照)．

## 形式
ヘッダを持たず，命令を先頭から8バイトずつ並べる．各命令のバイトの並びは[qurge/memory.md](../../qurge/memory.md)の「メモリ上の命令の実行」を参照．\
大きさは，命令を1つ以上含み，引数の置き場より手前の32512バイト(上記「領域」を参照)以下で，8の倍数である必要がある．

## 実行の仕方
シェルは次の順に実行ファイルを動かす．

1. 実行ファイルの内容を，領域の先頭から書き写す
2. コマンド名と引数を引数の置き場に置き，SPを決める(下記の表を参照)
3. 領域の先頭の命令(領域の中のPC 0)から，ユーザーモードで実行する
4. 実行ファイルが終了のシステムコール([qosmos/program/syscall.md](syscall.md)を参照)を実行すると，渡された値を終了状態とし([qosmos/user/command.md](../user/command.md)の「終了状態」を参照)，プロンプトを表示して次の入力を待つ

コマンド名と引数は[qosmos/user/command.md](../user/command.md)と同じく半角空白で区切り，区切りの空白は文字列に含めない．実行ファイルが始まる時点の引数の置き場は，次のとおりである．`argc`・`argv`は，Pynesisの関数をCALLで呼び出した直後と同じ位置に置く([pynesis/compiler.md](../../pynesis/compiler.md)の「呼び出し規約」を参照)．このため，Pynesisでは`main`を`int main(int argc, char **argv)`と定義すれば受け取れる．引数を使わない場合は`int main(void)`とも書ける([pynesis/language.md](../../pynesis/language.md)の「main関数」を参照)．

| 位置 | 内容 |
|:-|:-|
| 領域の末尾 | コマンド名と各引数の文字列(ヌル終端)を，入力した順に並べたもの |
| 文字列の下(4バイト境界に揃える) | `argv`の配列．各文字列の先頭の領域の中の番地を並べ，最後に`nullptr`を置く．`argv[0]`はコマンド名(入力したとおりの綴り)である |
| 配列のすぐ下の4バイト | SPが指す位置．CALLが戻り先を積む位置にあたるが，値は不定で，戻り先としては使えない |
| SP-8 | `argc`(`int`)．コマンド名と引数を合わせた数(1以上) |
| SP-4 | `argv`(`char **`)．`argv`の配列の先頭の領域の中の番地 |

実行ファイルは，文字列と`argv`の配列を書き換えてもよい．

実行ファイルは次の取り決めを守る必要がある．

- 終了のシステムコールで終える．`main`の戻り先は無いため，RETでは終えられない．Pynesisのコンパイラは，`main`の`return`文と終端で，戻り値を渡して終了のシステムコールを実行する([pynesis/compiler.md](../../pynesis/compiler.md)の「出力先」を参照)
- JMP/CALLの飛び先と固定番地(グローバル変数など)は，領域の中の番地で指定する．Pynesisのコンパイラは，グローバル変数と文字列リテラルを命令列の直後に置く(上記「領域」を参照)
- OSの機能は，システムコール([qosmos/program/syscall.md](syscall.md)を参照)を通して呼び出す
- SPは，スタックの確保・参照にだけ使う．Pynesisのソースからは，SPを含むどのハードウェア変数も読み書きできない(コンパイルエラーになる．[pynesis/language.md](../../pynesis/language.md)の「定義済みハードウェア変数」を参照)

実行ファイルが例外([qurge/cpu/exception.md](../../qurge/cpu/exception.md)を参照)を起こすと，例外ハンドラはCPUを停止させる．シェルには戻れないため，SRSTのボタンで起動し直す必要がある([qurge/board.md](../../qurge/board.md)の「SRSTのボタン」を参照)．

## エラー
次の場合はコマンド名を前置したエラーメッセージを出力し，実行ファイルを実行しない．

| 条件 | メッセージ |
|:-|:-|
| コマンド名が`.`を含む，`/bin`が無い，`/bin`に同じ名前のファイルが無い，名前が規則に合わない | `unknown command`(組み込みコマンドとも一致しない場合と同じ) |
| ファイルシステムをマウントしていない，カードから読み出せない，ファイルシステムの記録が壊れている | 各原因のメッセージ(ファイルを扱うコマンドと同じ) |
| 同じ名前がディレクトリを指す | `is a directory` |
| 大きさが上記「形式」の条件に合わない | `invalid executable` |

`.`を含むコマンド名はカードを読まずにエラーにし，それ以外は`/bin`を探してから名前が規則に合うかを確かめる．このため，ファイルシステムをマウントしていない場合や`/bin`の読み出しに失敗した場合は，`.`を含むものを除く組み込みコマンドに一致しない入力が，すべてその原因のエラーになる(実行ファイルが無いかどうかを確かめられないため)．\
読み込みの途中で読み出しに失敗した場合，領域に書き写した内容は途中のまま残り，実行はしない．
