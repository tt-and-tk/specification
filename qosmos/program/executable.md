# 実行ファイル
SDカード上に置いた機械語のプログラム(実行ファイル)を，その名前をコマンド名として入力すれば実行できる．起動専用のコマンドは無い．

## 探し方
- ルートディレクトリ直下の`bin`ディレクトリ(既定のディレクトリ)から探す．現在のディレクトリによらず同じ場所を探し，現在のディレクトリは変えない
- 組み込みコマンドを優先する．組み込みコマンド名の照合は大文字・小文字を区別し，実行ファイル名の照合は他のファイルと同じく区別しない([qosmos/resource/filesystem.md](../resource/filesystem.md)の「ファイル・ディレクトリの名前」を参照)．このため，組み込みコマンドと同じ名前の実行ファイル(`/bin/echo`など)は，組み込みコマンド名のとおりに入力すると(`echo`)組み込みコマンドが実行され，大文字・小文字を変えて入力すると(`ECHO`)実行ファイルが実行される
- 実行ファイルは拡張子の無いファイルに限る．`.`を含むコマンド名は探さない(`README.TXT`などのデータファイルを，名前の打ち間違いで命令として実行しないため)

## 領域
実行ファイルは，シェルが割り振る領域の中で，領域の中の番地を使ってユーザーモードとして動く(領域の位置・大きさ・使い方は[qosmos/resource/memory.md](../resource/memory.md)の「実行ファイルの領域」を参照)．領域の外のメモリと，OS用のレジスタ・周辺機器のレジスタは読み書きできない([qurge/cpu/register.md](../../qurge/cpu/register.md)の「ユーザーモードでの制限」を参照)．

## 形式
ヘッダを持たず，命令を先頭から8バイトずつ並べる．各命令のバイトの並びは[qurge/cpu/isa.md](../../qurge/cpu/isa.md)の「基本構成」を参照．\
大きさは，命令を1つ以上含み，引数の置き場より手前の32512バイト([qosmos/resource/memory.md](../resource/memory.md)の「実行ファイルの領域」を参照)以下で，8の倍数である必要がある．

## 実行の仕方
シェルは次の順に実行ファイルを動かす．

1. 実行ファイルの内容を，領域の先頭から書き写す
2. コマンド名と引数を引数の置き場に置き，SPを決める(下記の表を参照)
3. 領域の先頭の命令(領域の中のPC 0)から，ユーザーモードで実行する
4. 実行ファイルが終了のシステムコール([qosmos/program/syscall.md](syscall.md)を参照)を実行すると，渡された値を終了状態とし([qosmos/user/command.md](../user/command.md)の「終了状態」を参照)，プロンプトを表示して次の入力を待つ

コマンド名と引数は[qosmos/user/command.md](../user/command.md)と同じく半角空白で区切り，区切りの空白は文字列に含めない．実行ファイルが始まる時点の引数の置き場は，次のとおりである(Pynesisの`main`での受け取り方は，[pynesis/compiler/call.md](../../pynesis/compiler/call.md)の「実行ファイルのmain」を参照)．

| 位置 | 内容 |
|:-|:-|
| 領域の末尾 | コマンド名と各引数の文字列(ヌル終端)を，入力した順に並べたもの |
| 文字列の下(4バイト境界に揃える) | `argv`の配列．各文字列の先頭の領域の中の番地を並べ，最後に`nullptr`を置く．`argv[0]`はコマンド名(入力したとおりの綴り)である |
| 配列のすぐ下の4バイト | SPが指す位置．CALLが戻り先を積む位置にあたるが，値は不定で，戻り先としては使えない |
| SP-8 | `argc`(`int`)．コマンド名と引数を合わせた数(1以上) |
| SP-4 | `argv`(`char **`)．`argv`の配列の先頭の領域の中の番地 |

実行ファイルは，文字列と`argv`の配列を書き換えてもよい．

実行ファイルは次の取り決めを守る必要がある．

- 終了のシステムコールで終える．シェルは領域の先頭の命令からCALLを使わずに実行を始め，戻り先を積まないため，RETでは終えられない
- JMP/CALLの飛び先と固定番地(グローバル変数など)は，領域の中の番地で指定する
- OSの機能は，システムコール([qosmos/program/syscall.md](syscall.md)を参照)を通して呼び出す
- SPは，スタックの確保・参照にだけ使う

Pynesisのコンパイラがこれらの取り決めに従って実行ファイルを生成する方法は，[pynesis/compiler/call.md](../../pynesis/compiler/call.md)の「実行ファイルのmain」を参照．

実行ファイルが例外([qurge/cpu/exception.md](../../qurge/cpu/exception.md)を参照)を起こすと，例外ハンドラはCPUを停止させる．シェルには戻れないため，SRSTのボタンで起動し直す必要がある([qurge/board.md](../../qurge/board.md)の「SRSTのボタン」を参照)．

## エラー
次の場合はコマンド名を前置したエラーメッセージを出力し，実行ファイルを実行しない．

| 条件 | メッセージ |
|:-|:-|
| コマンド名が`.`を含む，`/bin`が無い，`/bin`に同じ名前のファイルが無い，名前が規則に合わない | `unknown command`(組み込みコマンドとも一致しない場合と同じ) |
| ファイルシステムをマウントしていない，カードから読み出せない，ファイルシステムの記録が壊れている | 各原因のメッセージ(ファイルを扱うコマンドと同じ) |
| 同じ名前がディレクトリを指す | `is a directory` |
| 大きさが上記「形式」の条件に合わない | `invalid executable` |

`.`を含むコマンド名はカードを読まずにエラーにし，それ以外は`/bin`を探してから名前が規則に合うかを確かめる．このため，ファイルシステムをマウントしていない場合や`/bin`の読み出しに失敗した場合は，`.`を含むものを除く組み込みコマンドに一致しない入力が，すべてその原因のエラーになる(実行ファイルが無いかどうかを確かめられないため)．\
読み込みの途中で読み出しに失敗した場合，領域に書き写した内容は途中のまま残り，実行はしない．
