# 実行ファイル
SDカードの`/bin`に置いたプログラム(実行ファイル)は，その名前をそのままコマンド名として入力すれば実行できる．  

```c
// hello.pn: 引数を1つずつ出力する実行ファイル
#include "lib/syscall.pn"             // qurgeのmypc.srcs/pn/lib/syscall.pn(パスは置き場所に合わせる)

int main(int argc, char **argv) {
    for (int i = 0; i < argc; i++) {
        console_print(argv[i]);      // コンソールへ出力する
        console_print("\n");
    }
    return 0;                        // 終了状態としてシェルへ伝わる
}
```

```
> hello a b
hello
a
b
> status
0
```

# 作り方
Pynesisのソースを，コンパイラで実行ファイルにする([pynesis/compiler/usage.md](../../pynesis/compiler/usage.md)を参照)．  

```
pn2mc.exe -pn hello.pn -pt hello.pt -bin HELLO
```

Pyntaxisで書いたアセンブリは，アセンブラで実行ファイルにする([pyntaxis/assembler/usage.md](../../pyntaxis/assembler/usage.md)を参照)．  
アセンブリで書く場合は，「アセンブリで書く場合の取り決め」を守る．  

OSの機能は，システムコールで呼び出す([qosmos/program/syscall.md](syscall.md)を参照)．  
実行ファイルの名前は，拡張子を持たない8.3形式の名前にする([qosmos/user/file.md](../user/file.md)の「名前の規則」を参照)．  
できた実行ファイルを，SDカードの`/bin`へ置く([operation.md](../../operation.md)の「実行ファイルを置く方法」を参照)．  

# 置き場所と探し方
シェルは，ルートディレクトリ直下の`bin`ディレクトリから実行ファイルを探す．  
現在のディレクトリによらず同じ場所を探し，現在のディレクトリは変えない．  

実行ファイルは，拡張子の無いファイルに限る．  
`.`を含むコマンド名は探さない．  
`README.TXT`などのデータファイルを，名前の打ち間違いで命令として実行しないためである．  

## 組み込みコマンドと同じ名前の場合
組み込みコマンドを優先する．  
組み込みコマンド名の照合は大文字・小文字を区別し，実行ファイル名の照合はほかのファイルと同じく区別しない([qosmos/user/file.md](../user/file.md)の「名前の規則」を参照)．  
このため，組み込みコマンドと同じ名前の実行ファイル(`/bin/echo`など)は，次のように動く．  

- 組み込みコマンド名のとおりに入力した場合(`echo`): 組み込みコマンドを実行する  
- 大文字・小文字を変えて入力した場合(`ECHO`): 実行ファイルを実行する  

# 引数
シェルは，入力した1行を半角空白で区切り，コマンド名と引数として実行ファイルへ渡す([qosmos/user/shell.md](../user/shell.md)の「入力の解析」を参照)．  
区切りの空白は，文字列に含めない．  
実行ファイルは，渡された文字列と配列を書き換えてもよい．  

Pynesisでは，`main`の`argc`・`argv`で受け取る([pynesis/language/function.md](../../pynesis/language/function.md)の「main関数」を参照)．  
それぞれの内容は，次のとおりである．  

- `argc`: コマンド名と引数を合わせた数(1以上)  
- `argv`: 各文字列(ヌル終端)へのポインタの配列．`argv[0]`はコマンド名(入力したとおりの綴り)で，最後の要素の次に`nullptr`を置く  

引数の置き場の詳細は，[qosmos/kernel/exec.md](../kernel/exec.md)の「引数の置き方」を参照．  

# 終了状態
実行ファイルは，終了のシステムコールで終える([qosmos/program/syscall.md](syscall.md)の「実行ファイルの終了」を参照)．  
渡した値が，シェルの終了状態になる([qosmos/user/shell.md](../user/shell.md)の「終了状態」を参照)．  

Pynesisでは，`main`の戻り値が終了状態になる．  
`main`が`return`文を通らずに本体を閉じる`}`まで進んだ場合，終了状態は不定になる．  

# 使えるメモリ
実行ファイルは，シェルが割り振る32768バイトの領域の中で動く．  
領域の外のメモリと，OS用のレジスタ・周辺機器のレジスタは読み書きできない([qurge/cpu/register.md](../../qurge/cpu/register.md)の「ユーザーモードでの制限」を参照)．  

実行ファイルの命令と，グローバル変数を合わせて，32512バイトに収める必要がある．  
領域の末尾の256バイトは，シェルが引数を置くために使う．  
残りの範囲を，スタックとして使う．  
使えるスタックの量は保証しない．  

領域の中の配置は，[qosmos/kernel/memory.md](../kernel/memory.md)の「実行ファイルの領域」を参照．  
Pynesisで書く場合の量的制限は，[pynesis/language/limit.md](../../pynesis/language/limit.md)を参照．  

# 実行できない場合
次の場合は，コマンド名を前置したエラーメッセージを出力し，実行ファイルを実行しない．  

| 条件 | メッセージ |
|:-|:-|
| コマンド名が`.`を含む，`/bin`が無い，`/bin`に同じ名前のファイルが無い，名前が規則に合わない | `unknown command`(組み込みコマンドとも一致しない場合と同じ) |
| ファイルシステムをマウントしていない，カードから読み出せない，ファイルシステムの記録が壊れている | 各原因のメッセージ(ファイルを扱うコマンドと同じ) |
| 同じ名前がディレクトリを指す | `is a directory` |
| 大きさが条件に合わない(「形式」を参照) | `invalid executable` |

`.`を含むコマンド名は，カードを読まずにエラーにする．  
それ以外のコマンド名は，`/bin`を探してから，名前が規則に合うかを確かめる．  
このため，ファイルシステムをマウントしていない場合や`/bin`の読み出しに失敗した場合は，組み込みコマンド以外の入力がすべて，その原因のエラーになる(`.`を含むものを除く)．  
実行ファイルが無いかどうかを確かめられないためである．  

読み込みの途中で読み出しに失敗した場合も，実行しない．  

# 例外を起こした場合
実行ファイルは，CPUが実行できない命令や不正な操作(0で割る，領域の外を読み書きする，など)を行うと，例外を起こす．  
例外の種類と番号は，[qurge/cpu/exception.md](../../qurge/cpu/exception.md)の「例外の種類」を参照．  

実行ファイルが例外を起こすと，シェルはその実行ファイルを終わらせる．  
実行ファイルへは戻らない．  
実行ファイルが例外を起こすまでに行ったファイルの書き込みやコンソールへの出力は，そのまま残る．  
シェルが実行ファイルを終わらせる仕組みは，[qosmos/kernel/exec.md](../kernel/exec.md)の「実行ファイルが終わったとき」を参照．  

## 例
`/bin`に置いた実行ファイル`crash`が，領域の外の番地を読み込んで，番号5の例外を起こすとする．  
例外を起こした命令のPCは`0x2a`とする．  
このとき，端末には次のように表示される(`> `はシェルのプロンプト)．  

```
> crash
crash: memory access out of range (pc 0x0000002a)
> status
exception 5
```

シェルは，エラーメッセージを1行出力してから，プロンプトを表示して次の入力を待つ．  
直後に`status`を実行すると，`exception <例外の番号>`を出力する([qosmos/user/shell.md](../user/shell.md)の「終了状態」を参照)．  

## エラーメッセージ
エラーメッセージの形は，次のとおりである．  

```
<コマンド名>: <原因のメッセージ> (pc 0x<PC>)
```

原因のメッセージは，例外の番号ごとに次のとおり決まっている．  

| 番号 | 例外 | メッセージ |
|:-|:-|:-|
| 1 | 命令を取り出す番地が範囲外である | `instruction fetch out of range` |
| 2 | 不正な命令である | `invalid instruction` |
| 3 | カーネルモードでだけ許される操作を行おうとした | `privileged operation` |
| 4 | 割り算の除数が0である | `division by zero` |
| 5 | メモリを読み書きする番地が範囲外である | `memory access out of range` |

PCは，例外を起こした命令のPCを，16進数8桁で表したものである．  
PCは，実行ファイルの先頭の命令を0として数える([qurge/cpu/mode.md](../../qurge/cpu/mode.md)の「番地の変換」を参照)．  
命令を取り出す番地が範囲外の場合は，取り出そうとした命令のPCになる．  

エラーメッセージは，実行ファイルが最後に出力した内容の直後に続く．  
実行ファイルの出力が改行で終わっていない場合は，その出力と同じ行に続く．  

# 形式
実行ファイルは，ヘッダを持たず，命令を先頭から8バイトずつ並べたものである．  
各命令のバイトの並びは，[qurge/cpu/isa.md](../../qurge/cpu/isa.md)の「基本構成」を参照．  
大きさは，次の条件をすべて満たす必要がある．  

- 命令を1つ以上含む  
- 32512バイト以下である  
- 8の倍数である  

# アセンブリで書く場合の取り決め
Pynesisのコンパイラは，次の取り決めを満たす実行ファイルを作る([pynesis/compiler/call.md](../../pynesis/compiler/call.md)の「実行ファイルのmain」を参照)．  
アセンブリで書く場合は，自分で守る．  

- 終了のシステムコールで終える．シェルは領域の先頭の命令からPyntaxisの`call`を使わずに実行を始め，戻り先を積まないため，Pyntaxisの`ret`では終えられない([pyntaxis/language/target.md](../../pyntaxis/language/target.md)の「mainの終わり方」を参照)  
- 固定の番地(グローバル変数など)は，領域の中の番地(領域の先頭を0とする番地)で指定する  
- OSの機能は，システムコールを通して呼び出す  
- SPは，スタックの確保と参照にだけ使う
