# システムコール
実行ファイルは，システムコールを通してOSの機能を呼び出せる．どの機能もSYSCALL命令で呼び出し([qurge/cpu/mode.md](../../qurge/cpu/mode.md)の「動作状態の切り替え」を参照)，呼び出す機能は番号で指定する．

- 呼び出し方: SYSCALL命令を実行する時点のSPが指す番地から，次の6つの値を4バイトずつ順に並べておく．`a`〜`d`のうち機能が使わない引数の値は問わない．番地は領域の中の番地([qosmos/resource/memory.md](../resource/memory.md)の「実行ファイルの領域」を参照)を整数として渡す
  | SPからの位置 | 内容 |
  |:-|:-|
  | +0 | 戻り値の置き場(OSが書き込む) |
  | +4 | 機能の番号 |
  | +8〜+20 | 機能に渡す引数`a`〜`d` |
- 並べられない場合: SPが4の倍数でない場合と，並べた24バイトが領域に収まらない場合は，機能によらず何もせずに戻る(戻り値の置き場も書き換えない)
- 戻り値: 並べた値を読めた場合，終了の機能(番号5)を除き，OSは機能を実行してから戻り値を置き場へ書き込み，SYSCALL命令の次の命令へ戻る．0以上は成功，負の値はエラー(下記「エラー」を参照)を表す．終了の機能では，実行ファイルへ戻らない
- 戻った時点のr0〜r15とRAXの値は保たれない．SPは保たれる
- OSは，カーネルモードのスタックで機能を実行するため，実行ファイルのスタックを使わない
- OSは，コンソールへ出力する機能に渡されたバイト列と，1行を受け取る間のエコーのほかは，コンソールへ何も出力しない．エラーを表示するかどうかは実行ファイルが決める

## 機能
機能は，ファイル・コンソール・実行ファイルのそれぞれを扱うものに分かれる(次の表の「対象」の列)．ファイルを扱う機能に渡す名前は，組み込みコマンドと同じく，シェルの現在のディレクトリの直下にあるファイルの名前だけを指定できる([qosmos/resource/filesystem.md](../resource/filesystem.md)の「ディレクトリ」「ファイル・ディレクトリの名前」を参照)．コンソールを扱う機能は，シェルと同じコンソールを使う([qosmos/user/console.md](../user/console.md)を参照)．文字列はヌル終端とする．

| 番号 | 対象 | 機能 | 使う引数 | 戻り値 | ライブラリの関数(下記「ライブラリ」を参照) |
|:-|:-|:-|:-|:-|:-|
| 0 | ファイル | ファイルの大きさを調べる | `a`: 名前 | ファイルのバイト数 | `file_size(name)` |
| 1 | ファイル | ファイルの内容を丸ごと読み込む | `a`: 名前，`b`: 読み込み先，`c`: 読み込み先のバイト数 | 読み込んだバイト数 | `file_read(name, buf, size)` |
| 2 | ファイル | ファイルの内容を丸ごと書き込む | `a`: 名前，`b`: 書き込む内容，`c`: そのバイト数 | `0` | `file_write(name, data, length)` |
| 3 | コンソール | コンソールから1行を受け取る | `a`: 格納先，`b`: 格納先のバイト数 | 格納した文字数 | `console_read(buf, size)` |
| 4 | コンソール | コンソールへ出力する | `a`: 出力するバイト列，`b`: そのバイト数 | `0` | `console_write(data, length)` |
| 5 | 実行ファイル | 実行ファイルを終え，シェルへ戻る | `a`: 終了状態([qosmos/user/command.md](../user/command.md)の「終了状態」を参照) | なし(戻らない) | なし(Pynesisのコンパイラが`main`の終了で実行する．[pynesis/compiler.md](../../pynesis/compiler.md)の「出力先」を参照) |

- 読み込み: 内容をそのまま書き写し，ヌル終端は付けない．内容が読み込み先に収まらない場合は，読み込み先へ何も書き込まずにエラーを返す．読み出しの途中で失敗した場合は，読み込み先に書き写した内容が途中のまま残る．ファイルの大きさは，必要なら番号0で調べてから読み込む
- 書き込み: 内容を丸ごと置き換え，ファイルが無ければ作成する(失敗した場合に残る内容を含め，`write`コマンドと同じ動作．[qosmos/user/command.md](../user/command.md)の「コマンド一覧」を参照)．新しい内容を空きへ書き終えてから元の内容を解放するため，元の内容が占めている領域は新しい内容の書き込みに使えない(空きが足りなければ，同じ大きさや小さい内容への上書きでもエラーになる)
- コンソールからの1行の入力: 改行までの1行を，改行を除いてヌル終端付きで格納し，改行を読み出した時点で成功を返す．シェルと同じくエコーと1行の編集を行う([qosmos/user/console.md](../user/console.md)の「1行の入力」を参照)．格納できる文字数は格納先のバイト数-1で，それを超えた分は捨てる．受け取った文字は，各端末の受信バッファから読み出した時点で処理する([qosmos/user/console.md](../user/console.md)の「1行の入力」「UARTの接続」を参照)．telnetでの接続が切れてもエラーにはせず，UARTで接続した端末から続けて受け取る．受け取る途中で新たな端末がtelnetで接続した場合は，受け取り途中の行を捨てて受け取り直す([qosmos/user/console.md](../user/console.md)を参照)
- コンソールへの出力: シェルの出力と同じく変換する(改行の前に復帰を補い，値0のバイトは省き，telnetで接続した端末へは値`0xFF`のバイトを`0xFF 0xFF`として送る．[qosmos/user/console.md](../user/console.md)の「コンソール」「telnet」を参照)．この機能を呼び出すたびに，ためた出力をtelnetで接続した端末へ送る．telnetでの接続が切れたことは送る時点で分かり，そのときまでにためたtelnetで接続した端末への出力と，以降のtelnetで接続した端末への出力は失われる．接続が切れてもエラーにはしない
- 番地: ファイルの名前は，ヌル終端までが領域に収まる必要がある．読み込み先・書き込む内容・格納先・出力するバイト列は，番地から渡したバイト数の範囲が領域に収まる必要がある．収まらなければ，何も読み書きせずにエラー`-2`を返す．`nullptr`は領域の外を指す値のため，同じくエラー`-2`になる．大きな読み込み先・格納先は，スタックを使い切らないよう，スタック上ではなくグローバル変数に置く

## エラー
| 値 | 条件 |
|:-|:-|
| `-1` | 未定義の番号を渡した |
| `-2` | 引数の値が不正(番地が領域の外を指すか，バイト数が機能の受け付ける範囲の外にある．ファイルを扱う機能は0以上，コンソールを扱う機能は1以上のバイト数を受け付ける) |
| `-3` | ファイルが読み込み先に収まらないか，大きさが`int`の正の値で表せない |
| `-4` | 指定した名前のファイルが無い |
| `-5` | 指定した名前がディレクトリを指す |
| `-6` | 名前が規則に合わない |
| `-7` | SDカードに空きが無い |
| `-8` | ファイルを扱う機能が`-3`〜`-7`のほかの理由で失敗した(SDカードを読み書きできない場合や，ファイルシステムの記録が壊れている場合など) |

## ライブラリ
Pynesisでは，`qurge`の`mypc.srcs/pn/lib/syscall.pn`を取り込めば，次の関数を使える．番号とエラーの値も，同じファイルから取り込まれる`syscall_number.pn`に定数として定義されている．番号を指定して機能を呼び出す場合は，組み込み関数`syscall`を使う([pynesis/language.md](../../pynesis/language.md)の「システムコールを呼ぶ組み込み関数」を参照)．

| 関数 | 内容 |
|:-|:-|
| 各機能の名前の関数 | その機能を呼び出す(上記「機能」の表の「ライブラリの関数」の列を参照) |
| `console_print(text)` | ヌル終端の文字列をコンソールへ出力する(文字数は渡さなくてよい．関数の中で数える) |
