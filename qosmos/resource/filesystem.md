# ファイルシステム
パソコン(Windowsなどが動く一般のパソコン)でFAT32にフォーマットしたSDカードを読み書きする．Pynthesisで作成・変更したファイル・ディレクトリは，カードをパソコンへ差せばそのまま読める．フォーマットは行えないため，パソコンで行う．

## 扱えるカード
- 扱えるカードはSDHC/SDXCで，SDSC(容量2GB以下．SD v1のカードを含む)には対応しない
- カードはFAT32でフォーマットされている必要がある．FAT16やexFAT(SDXCカードの標準のフォーマット)には対応しないため，FAT32でフォーマットし直して使う
- カードの第1パーティションの種別がFAT32(`0x0B`または`0x0C`)であれば，そのパーティションをマウントする．パーティションを持たず，カードの先頭からFAT32ファイルシステムが始まるカードもマウントできる
- セクタ長が512バイトのファイルシステムのみ扱える

## 起動時の段階
1. リセット(CMD0): カードをSPIモードへ切り替えてリセットする．アイドル状態を表す応答(`0x01`)が返らなければ失敗とする．カードが差さっていない場合は無応答(`0xff`)になる
2. 電圧確認(CMD8): 2.7〜3.6Vで動くかを問い合わせる．応答が`0x01`で，問い合わせた電圧範囲とチェックパターン(`0x01`・`0xaa`)がそのまま戻れば成功とし，それ以外は失敗とする．パターンが戻らない場合の理由に添える値は，戻った電圧範囲とチェックパターンの2バイトとする．SD v1のカードはこの問い合わせを拒否するため，ここで失敗する
3. 初期化完了待ち(ACMD41): カードに内部の初期化を始めさせ，初期化中を表す応答(`0x01`)と完了を表す応答(`0x00`)以外が返った場合と，規格上の上限である1秒を過ぎても完了が返らない場合に失敗とする
4. カード種別(CMD58): カードの種別を読み出し，応答が`0x00`以外の場合と，SDSCである場合に失敗とする．SDSCである場合の理由に添える値は，種別を表すOCRの最上位バイトとする．成功の行には，SDSCでないことを表す種別名`SDHC/SDXC`を添える
5. マウント: カードから読み出せない場合と，FAT32ファイルシステムが見つからない場合に失敗とする

## ディレクトリ
- シェルは現在のディレクトリを1つ持ち，2つの端末で共有する．起動時(`reboot`による再起動を含む)にマウントした時点ではルートディレクトリで，`cd`で移る．端末がtelnetで接続しても変わらない
- 名前は，現在のディレクトリの直下にあるファイル・ディレクトリの名前だけを指定できる．`/`で区切ったパス(`/DOCS`・`DOCS/a.txt`など)は，`/`が名前に使えない文字のため，名前が規則に合わないエラーになる
- `cd`は次のように移る

  | 書式 | 動作 |
  |:-|:-|
  | `cd` | ルートディレクトリへ移る |
  | `cd <名前>` | 現在のディレクトリの直下にある，その名前のディレクトリへ移る |
  | `cd ..` | 親ディレクトリへ移る．ルートディレクトリでは何もしない |
  | `cd .` | 何もしない |
- `pwd`は，ルートディレクトリを`/`とし，ルートディレクトリから現在のディレクトリまでの各ディレクトリの名前を`/`に続けて並べた絶対パスを出力する(`/DOCS/sub`など)．各名前は`ls`と同じ形で表示する
- 現在のディレクトリの絶対パスは255文字まで保持できる．これを超えるディレクトリへの`cd`はエラーになる
- `.`・`..`は，ディレクトリ自身と親ディレクトリを表すエントリである．FAT32の決まりにより，ルート以外のディレクトリは先頭にこの2つを持ち，ルートディレクトリはどちらも持たない．`cd`はこれらのエントリを読まずに移るため，ルートディレクトリでも上の`cd`の表のとおりに動く．`mkdir`はこの2つを作成する．`ls`はこれらを表示せず，`cd`以外のコマンドでは名前として指定できない(名前が規則に合わないエラーになる)
- `rmdir`は，`.`・`..`以外のエントリが無いディレクトリだけを削除する．中身ごと削除する機能は無い
- パソコンで作ったディレクトリも，Pynthesisで作ったディレクトリと同じように辿れる

## ファイル・ディレクトリの名前
- 名前は8.3形式(基本名1〜8文字，拡張子0〜3文字．いずれも空白を含まない)の短い名前で扱う．ディレクトリの名前もファイルと同じ規則に従い，拡張子を持てる．空白は引数の区切りになるため，空白を含む名前は指定できない
- 長いファイル名(LFN)は読まず，LFNを持つファイルも短い名前で表示・指定する．パソコンで8.3形式に収まらない名前や空白を含む名前を付けると，パソコンのOSが空白を除いた短い名前を作り，元の長いファイル名とは別に記録する(`LongFileName.txt`は`LONGFI~1.TXT`，`My File.txt`は`MYFILE~1.TXT`になる)．SDカード自体はセクタを読み書きするだけで，名前を作る機能は持たない
- 指定する名前は，大文字・小文字を区別せずに照合する．パソコンが作った短い名前(`~1`などの付いた名前)も，`ls`が表示したとおりに指定できる
- 規則に合わない名前はエラーになる．名前の規則は次のとおり
  - 8.3形式に収まること．収まらない名前は切り詰めて扱わない(切り詰めると別のファイルの名前になりうるため)
  - 制御文字・空白と，記号`" * + , / : ; < = > ? [ \ ] |`を含まないこと(FATの仕様で，短い名前に使えないと定められた文字のため)
- Pynthesisで作成・変更した名前は，カードには大文字で記録する．長いファイル名は作らないため，英字を大文字・小文字のどちらで表示するかは小文字で表示する印だけで決まる(数字や`( )`などの記号は変換されず，入力したとおりに表示される．パソコンで付けた名前の表示は後述)．基本名・拡張子のそれぞれについて，英小文字だけで書いた部分には，Windowsと同じく小文字で表示する印を付けるため，`ls`とパソコンで小文字のまま表示される．大文字・小文字が混ざった部分は大文字で表示される(`Hello.txt`は，大文字・小文字が混ざった基本名`Hello`が大文字になり，小文字だけの拡張子`txt`は小文字のまま残るため，`HELLO.txt`と表示される)
- パソコンで長いファイル名を付けたファイル・ディレクトリには，短い名前とは別に長いファイル名が記録されている．これを削除・名前の変更すると，記録されている長いファイル名もあわせて削除する．このため名前を変更したファイル・ディレクトリは，パソコンでも変更後の短い名前で表示される．内容を書き換えただけのファイルは，パソコンで元の長いファイル名のまま表示される
- `ls`は，短い名前を基本名・拡張子ごとに次の規則で表示する．パソコンで付けた名前の基本名・拡張子がそれぞれ大文字のみ・小文字のみで書かれていれば，付けた名前のとおりに表示される
  - パソコンが小文字で表示する印を付けた部分(Windowsが全て小文字の基本名・拡張子に付ける)は小文字で表示する
  - それ以外は大文字で表示する．パソコンは，大文字・小文字が混ざった名前や8.3形式に収まらない名前には長いファイル名を作り，元の名前をそちらにだけ記録する．このとき短い名前には印を付けないため，拡張子を含めて全て大文字で表示される
- ファイルの属性(隠しファイル・読み取り専用など)による区別は行わず，どのファイルも他のファイルと同じように表示・操作できる．Windowsが拒む読み取り専用のファイルへの書き込みや削除も行える(Windowsが作る`System Volume Information`は`SYSTEM~1/`と表示される)

## ファイルの内容
- 内容はバイト列をそのまま文字として出力する．文字コードの変換は行わない
- 内容の途中にある値0のバイトは出力しない(テキストファイルを想定しており，バイナリファイルの表示には対応しない)

## 書き込みの前提
- 時計を持たないため，作成・変更したファイル・ディレクトリの日時は1980年1月1日0時0分(FATで表せる最も古い日時)になる
- ファイルシステムが記録している空きクラスタ数は，マウントしてから最初にファイル・ディレクトリの領域を確保または解放する時点で「不明」を表す値にし，以降は更新しない．パソコンは次に差したときに数え直す
- 書き込みの途中で中断した場合(電源を切った場合など)の整合性は保証しない．壊れた記録はパソコンのディスク検査で修復する
