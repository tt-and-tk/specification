# ネットワーク
Ethernetモジュール(W5100S)を通してLANにつながる．モジュールを制御するレジスタは[qurge/cpu/register.md](../../qurge/cpu/register.md)の`6'h26`を参照．

## 設定
起動時に次の値を設定する．値はQosmosのソースに固定しており，変えるにはROMを作り直す．DHCPによる自動取得は行わない．

| 設定 | 値 |
|:-|:-|
| MACアドレス | `02:00:00:00:00:01`(ローカル管理アドレス) |
| IPアドレス | `192.168.10.200` |
| サブネットマスク | `255.255.255.0` |
| ゲートウェイ | `192.168.10.1` |

## 起動時の段階
1. リセット: モジュールをハードウェアリセットし，動き出すまで待ってからバージョンを読み出す．W5100Sの値(`0x51`)でなければ失敗とする．モジュールが接続されていない場合は無応答(`0xff`)になる
2. ネットワークの設定: 「設定」の表の値を書き込み，読み戻した値が1つでも異なれば失敗とする．成功の行には設定したIPアドレスを添える

成功は設定を書き込めたことを表し，ケーブルの接続やリンクの確立は確かめない．

## 応答
`ping`(ICMPのエコー要求)にはモジュールが自動で応答する．CPUの処理を介さないため，シェルの入力待ちの間も実行ファイルの実行中も応答する．リンクが確立していなければ応答しない．

## TCP
TCPの接続の確立・再送・切断はモジュールが行い，Qosmosは接続の待ち受け・受け付け，データの送受信，切断の検出を行う．Qosmosは接続を待ち受ける側だけを担い，自分から接続しには行かない．同時に扱う接続は1つで，シェルのコンソールとして使う([qosmos/user/console.md](../user/console.md)の「telnetでの接続」を参照)．

相手が切断を伝えずに応答しなくなった場合(ケーブルが抜けた場合など)は検出せず，接続中のままになる．その間は，別の相手からの接続を受け付けない．送信中であれば，モジュールの再送のタイムアウトで接続が切れたとみなす．
