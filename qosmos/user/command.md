# 組み込みコマンド
シェル([qosmos/user/shell.md](shell.md)を参照)は，次の組み込みコマンドを持つ．  

| 分類 | コマンド |
|:-|:-|
| シェル | `echo`・`help`・`status` |
| ファイル | `ls`・`cat`・`touch`・`write`・`rm`・`mv` |
| ディレクトリ | `mkdir`・`rmdir`・`cd`・`pwd` |
| システム | `reboot`・`exit` |

書式の`<名前>`は省略できない引数を，`[名前]`は省略できる引数を表す．  

# 共通の規則
- 名前を引数に取るコマンドは，`cd`の`.`・`..`を除き，現在のディレクトリの直下にあるファイル・ディレクトリを対象にする([qosmos/user/shell.md](shell.md)の「現在のディレクトリ」を参照)  
- 名前は，[qosmos/user/file.md](file.md)の「名前の規則」に従う  
- 引数を取らないコマンドに引数を与えると，エラーになる  
- エラーになると，コマンド名を前置したエラーメッセージを出力し，何も行わない([qosmos/user/shell.md](shell.md)の「エラーの表示」を参照)  

## ファイル操作に共通するエラー
ファイル・ディレクトリを扱うコマンドは，各節に書いた条件のほか，次の場合もエラーになる．  

- ファイルシステムをマウントしていない([qosmos/user/boot.md](boot.md)を参照)  
- カードを読み書きできない  
- ファイルシステムの記録が壊れている  

## 途中で失敗した場合
カードを書き換えるコマンドが途中でカードの読み書きに失敗した場合，それまでの書き換えはそのまま残る．  
`write`の例外は，「write」の節を参照．  

# echo
```
echo [文字列]
```

引数をそのまま出力する．  
引数が無ければ，空行を出力する．  
エラーにはならない．  

# help
```
help
```

使えるコマンド名の一覧を出力する．  

# status
```
status
```

直前のコマンドの終了状態を，10進数で出力する([qosmos/user/shell.md](shell.md)の「終了状態」を参照)．  
`status`自身は終了状態を変えない．  

# ls
```
ls
```

現在のディレクトリにあるファイルとディレクトリの名前を，1行ずつ出力する．  

- ディレクトリは，名前の末尾に`/`を付ける  
- 出力する順序は，ディレクトリに記録された順序であり，名前順ではない  
- 名前の表示の規則は，[qosmos/user/file.md](file.md)の「名前の表示」を参照  
- 出力の途中で読み出しに失敗した場合，それまでに出力した内容はそのまま残る  

# cat
```
cat <名前>
```

ファイルの内容を出力する．  

- ファイルの内容が改行で終わっていなければ，末尾に改行を補う  
- 内容が空のファイルでは，何も出力しない  
- 内容の扱いは，[qosmos/user/file.md](file.md)の「ファイルの内容」を参照  
- 出力の途中で読み出しに失敗した場合，それまでに出力した内容はそのまま残る  

次の場合はエラーになる．  

- 引数の過不足  
- 名前が規則に合わない  
- 該当するファイルが無い  
- 名前がディレクトリを指す  

# touch
```
touch <名前>
```

内容が空のファイルを作成する．  
同じ名前のファイルが既にあればエラーになり，そのファイルには何もしない．  
Unixの`touch`のように，既存のファイルの更新日時を書き換えて成功する動作はしない．  

次の場合はエラーになる．  

- 引数の過不足  
- 名前が規則に合わない  
- 同じ名前のファイル・ディレクトリが既にある  
- カードに空きが無い  

# write
```
write <名前> [内容]
```

ファイルの内容を，名前の後ろの引数全体で置き換える．  
ファイルが無ければ作成する．  

- 名前の後ろを空白で区切らず，丸ごと内容として扱う．このため，内容に空白を含められる．名前との間の空白だけが，区切りとして取り除かれる  
- 内容を省くと，空のファイルになる  
- 内容の末尾に改行は付けない  
- 書ける内容の長さは，1行の長さの上限(63文字)から，コマンド名・名前とその前後の空白を除いた分までである  

次の場合はエラーになる．  

- 名前が無い  
- 名前が規則に合わない  
- 名前がディレクトリを指す  
- カードに空きが無い  

## 途中で失敗した場合
`write`は，新しい内容を元の内容とは別の空きへ書き終えてから，ファイルの記録を差し替える．  

- 差し替えより前に失敗した場合(カードの空きが足りない場合を含む): ファイルは元の内容のまま残る．ファイルが無く新たに作成した場合は，内容が空のファイルが残る  
- 差し替えの書き込みそのものに失敗した場合: 元の内容と新しい内容のどちらになっているかは分からない  

元の内容が占めている領域は，新しい内容の書き込みに使えない．  
このため，空きが足りなければ，同じ大きさや小さい内容への書き換えでもエラーになる．  

# rm
```
rm <名前>
```

ファイルを削除する．  
ディレクトリは削除できない．  
ディレクトリは`rmdir`で削除する．  

次の場合はエラーになる．  

- 引数の過不足  
- 名前が規則に合わない  
- 該当するファイルが無い  
- 名前がディレクトリを指す  

# mv
```
mv <旧名> <新名>
```

ファイル・ディレクトリの名前を変更する．  

- 大文字・小文字だけが異なる名前へも変更できる  
- 名前を変えるだけで，別のディレクトリへは移せない．新名に既存のディレクトリの名前を指定すると，Unixの`mv`のようにその中へ移すのではなく，名前の重複としてエラーになる  

次の場合はエラーになる．  

- 引数の過不足  
- 名前が規則に合わない  
- 旧名に当たるものが無い  
- 新名がほかのファイル・ディレクトリと重複する  

# mkdir
```
mkdir <名前>
```

空のディレクトリを作成する．  
作成したディレクトリには，`.`・`..`のエントリを作る([qosmos/user/file.md](file.md)の「.と..」を参照)．  

次の場合はエラーになる．  

- 引数の過不足  
- 名前が規則に合わない  
- 同じ名前のファイル・ディレクトリが既にある  
- カードに空きが無い  

# rmdir
```
rmdir <名前>
```

空のディレクトリを削除する．  
空のディレクトリとは，`.`・`..`以外のエントリが無いディレクトリである．  
中身ごと削除する機能は無い．  

次の場合はエラーになる．  

- 引数の過不足  
- 名前が規則に合わない  
- 該当するディレクトリが無い  
- 名前がファイルを指す  
- ディレクトリが空でない  

# cd
```
cd [名前]
```

現在のディレクトリを移す．  

| 書式 | 動作 |
|:-|:-|
| `cd` | ルートディレクトリへ移る |
| `cd <名前>` | 現在のディレクトリの直下にある，その名前のディレクトリへ移る |
| `cd ..` | 親ディレクトリへ移る．ルートディレクトリでは何もしない |
| `cd .` | 何もしない |

- `.`・`..`のエントリは読まずに移る．このため，ルートディレクトリでも表のとおりに動く  
- 現在のディレクトリの絶対パスは，255文字まで保持できる．これを超えるディレクトリへの`cd`はエラーになる  

次の場合はエラーになる．  

- 引数が多い  
- 名前が規則に合わない  
- 該当するディレクトリが無い  
- 名前がファイルを指す  
- 移る先の絶対パスが長すぎる  

# pwd
```
pwd
```

現在のディレクトリの絶対パスを出力する(`/DOCS/sub`など)．  

- ルートディレクトリを`/`とし，ルートディレクトリから現在のディレクトリまでの各ディレクトリの名前を，`/`に続けて並べる  
- 各名前は，`ls`と同じ形で表示する  

ファイルシステムをマウントしていない場合はエラーになる．  

# reboot
```
reboot
```

Qosmosを起動し直す．  
電源を入れたときと同じく，SDカードとEthernetモジュールを使える状態にし直し，OS名を出力する([qosmos/user/boot.md](boot.md)を参照)．  

- 現在のディレクトリは，ルートディレクトリに戻る  
- 途中でtelnetでの接続を閉じる．このため，Ethernetモジュールの段階の行とOS名は，UARTで接続した端末にだけ届く([qosmos/user/boot.md](boot.md)の「起動の行が届く端末」を参照)．SDカードとファイルシステムの段階の成否は，接続し直して`status`で確かめられる  

## エラーの伝え方
`reboot`は，引数を与えた場合を除き，コマンド名を前置したエラーメッセージを出力しない．  

- SDカードとファイルシステムの段階の失敗: 起動時と同じ形の行と，終了状態で伝わる  
- Ethernetモジュールの段階の失敗: エラーとせず，telnetでの接続を受け付けられるまでやり直す  

SDカードとファイルシステムの段階で失敗した場合は，それまでマウントしていたファイルシステムも外れる．  
以降は，`reboot`ですべての段階が成功するまで，ファイルを扱うコマンドは，マウントしていない旨のエラーになる．  

# exit
```
exit
```

telnetでの接続を閉じ，次の接続を待ち受ける([qosmos/user/console.md](console.md)の「telnetでの接続」を参照)．  
それまでの出力を相手へ送り切ってから閉じる．  

次の場合はエラーになる．  

- 引数を与えた  
- 行を入力した端末([qosmos/user/console.md](console.md)の「1行の入力」を参照)が，UARTで接続した端末である  
- コマンドを受け取った後の出力の送信で，telnetでの接続が切れた
