# 入力の解析
プロンプト`> `を表示して1行を受け取り，半角空白で区切った先頭のトークンをコマンド名，以降を引数として扱う．

- 区切りとして扱うのは半角空白のみで，タブなど他の空白文字は引数の一部になる．コマンド名の手前と引数の間の空白は何文字でもよい
- コマンド名が下表の組み込みコマンドのいずれかと完全に一致すれば(大文字・小文字を区別する)，そのコマンドを実行する．一致しなければ，同じ名前の実行ファイルを探して実行する([qosmos/program/executable.md](../program/executable.md)を参照)．どちらも見つからない場合はエラーになり，何も実行しない
- コマンド名が無い行(改行だけの行，空白だけの行，入力した文字をすべてバックスペースで消した行など)は，何も実行・出力せず次のプロンプトを表示する
- 1行の長さの上限は63文字である．上限を超えた分とバックスペースの扱いは[qosmos/user/console.md](console.md)の「1行の入力」を参照

# コマンド一覧
| 書式 | 動作 | エラーになる条件 |
|:-|:-|:-|
| `echo [文字列]` | 引数をそのまま出力する(引数が無ければ空行を出力する) | なし |
| `help` | 使用できるコマンド名の一覧を出力する | 引数を与えた |
| `status` | 直前のコマンドの終了状態を10進数で出力する(「終了状態」を参照) | 引数を与えた |
| `ls` | 現在のディレクトリにあるファイルとディレクトリの名前を1行ずつ出力する．ディレクトリは名前の末尾に`/`を付ける | 引数を与えた，ファイル操作に共通する条件 |
| `cat <名前>` | ファイルの内容を出力する | 引数の過不足，名前が規則に合わない，該当するファイルが無い，名前がディレクトリを指す，ファイル操作に共通する条件 |
| `touch <名前>` | 内容が空のファイルを作成する | 引数の過不足，名前が規則に合わない，同じ名前のファイル・ディレクトリが既にある，カードに空きが無い，ファイル操作に共通する条件 |
| `write <名前> [内容]` | ファイルの内容を，名前の後ろの引数全体で置き換える．ファイルが無ければ作成する | 名前が無い，名前が規則に合わない，名前がディレクトリを指す，カードに空きが無い，ファイル操作に共通する条件 |
| `rm <名前>` | ファイルを削除する | 引数の過不足，名前が規則に合わない，該当するファイルが無い，名前がディレクトリを指す，ファイル操作に共通する条件 |
| `mv <旧名> <新名>` | ファイル・ディレクトリの名前を変更する | 引数の過不足，名前が規則に合わない，旧名に該当するものが無い，新名が他のファイル・ディレクトリと重複する，ファイル操作に共通する条件 |
| `mkdir <名前>` | 空のディレクトリを作成する | 引数の過不足，名前が規則に合わない，同じ名前のファイル・ディレクトリが既にある，カードに空きが無い，ファイル操作に共通する条件 |
| `rmdir <名前>` | 空のディレクトリを削除する | 引数の過不足，名前が規則に合わない，該当するディレクトリが無い，名前がファイルを指す，ディレクトリが空でない，ファイル操作に共通する条件 |
| `cd [名前]` | 現在のディレクトリを移す(移り方は，下記の前提となる挙動の`cd`の表を参照) | 引数が多い，名前が規則に合わない，該当するディレクトリが無い，名前がファイルを指す，移動先のパスが長すぎる，ファイル操作に共通する条件 |
| `pwd` | 現在のディレクトリの絶対パスを出力する | 引数を与えた，ファイルシステムをマウントしていない |
| `reboot` | OSを再起動する([qosmos/boot.md](../boot.md)の「起動時の動作」のハードウェアの初期化をやり直し，OS名を出力する)．現在のディレクトリはルートディレクトリに戻る．途中でtelnetでの接続を閉じる([qosmos/user/console.md](console.md)の「telnetでの接続」を参照) | 引数を与えた，SDカードの初期化に失敗した，カードから読み出せない，カード上にFAT32ファイルシステムが見つからない |
| `exit` | telnetでの接続を閉じ，次の接続を待ち受ける([qosmos/user/console.md](console.md)の「telnetでの接続」を参照) | 引数を与えた，行が入力された端末([qosmos/user/console.md](console.md)の「1行の入力」を参照)がUARTで接続した端末である，コマンドを受け取った後の出力の送信でtelnetでの接続が切れた |

名前を引数に取るコマンドは，いずれも現在のディレクトリの直下にあるファイル・ディレクトリを対象にする([qosmos/resource/filesystem.md](../resource/filesystem.md)の「ディレクトリ」を参照)．\
表中の「ファイル操作に共通する条件」は，ファイルシステムをマウントしていない場合，カードを読み書きできない場合，ファイルシステムの記録が壊れている場合を指す．

上表のエラーになる条件に当てはまる場合は，コマンド名を前置したエラーメッセージを出力し，そのコマンドは何も行わない．ただし次のものは例外である．

- `reboot`は，引数を与えた場合を除き，コマンド名を前置したエラーメッセージを出力しない．ストレージの項目([qosmos/boot.md](../boot.md)を参照)の失敗は，起動時と同じ形の行と終了状態で伝わる．ネットワークの項目の失敗はエラーとせず，接続を受け付けられるまでやり直す(「終了状態」と，[qosmos/user/console.md](console.md)の「telnetでの接続」を参照)．ストレージの段階で失敗した場合は，それまでマウントしていたファイルシステムも外れる．以降は，`reboot`でストレージの全段階が成功するまで，ファイルを扱うコマンドはマウントしていない旨のエラーになる
- `ls`・`cat`が出力の途中で読み出しに失敗した場合，それまでに出力した内容はそのまま残る
- カードを書き換えるコマンドが途中でカードの読み書きに失敗した場合，それまでの書き換えはそのまま残る．ただし`write`は，新しい内容を元の内容とは別の空きへ書き終えてからファイルの記録を差し替えるため，差し替えより前に失敗すれば(カードの空きが足りない場合を含む)ファイルは元の内容のまま残る(ファイルが無く新たに作成した場合は，内容が空のファイルが残る)．差し替えの書き込みそのものに失敗した場合は，元の内容と新しい内容のどちらになっているか分からない

使用にあたって前提となる挙動:

- `cat`は，ファイルの内容が改行で終わっていなければ末尾に改行を補う．内容が空のファイルでは何も出力しない
- `ls`が出力する順序は，ディレクトリに記録された順序であり，名前順ではない
- `write`は，名前の後ろを空白で区切らず丸ごと内容として扱うため，内容に空白を含められる(名前との間の空白だけが区切りとして取り除かれる)．内容を省くと空のファイルになる．内容の末尾に改行は付けない
- `write`で書ける内容の長さは，1行の長さの上限から，コマンド名・名前とその前後の空白を除いた分までである
- `touch`は，同じ名前のファイルが既にあればエラーになり，そのファイルには何もしない(Unixの`touch`のように，既存のファイルの更新日時を書き換えて成功する動作はしない)
- `mv`は，大文字・小文字だけが異なる名前へも変更できる．名前を変えるだけで，別のディレクトリへは移せない(新名に既存のディレクトリの名前を指定すると，Unixの`mv`のようにその中へ移すのではなく，名前の重複としてエラーになる)
- `rm`はファイルだけを削除する．ディレクトリは`rmdir`で削除する
- `rmdir`は，`.`・`..`以外のエントリが無いディレクトリだけを削除する．中身ごと削除する機能は無い
- `cd`は次のように移る．`.`・`..`のエントリ([qosmos/resource/filesystem.md](../resource/filesystem.md)の「ディレクトリ」を参照)は読まずに移るため，ルートディレクトリでもこの表のとおりに動く

  | 書式 | 動作 |
  |:-|:-|
  | `cd` | ルートディレクトリへ移る |
  | `cd <名前>` | 現在のディレクトリの直下にある，その名前のディレクトリへ移る |
  | `cd ..` | 親ディレクトリへ移る．ルートディレクトリでは何もしない |
  | `cd .` | 何もしない |
- 現在のディレクトリの絶対パスは255文字まで保持できる．これを超えるディレクトリへの`cd`はエラーになる
- `pwd`は，ルートディレクトリを`/`とし，ルートディレクトリから現在のディレクトリまでの各ディレクトリの名前を`/`に続けて並べた絶対パスを出力する(`/DOCS/sub`など)．各名前は`ls`と同じ形で表示する

# 終了状態
シェルは終了状態(整数1つ)を保持し，成否を確かめられるよう`status`で出力する．保持するのは，電源を入れてから最初のコマンドを実行するまでは電源を入れたときの起動時の動作の結果，その後は直前に実行したコマンドの結果である．出力は符号付きの10進数1行で，負の数は`-`を前置する．

| 直前に行ったこと | 終了状態 |
|:-|:-|
| 電源を入れたときの起動時の動作(まだコマンドを実行していない場合) | ストレージの項目が成功すれば0，失敗すれば1 |
| 組み込みコマンド | 成功すれば0，エラーになれば1 |
| 実行ファイル | 実行ファイルが終了のシステムコールで渡した値(Pynesisでは`main`の戻り値で，`main`が`return`文を通らずに終端へ進んだ場合は不定．[qosmos/program/executable.md](../program/executable.md)の「実行の仕方」を参照) |
| 実行ファイルを実行できなかったコマンド([qosmos/program/executable.md](../program/executable.md)の「エラー」を参照) | 1 |

- 組み込みコマンドのエラーには，出力や書き換えの途中で失敗した場合も含む．`reboot`(引数なし)は，電源を入れたときと同じく，ストレージの項目が失敗すれば1になる
- 起動時の動作の終了状態には，ネットワークの項目の成否を含めない．失敗しても，telnetでの接続を受け付けられるまでやり直すためである([qosmos/user/console.md](console.md)の「telnetでの接続」を参照)．起動時のネットワークの項目の結果は，UARTで接続した端末に届く行で確かめる
- `status`自身は終了状態を変えない．引数を与えてエラーになった場合も変えないため，何度実行しても同じ値を確かめられる
- コマンド名が無い行は，何も実行しないため終了状態を変えない
- 実行ファイルが返した1と，実行ファイルを実行できなかった場合の1は区別しない．実行できなかった場合は，その理由がコマンド名を前置したエラーメッセージで出力される
