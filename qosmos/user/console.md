# コンソール
コンソールは，シェルと実行ファイルが1行を受け取り，出力を表示する端末である．  
コンソールは次の2つの端末から成り，どちらからでもQosmosを操作できる．  
端末のつなぎ方の手順は，[operation.md](../../operation.md)の「接続」を参照．  

| 端末 | つなぎ方 | 使える間 |
|:-|:-|:-|
| telnetで接続した端末 | LANを通して，IPアドレス`192.168.10.200`のポート`23`へtelnetで接続する | 接続している間．同時に接続できるのは1つ |
| UARTで接続した端末 | ボードの電源用のUSB(PROG/UART)をパソコンにつなぎ，USBのシリアル通信(UART)でやり取りする | 常に |

実行ファイルは，システムコールを通してコンソールを使う([qosmos/program/syscall.md](../program/syscall.md)を参照)．  

# 2つの端末の関係
2つの端末は，1つの画面を2か所で共有する形で使う．  

- 出力: UARTで接続した端末へは常に送り，telnetで接続した端末へは接続している間だけ送る  
- 入力: どちらの端末から入力された文字も受け付ける  
- 受け取り途中の1行は，2つの端末で共有する．このため，両方の端末で同時に打つと，文字が1行に混ざる．BS・DELは，もう一方の端末で入力された文字も取り消す  
- 現在のディレクトリも，2つの端末で共有する  
- 入力された文字の表示(エコー): UARTで接続した端末へは常に送る．telnetで接続した端末へは，telnetのエコーのオプションが有効な間だけ送る([qosmos/kernel/console.md](../kernel/console.md)の「telnetのオプション」を参照)  

## 新たにtelnetで接続したとき
接続すると，OS名を出力する．  
直前の起動でストレージの項目が失敗していれば，そのやり直し方も出力する([qosmos/user/boot.md](boot.md)を参照)．  
以下，これらの出力を案内と呼ぶ．  
接続したときに行っていたことによって，扱いは次のように異なる．  

- シェルが1行を受け取る途中: 受け取り途中の行を捨て，行を改めて案内を出力してから，プロンプトを表示し直す  
- 実行ファイルが1行を受け取る途中: 受け取り途中の行を捨てて，受け取り直す．案内は，そのコマンドが終わった後も出力しない  
- コマンドの実行中: コマンドが終わった後，プロンプトを表示する前に案内を出力する  

# UARTの接続
| 設定 | 値 |
|:-|:-|
| 通信速度 | 115200bps |
| データ | 8ビット |
| パリティ | なし |
| ストップビット | 1 |
| フロー制御 | なし |

- 受け取ったバイトは，そのまま文字として扱う  
- 端末のソフトウェアがシリアルポートを開いていない間に送られた出力は失われる．ボードの電源を入れた後に開いても使える  
- コマンドの実行中に入力した文字は，シェルや実行ファイルが次に入力を待つときに表示される．ためておける量を超えて打つと，超えた分の文字は失われる([qosmos/kernel/console.md](../kernel/console.md)の「UARTの送受信」を参照)  

# telnetでの接続
- 接続を受け付けるのは，起動を終えてプロンプトを表示した後である  
- ネットワークの項目が失敗していても，Qosmosがやり直すうちに接続できるようになる([qosmos/kernel/console.md](../kernel/console.md)の「接続の待ち受け」を参照)  
- 接続中に別の相手が接続しようとしても，受け付けない  
- `exit`で接続を閉じる([qosmos/user/command.md](command.md)の「exit」を参照)．相手が切断した場合も，Qosmosは次の接続を待ち受ける  
- telnetではなく生のTCPで接続すると，接続直後に送るtelnetの申し出のバイト列が画面に表示される．また，入力した文字を端末自身も表示する場合は，二重に表示される  

## 出力が届く時点
telnetで接続した端末への出力はまとめて送るため，届くまでに遅れがある．  
シェルか実行ファイルが入力を待つ時点には，それまでの出力が届く．  
まとめて送る時点の一覧は，[qosmos/kernel/console.md](../kernel/console.md)の「telnetの送信」を参照．  

## 接続が切れたとき
相手が切断するか接続が切れると，Qosmosは接続を閉じて，次の接続を待ち受ける．  
受け取り途中の行はそのまま残り，UARTで接続した端末から続けて入力できる．  
送る前の出力は失われる．  

# 1行の入力
受け取った文字は，どちらの端末から受け取ったかによらず，次のように扱う．  

| 受け取った文字 | 1行の編集 | 画面の表示(エコー) |
|:-|:-|:-|
| 印字可能な文字(`0x20`〜`0x7E`)・タブ | 格納する．63文字を格納した後は捨てる | 格納した文字を表示する |
| BS(`0x08`)・DEL(`0x7F`) | 格納した直前の1文字を取り消す．格納した文字が無ければ何もしない | 取り消した文字を画面から消す |
| 復帰(CR)・改行(LF) | 行を確定する．同じ端末から受け取った復帰の直後のLF・NULは同じ改行の一部として捨てるため，`CR LF`・`CR NUL`も1つの改行になる | 改行を表示する |
| ほかの制御文字，`0x80`以上の値 | 捨てる | 表示しない |

- 入力した文字の表示は，端末ではなくQosmosが行う  
- 行を確定した時点で受け取っていた後続の文字は，次の行に使う  
- 行を入力した端末は，その行を確定した復帰・改行を送ってきた端末とする．2つの端末から入力された文字が混ざった行も同じである  
- タブを取り消すと，格納した内容からはタブ1文字が消えるが，画面上は1文字分しか戻らない  
- 日本語などのマルチバイト文字は入力できない  

## 出力の変換
- 改行(LF)の直前が復帰(CR)でなければ，復帰を補う．端末が改行だけでは行頭へ戻らないためである  
- 値0のバイトは出力しない
