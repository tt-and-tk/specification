# ファイルとディレクトリ
Qosmosは，パソコン(Windowsなどが動く一般のパソコン)でFAT32にフォーマットしたSDカードを読み書きする．  
Qosmosで作成・変更したファイル・ディレクトリは，カードをパソコンへ差せばそのまま読める．  
フォーマットはQosmosでは行えないため，パソコンで行う．  

```
> mkdir docs
> cd docs
> write memo.txt hello
> cat memo.txt
hello
> pwd
/docs
```

ファイルを扱うコマンドは，[qosmos/user/command.md](command.md)を参照．  

# 扱えるカード
扱えるカードの条件は，次のとおりである．  

- カードの種別: SDHC/SDXCである．容量2GB以下のSDSCには対応しない．SD v1のカードもSDSCに含まれる  
- フォーマット: FAT32である．FAT16やexFATには対応しないため，FAT32でフォーマットし直して使う．SDXCのカードは，標準ではexFATでフォーマットされている  
- パーティション: 第1パーティションの種別がFAT32(`0x0B`または`0x0C`)であれば，そのパーティションを使う．パーティションを持たず，カードの先頭からFAT32ファイルシステムが始まるカードも使える  
- セクタ長: ファイルシステムのセクタ長が512バイトである  

# ディレクトリ
ディレクトリの中に，ファイルとディレクトリを置ける．  
パソコンで作ったディレクトリも，Qosmosで作ったディレクトリと同じように辿れる．  
シェルで現在のディレクトリを移す方法は，[qosmos/user/shell.md](shell.md)の「現在のディレクトリ」を参照．  

## .と..
`.`・`..`は，ディレクトリ自身と親ディレクトリを表すエントリである．  
FAT32の決まりにより，ルート以外のディレクトリは先頭にこの2つを持ち，ルートディレクトリはどちらも持たない．  
コマンドでの扱いは，次のとおりである．  

- `mkdir`は，この2つを作成する  
- `ls`は，この2つを表示しない  
- `cd`以外のコマンドでは，名前として指定できない(名前が規則に合わないエラーになる)  

# 名前の規則
名前は，8.3形式の短い名前で扱う．  
8.3形式は，基本名1〜8文字と拡張子0〜3文字から成る名前である．  
ディレクトリの名前もファイルと同じ規則に従い，拡張子を持てる．  
名前には，制御文字・空白と，記号`" * + , / : ; < = > ? [ \ ] |`は使えない．  
FATの仕様で，短い名前に使えないと定められた文字のためである．  
空白は引数の区切りにもなる．  

規則に合わない名前はエラーになる．  
8.3形式に収まらない名前も，切り詰めずにエラーにする．  
切り詰めて扱うと，別のファイルの名前になりうるためである．  
指定する名前は，大文字・小文字を区別せずに照合する．  

## 長いファイル名
Qosmosは，長いファイル名(LFN)を読まない．  
LFNを持つファイルも，短い名前で表示・指定する．  

パソコンで8.3形式に収まらない名前や空白を含む名前を付けると，パソコンのOSが空白を除いた短い名前を作る．  
短い名前は，元の長いファイル名とは別に記録される．  
例えば，`LongFileName.txt`は`LONGFI~1.TXT`に，`My File.txt`は`MYFILE~1.TXT`になる．  
パソコンが作った短い名前(`~1`などの付いた名前)も，`ls`が表示したとおりに指定できる．  

長いファイル名を持つファイル・ディレクトリを削除するか名前を変更すると，記録されている長いファイル名もあわせて削除する．  
このため，名前を変更したものは，パソコンでも変更後の短い名前で表示される．  
内容を書き換えただけのファイルは，パソコンで元の長いファイル名のまま表示される．  

# 名前の表示
## Qosmosで付けた名前
Qosmosで作成・変更した名前は，カードには大文字で記録する．  
長いファイル名は作らないため，英字の大文字・小文字の表示は，小文字で表示する印だけで決まる．  
基本名・拡張子の各部分は，書き方によって次のように表示される．  

- 基本名・拡張子のそれぞれについて，英小文字だけで書いた部分には，Windowsと同じく小文字で表示する印を付ける．このため，`ls`でもパソコンでも小文字のまま表示される  
- 大文字・小文字が混ざった部分は，大文字で表示される(`Hello.txt`は`HELLO.txt`と表示される)  
- 数字や`( )`などの記号は変換されず，入力したとおりに表示される  

## パソコンで付けた名前
`ls`は，短い名前を基本名・拡張子ごとに次の規則で表示する．  

- パソコンが小文字で表示する印を付けた部分(Windowsが，すべて小文字の基本名・拡張子に付ける)は，小文字で表示する  
- それ以外は，大文字で表示する  

このため，基本名・拡張子がそれぞれ大文字だけ・小文字だけで書かれていれば，付けた名前のとおりに表示される．  
大文字・小文字が混ざった名前や8.3形式に収まらない名前には，パソコンが長いファイル名を作り，元の名前をそちらにだけ記録する．  
このとき短い名前には印を付けないため，拡張子を含めてすべて大文字で表示される．  

## 属性
ファイルの属性(隠しファイル・読み取り専用など)による区別は行わない．  
どのファイルも，ほかのファイルと同じように表示・操作できる．  
Windowsが拒む，読み取り専用のファイルへの書き込みや削除も行える(Windowsが作る`System Volume Information`は`SYSTEM~1/`と表示される)．  

# ファイルの内容
内容は，バイト列をそのまま文字として出力する．  
文字コードの変換は行わない．  
内容の途中にある値0のバイトは出力しない．  
テキストファイルを想定しており，バイナリファイルの表示には対応しない．  

# 書き込みについて
時計を持たないため，作成・変更したファイル・ディレクトリの日時は，1980年1月1日0時0分(FATで表せる最も古い日時)になる．  

書き込みの途中で中断した場合(電源を切った場合など)の整合性は保証しない．  
壊れた記録は，パソコンのディスク検査で修復する．  

ファイルシステムが記録している空きの量は，Qosmosが書き込むと「不明」になる．  
パソコンは，次に差したときに数え直す([qosmos/kernel/filesystem.md](../kernel/filesystem.md)の「空きクラスタ数」を参照)．
