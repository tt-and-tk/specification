# 例外
CPUは，実行できない命令や不正な値(以下，例外と書く)を検出すると，その命令を実行せずに次のとおり処理を移す．  

|例外を検出した動作状態|動作|
|:-|:-|
|カーネルモード|CPUが停止する(「停止と復帰」を参照)．カーネルモードで動くOS自身の不具合として扱う|
|ユーザーモード|停止せずに，カーネルモードで例外ハンドラへ飛ぶ([qurge/cpu/mode.md](mode.md)の「ユーザーモードの例外」を参照)|

例外を起こした命令は，レジスタ・メモリのどちらへも書き込まない．  
メモリは停止・例外ハンドラへ飛ぶ処理・リセットのいずれでも初期化されないため，例外を検出する前の内容がそのまま残る．  

# 例外の種類
例外は次の5種類で，それぞれに番号を割り当てる．  
ユーザーモードで例外ハンドラへ飛ぶときは，この番号を例外の原因としてECAUSEへ書き込む([qurge/cpu/mode.md](mode.md)の「ユーザーモードの例外」を参照)．  

|番号|例外|検出する条件|
|:-|:-|:-|
|1|命令を取り出す番地が範囲外である|「命令を取り出す番地の条件」|
|2|不正な命令である|「命令の内容の条件」|
|3|カーネルモードでだけ許される操作を，ユーザーモードで行おうとした|「命令の内容の条件」|
|4|割り算の除数が0である|「レジスタの値の条件」|
|5|メモリを読み書きする番地が範囲外である|「レジスタの値の条件」|

# 命令を取り出す番地の条件
プログラムカウンタが次のいずれかに当たる番地から命令を取り出そうとした場合は，番号1の例外である(動作状態ごとの命令を取り出す場所は，[qurge/cpu/mode.md](mode.md)の「命令を取り出す場所」を参照)．  

- カーネルモードで，ROMに対応する範囲(ROMへ渡せる幅に収まる範囲．[qurge/rom.md](../rom.md)を参照)の外にある  
- カーネルモードで，ROMに対応する範囲にあるが，ROMに格納された命令数の範囲外である．ROMの最後の命令の次へ進んだ場合もこれに当たる  
- ユーザーモードで，命令の番地が領域の範囲外である．領域の末尾に置いた命令の次へ進んだ場合もこれに当たる(範囲は[qurge/cpu/mode.md](mode.md)の「番地の変換」を参照)  

# 命令の内容の条件
命令タイプ・func・レジスタ番地・immと，命令を実行する時点の動作状態から判定する条件である．  
レジスタの値は参照しない．  
次のいずれかに当たる命令は，番号2か3の例外である．  

- rs1・rs2・rdのいずれかが，レジスタ番地の上限(`6'h34`)を超えている  
- imm[32]が1のDIV・DIVUで，剰余の格納先(imm[31:0])がレジスタ番地の上限を超えている  
- m_typeが，どの命令タイプにも割り当てていない値である  
- funcが，その命令タイプに定義されていない値である(命令表に載っているBRM/BWMも，未実装のため定義されていない値として扱う)  
- immの使用が必須の命令でimm[32]が0である(使用が必須の命令は[qurge/cpu/isa.md](isa.md)の各命令の説明を参照)  
- 命令が読み出しに使うレジスタが読み込み不可である，または書き込みに使うレジスタが書き込み不可である．読み書きの可否は動作状態によって異なる([qurge/cpu/register.md](register.md)を参照)  
- ユーザーモードで，カーネルモードでだけ実行できる命令(SYSRET)を実行しようとした([qurge/cpu/mode.md](mode.md)を参照)  

## 番号2と番号3の区別
番号3の例外になるのは，次のどちらかだけに当たる命令である．  
それ以外の命令は，番号2の例外になる．  

- カーネルモードでは読み書きでき，ユーザーモードでは読み書きできないレジスタを使う  
- ユーザーモードでSYSRETを実行する  

## 判定に使う動作状態
命令の実行可否は，その命令を実行する時点の動作状態で判定する．  
動作状態を切り替える命令(SYSCALL・SYSRET)より後にある命令は，切り替えた後の動作状態で判定する．  

## 判定の対象とするオペランド
レジスタ番地の上限の条件と，レジスタの読み書きの可否の条件は，条件ごとに判定の対象とする範囲が異なる．  

- rs1・rs2・rdの番地の上限: 命令タイプによらず機械語中に必ず存在するフィールドであるため，その命令が実際には使わないフィールドも含めて判定する  
- 剰余の格納先の番地の上限と，読み書きの可否: その実行で実際に使うオペランドのみを判定する．イミディエイトデータの使用によって無視されるrs1・rs2，命令が使用しないrd，imm[32]が0のときのDIV・DIVUの剰余格納先は判定しない  

各命令に伴うPCの更新と，SYSCALLによるKENTRYの読み出し・KRETへの戻り先の書き込みは，オペランドとして指定した番地の読み書きではない．  
このため，読み込み不可・書き込み不可であっても判定の対象外である．  

# レジスタの値の条件
レジスタの値そのものに依存する条件である．  
例外の番号は条件ごとに示す．  

- DIV・DIVUの除数(rs2)が0である．番号4の例外である  
- メモリを読み書きする命令(M系・CALL・RET)の番地が，その命令が読み書きできる範囲の外にある．番号5の例外である  
    - 番地の求め方は[qurge/cpu/isa.md](isa.md)の各命令の説明を，命令と動作状態ごとの範囲は[qurge/cpu/mode.md](mode.md)の「メモリを読み書きできる範囲」を参照  
    - 空のスタックでの`RET`も，読み出す番地(SP)が範囲外になるため，これに当たる([qurge/cpu/stack.md](stack.md)の「空のスタック」を参照)  

# 停止と復帰
停止したCPUは，外部からCPUのリセットが入るまで実行を再開しない．  
停止した状態から自力で復帰する手段はない．  

停止と同時に，すべてのレジスタは初期値(各レジスタの初期値は[qurge/cpu/register.md](register.md)を参照)に戻され，停止した時点の値は残らない．  
動作状態もカーネルモードに戻る([qurge/cpu/mode.md](mode.md)を参照)．  
リセットを受けるとPCも0に戻っているため，プログラムの先頭から実行し直す．  
メインメモリの内容は，CPUのリセットでは初期化されず，停止前の値がそのまま残る([qurge/memory.md](../memory.md)を参照)．  

# 検出しない不正
次のものは不正な使い方だが，CPUは例外として検出せず，誤った動作のまま実行を続ける．  
プログラムを生成・記述する側で避ける必要がある．  

- DIVで32ビット符号あり整数の最小値(`-2147483648`)を`-1`で割る場合．商が32ビットで表現できないが，除算は実行され誤った値が格納される  
- 読み書きするバイト範囲(M系の命令ではmaskが対象とする範囲，CALL/RETでは戻り先の4バイト)が，4バイト境界に揃った同一ワード内に収まっていない([qurge/memory.md](../memory.md)を参照)  
- スタックが，プログラムが変数などに使う領域まで伸びる．CPUはスタックの領域の境界を持たないため検出せず，変数とスタック上の値が互いに上書きされる([qurge/cpu/stack.md](stack.md)の「深さの上限」を参照)
