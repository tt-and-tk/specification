# 割り込み
CPUは，一定時間ごとにユーザーモードの実行を止め，カーネルモードの割り込みハンドラへ処理を移すタイマー割り込みを持つ．ユーザーモードのプログラムがシステムコールを呼ばず，例外も起こさずに実行し続けても，OSが処理を取り戻せるようにするためである．  

# 設定
タイマー割り込みは，次の2つのレジスタで設定する．どちらもカーネルモードでだけ読み書きできる([qurge/cpu/register.md](register.md)を参照)．  

|レジスタ|設定する内容|
|:-|:-|
|IENTRY(`6'h17`)|割り込みハンドラの番地|
|TINTERVAL(`6'h18`)|タイマー割り込みの間隔(クロックのサイクル数)．0なら無効|

CPUのクロックは100MHzのため，1サイクルは10nsである．  

# 割り込みの要求
CPUは，TINTERVALが0以外の間，動作状態によらずクロックのサイクルを数え，TINTERVALのサイクル数が経つたびに割り込みを要求する．  

- 数え始め: TINTERVALへ書き込んだ時点と，割り込みを要求した時点から，0から数え直す．書き込んだ値が前と同じ場合も数え直す  
- 無効: TINTERVALが0の間は数えず，割り込みを要求しない．TINTERVALの初期値は0のため，リセット直後と停止した後は無効である  
- 保留: 要求は，受け付けるまで保留する．保留できる要求は1つだけで，受け付ける前に次の間隔が経っても，受け付けるのは1回である  
- 取り消し: TINTERVALへ書き込むと，保留している要求を取り消す．0を書き込んだ場合も，0以外の値を書き込んだ場合も取り消す  

数えたサイクル数と要求はレジスタの番地に割り当てておらず，命令で読み書きすることはできない．  

# 受け付ける時点
CPUは，次の条件がそろった時点で，保留している要求を受け付ける(受け付ける段は[qurge/cpu/pipeline.md](pipeline.md)の「メインメモリの命令」を参照)．  

- 動作状態がユーザーモードである  
- 前の命令がすべて完了している  
- 次の命令をまだ取り出していない  

このため，割り算やメモリの読み書きのように複数サイクルかかる命令の実行中に要求しても，その命令を完了させてから受け付ける．次に取り出す命令の番地が範囲外の場合([qurge/cpu/exception.md](exception.md)の「命令を取り出す番地の条件」を参照)も，例外より先に割り込みを受け付ける．  

カーネルモードの間は受け付けず，要求を保留する．OSの変数を，処理の途中で別のプロセスのための処理が書き換える問題を避けるためである．システムコールハンドラ・例外ハンドラ・割り込みハンドラの実行中に間隔が経った場合は，SYSRETでユーザーモードへ移ると，戻り先の命令を取り出す前にその要求を受け付ける．  

# 割り込みハンドラへ飛ぶ処理
要求を受け付けた時点で次に取り出そうとしていた命令を，割り込みで止めた命令と呼ぶ．要求を受け付けると，CPUは次の3つを同時に行う．この3つを行うことを，割り込みハンドラへ飛ぶと書く．  

1. 割り込みで止めた命令のPCを，KRET(`6'h12`)へ書き込む  
1. カーネルモードにして，IENTRYの値が示す番地(割り込みハンドラの番地)へ飛ぶ  
1. 保留している要求を下ろす  

割り込みハンドラへ飛んだ直後の状態は，次のとおりである．  

- 割り込みで止めた命令は，まだ取り出しも実行もしていない．それより前の命令の結果は，すべて残る  
- SPとほかのレジスタは，ユーザーモードのプログラムが使っていた値のままである(扱いは[qurge/cpu/mode.md](mode.md)の「カーネルモードへ入った直後」を参照)  
- ECAUSEは書き換わらず，最後に例外ハンドラへ飛んだときの例外の原因を表すまま保たれる  

割り込みハンドラはカーネルモードで実行するため，そこで例外を起こすとCPUが停止する．カーネルモードへ移るほかの方法との違いは，[qurge/cpu/mode.md](mode.md)の「動作状態の切り替え」を参照．  

## 専用のハンドラ
割り込みは，システムコール・例外と別のハンドラへ飛ぶことで，システムコール・例外と見分ける．入口を分けるのは，次の2つのためである．  

- 割り込みハンドラが，先頭で原因を調べて処理を分けずに済む  
- システムコールハンドラ・例外ハンドラも，割り込みかどうかを調べずに済む  

# 割り込みハンドラからの復帰
割り込みハンドラがKRETを変えずにSYSRETで戻ると，割り込みで止めた命令から実行する．このため，ユーザーモードのプログラムは止める前の続きから実行する．割り込みで止めた命令の番地が範囲外の場合は，戻った後にその命令を取り出そうとして例外を起こす．  

# 間隔の下限
OSは，割り込みハンドラにかかるサイクル数より十分大きい値をTINTERVALに設定する．割り込みハンドラへ飛んでからSYSRETで戻るまでのサイクル数がTINTERVAL以上だと，割り込みハンドラの実行中に次の間隔が経ち，戻った直後にまた割り込みハンドラへ飛ぶ．このため，ユーザーモードの命令が1つも進まなくなる．  
システムコールハンドラ・例外ハンドラから戻る場合も，その実行中に間隔が経っていれば，戻った直後に割り込みハンドラへ飛ぶ．
