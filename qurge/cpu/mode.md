# 動作状態
QurgeのCPUは，OSを動かすカーネルモードと，OSの状態を書き換えさせないプログラムを動かすユーザーモードの2つの動作状態を持つ．2つの動作状態の違いは次のとおりである．  

|項目|カーネルモード|ユーザーモード|
|:-|:-|:-|
|命令のオペランドとして読み書きできるレジスタ|[qurge/cpu/register.md](register.md)の読み書きの可否のとおり|次の3種類のレジスタを除く: OSが状態を持つもの・動作状態の切り替えに関わるもの・周辺機器のもの(「ユーザーモードでの制限」を参照)|
|動作状態を切り替える命令(「動作状態の切り替え」を参照)|SYSCALL・SYSRETとも実行できる|カーネルモードへ入るSYSCALLだけを実行でき，ユーザーモードへ戻るSYSRETは実行できない|
|命令を取り出す場所(「命令を取り出す場所」を参照)|ROM|OSが割り振ったメモリの領域|
|メモリを読み書きする番地|命令が指定した番地そのもの|命令が指定した番地を，領域の中の番地として変換した番地(「番地の変換」を参照)|
|メモリを読み書きできる範囲(「メモリを読み書きできる範囲」を参照)|M系の命令はメモリ全体，CALL/RETはカーネル用の範囲|M系の命令もCALL/RETも領域の中|
|例外を検出したとき([qurge/cpu/exception.md](exception.md)を参照)|CPUが停止する|カーネルモードへ移り，例外ハンドラへ飛ぶ([qurge/cpu/exception.md](exception.md)の「例外ハンドラへ飛ぶ処理」を参照)|
|タイマー割り込みが保留中のとき([qurge/cpu/timer-interrupt.md](timer-interrupt.md)を参照)|割り込みハンドラへ飛ばず，ユーザーモードへ移るまで保留中のままにする|実行中の命令を完了させた後，次の命令を取り出す前に，カーネルモードへ移り，割り込みハンドラへ飛ぶ|

動作状態はレジスタの番地に割り当てておらず，命令で直接読み書きすることはできない．  

# 命令を取り出す場所
カーネルモードでは，ROMの命令だけを実行し，メモリ上の命令は実行しない．PCはROMの先頭の命令を0として数え，PCがpの命令はROMの番地pに置く．CPUがROMから命令を取り出せるのは，PCが次の両方を満たす場合だけである．満たさない場合は，例外を起こす．  

- ROMの受け取る幅([qurge/rom.md](../rom.md)の「容量と命令数の上限」を参照)に収まる(`0x0000`〜`0x3FFF`)．`0x4000`以上のPCは，上位のビットを捨てて折り返さない  
- ROMに格納した命令数より小さい  

ROMの最後の命令の次へ進んだ場合は，2つ目の条件を満たさない(例外の条件は[qurge/cpu/exception.md](exception.md)の「命令を取り出す番地の条件」を参照)．  

ユーザーモードでは，OSが割り振ったメモリの領域の中に置いた命令を実行し，ROMから命令を取り出さない．PCは領域の先頭の命令を0として数え，PCがpの命令は領域の中の番地p×8に置く(「番地の変換」を参照)．このため，領域を置く位置によらず同じプログラムを実行できる．1命令の中のバイトの並び方は，[qurge/cpu/isa.md](isa.md)の「基本構成」を参照．  

命令は，M系の命令で領域へ書き込めば置ける(命令を置くための専用の書き込み方法はない)．命令以外の値も置けるため，命令列の後ろにデータを置いてもよい．領域には，ROMに格納した命令数のような区切りがない．PCが領域の中を指していれば，その位置の内容を，命令として書き込んだものかどうかによらず実行する．  

# メモリを読み書きできる範囲
メモリの`0x00000`〜`0x07FFF`の32768バイトを，カーネル用の範囲と呼ぶ．カーネル用の範囲は，カーネルモードのプログラムが変数とスタックを置く範囲である．  

命令がメモリを読み書きできる範囲は，命令と動作状態によって次のとおり異なる．範囲の外の番地を読み書きしようとすると，例外を起こす([qurge/cpu/exception.md](exception.md)の「レジスタの値の条件」を参照)．  

|命令|カーネルモード|ユーザーモード|
|:-|:-|:-|
|M系の命令|メモリ全体．容量外の番地([qurge/memory.md](../memory.md)を参照)が範囲外にあたる|領域の中(「番地の変換」を参照)|
|CALL/RETが戻り先を積み下ろしするスタックの番地(CALLはSP−4，RETはSP)|カーネル用の範囲．カーネル用の範囲の外の番地は，容量内でも範囲外にあたる|領域の中|

カーネルモードのスタックは，カーネル用の範囲の末尾から番地の小さい方へ伸びる(スタックの一般則は[qurge/cpu/stack.md](stack.md)を参照)．SPのリセット時の初期値`0x8000`([qurge/cpu/register.md](register.md)を参照)は，カーネルモードの空のスタックにあたり，カーネル用の範囲の末尾の直後の番地を指す．このため，カーネルモードの空のスタックでの`RET`は，読み出す番地(SP)がカーネル用の範囲の外になり，範囲外にあたる．  
カーネル用の範囲の外も，M系の命令では通常どおり読み書きできる．SPからの相対位置をRMR/WMRで読み書きする場合も，M系の命令としてメモリ全体を読み書きできる．  

カーネル用の範囲の大きさは，メモリの容量([qurge/memory.md](../memory.md)を参照)によらず決まっている．大きさは2のべき乗とする．番地がカーネル用の範囲に収まるかを，番地のビット幅で判定するためである．大きさを変える場合は，次のものも合わせて変える．  

- SPのリセット時の初期値([qurge/cpu/register.md](register.md)を参照)  
- コンパイラのROM用の検査に使う値([pynesis/compiler/check.md](../../pynesis/compiler/check.md)の「検査に使う値」を参照)  
- Qosmosのプロセス用の範囲と，そこから決まる値([qosmos/kernel/memory.md](../../qosmos/kernel/memory.md)の「メモリの容量やカーネル用の範囲の大きさを変える場合」を参照)  

# 動作状態の切り替え
リセット直後と停止中はカーネルモードである(停止の扱いは[qurge/cpu/exception.md](exception.md)を参照)．実行を続けながら動作状態を切り替える方法は，次の4つである．  

|方法|起きる動作状態|切り替える先|KRET(`6'h12`)|飛び先|
|:-|:-|:-|:-|:-|
|SYSCALLの実行|両方|カーネルモード|次の命令のPC(SYSCALLのPC+1)を書き込む|KENTRY(`6'h11`)の値が示す番地(システムコールハンドラ)|
|例外の検出([qurge/cpu/exception.md](exception.md)の「例外ハンドラへ飛ぶ処理」を参照)|ユーザーモード|カーネルモード|例外を起こした命令のPCを書き込む|EENTRY(`6'h15`)の値が示す番地(例外ハンドラ)|
|タイマー割り込み([qurge/cpu/timer-interrupt.md](timer-interrupt.md)の「割り込みハンドラへ飛ぶ処理」を参照)|ユーザーモード|カーネルモード|割り込みで止めた命令(次に取り出すはずだった命令)のPCを書き込む|IENTRY(`6'h17`)の値が示す番地(割り込みハンドラ)|
|SYSRETの実行|カーネルモード|ユーザーモード|書き込まない|KRETの値が示す番地|

カーネルモードへ移る3つの方法では，CPUがKRETへの書き込み・カーネルモードへの切り替え・飛び先への移動を同時に行う．3つの方法は，それぞれ別のハンドラへ飛ぶ．OSは，飛び先のハンドラによって，カーネルモードへ移った方法を見分ける．ハンドラを分けるのは，各ハンドラが先頭で原因を調べて処理を分けずに済むためである．  
SYSCALL・SYSRETの機械語は，[qurge/cpu/isa.md](isa.md)の「ジャンプ系(J系)」を参照．表のレジスタの内容は[qurge/cpu/register.md](register.md)を参照．表のレジスタの初期値は，いずれも0である．  
カーネルモードでSYSCALLを実行した場合もKRETを上書きする．SYSRETで戻る先を保ちたい場合は，SYSCALLの前にKRETの値を退避しておく．  

## ユーザーモードへ移る前の設定
ユーザーモードでプログラムを始めるときも，SYSRETで移る．OSは，SYSRETでユーザーモードへ移る前に，次のレジスタを設定しておく．  

- UBASE・USIZE: プログラムの領域(「番地の変換」を参照)  
- KRET: プログラムの先頭の命令のPC(ユーザーモードのPCの数え方は「番地の変換」を参照)  
- SP: 領域の中のスタックを指す値．何も積んでいなければUSIZE  
- KENTRY: ユーザーモードのプログラムが実行するSYSCALLの飛び先となる，システムコールハンドラの番地  
- EENTRY: 例外ハンドラの番地([qurge/cpu/exception.md](exception.md)の「例外ハンドラへ飛ぶ処理」を参照)  
- IENTRY: 割り込みハンドラの番地([qurge/cpu/timer-interrupt.md](timer-interrupt.md)を参照)  
- TINTERVAL: 割り込み周期．0ならタイマー割り込みは起きない([qurge/cpu/timer-interrupt.md](timer-interrupt.md)を参照)  

KRETを書き込まずにSYSRETを実行すると，KRETに残っていたPC(初期値なら0)の命令を取り出そうとする．USIZEを設定していれば，その命令を意図せずユーザーモードで実行してしまう．USIZEが初期値の0のままなら，最初の命令の取り出しで例外を起こす．  
カーネルモードのSPのままユーザーモードへ移ると，CALLはその値を領域の中の番地とみなして戻り先を積む．その番地が範囲外なら例外を起こし，範囲内なら領域の意図しない位置を書き換えてしまう．  
KENTRY・EENTRY・IENTRYのどれかを書き込まずにユーザーモードへ移ると，CPUはそのハンドラへ飛ぶときに初期値の0番地へ飛ぶ．飛ぶのは，KENTRYならSYSCALLを実行したとき，EENTRYなら例外を検出したとき，IENTRYならTINTERVALが0以外で，割り込みハンドラへ飛ぶときである．カーネルモードの0番地はROMの先頭の命令のため，レジスタとメモリを残したまま，OSを先頭から実行し直してしまう．  

## カーネルモードへ入った直後
ユーザーモードからカーネルモードへ移った直後は，CPUが書き込んだレジスタ(KRETと，例外の場合のECAUSE)を除き，SPとほかのレジスタはユーザーモードのプログラムが使っていた値のままである．動作状態を切り替えても，レジスタは切り替わらないためである．ユーザーモードのプログラムが使っていたレジスタの退避は，OSが行う．  

SPは，領域の中の番地のままである．カーネルモードでは番地を変換しないため，このSPのままスタックを使うと，SPの値が指すメモリの番地を読み書きする．その番地は，ユーザーモードでSPが指していた位置(UBASEを足した番地)とは別の位置である．使う命令ごとに次のようになる．  

- M系の命令でSPからの相対位置を読み書きする場合: その別の位置を読み書きする．ほかのプログラムの領域に当たることもある  
- CALL/RET: 戻り先を積み下ろしする番地(CALLはSP−4，RETはSP)がカーネル用の範囲の外なら，範囲外としてCPUが停止する．範囲の中なら，カーネルの変数やスタックの位置を読み書きする  

OSは，カーネルモードのスタックを指すようSPを書き換えるまで，CALLとスタックの読み書きを行わない．  

## SYSRETで戻った後に実行する命令
カーネルモードへ移った後にSYSRETで戻ると，KRETへ書き込んだPCの命令から実行する．このため，戻った後に実行する命令は，カーネルモードへ移った方法によって次のとおり異なる．SYSRETの前にKRETへ別のPCを書き込んだ場合は，そのPCの命令から実行する．  

|カーネルモードへ移った方法|戻った後に実行する命令|
|:-|:-|
|SYSCALL|SYSCALLの次の命令|
|例外|例外を起こした命令．同じ命令をもう一度実行する|
|タイマー割り込み|割り込みで止めた命令．この命令はまだ実行していないため，止める前の続きから実行する|


# 番地の変換
ユーザーモードでは，命令の取り出しとメモリの読み書きに使う番地を，OSが割り振ったメモリの領域の中の番地として扱う．領域は，先頭の番地をUBASE(`6'h13`)に，大きさをUSIZE(`6'h14`)に書き込んで決める([qurge/cpu/register.md](register.md)を参照)．カーネルモードでは番地を変換せず，メモリの番地をそのまま使う．ユーザーモードでの番地とPCの扱いは，次のとおりである．  

- 領域の中の番地は，領域の先頭を0とするバイト単位の番地である．メモリの番地は，領域の中の番地にUBASEを足して求める  
- PCは，領域の先頭の命令を0として数える．PCがpの命令は，領域の中の番地p×8に置く(「命令を取り出す場所」を参照)  
- JMP/CALLの飛び先，CALL/RETが積み下ろしする戻り先，カーネルモードへ移るときにKRETへ書き込むPC(「動作状態の切り替え」を参照)，PCを読み出した値は，いずれもこの数え方のPCである  
- SPは領域の中の番地として使い，SP=USIZEが空のスタックになる  
- M系の命令が読み書きする番地と，CALL/RETが戻り先を積み下ろしするスタックの番地(CALLはSP−4，RETはSP)は，いずれも領域の中の番地である  

UBASE・USIZEへ書き込んだ値は，下位3ビットと，メモリの番地・容量を表せる幅より上のビットが0になる([qurge/cpu/register.md](register.md)を参照)．このため，メモリの容量以上の値をUBASEへ書き込んでも例外にはならず，上位のビットを捨てた番地が領域の先頭になる．UBASEが8の倍数のため，領域の中の番地を変換しても，8で割った余りは変わらない．このため，8の倍数に揃う番地は次のとおり変換後も揃う．  

- 命令(8バイト)は，領域の中の8の倍数の番地(PCに8を掛けた番地)に置く．変換後のメモリの番地も8の倍数になる  
- 4バイト境界に揃えた読み書きの番地は，変換後のメモリの番地でも4バイト境界に揃う．読み書きの範囲がワードをまたがない条件は，[qurge/memory.md](../memory.md)を参照  

USIZEも8の倍数のため，領域は8バイトの命令をちょうど整数個収める大きさになる．  

次のいずれかに当たる番地は範囲外である．範囲外の番地から命令を取り出そうとした場合と，範囲外の番地を読み書きしようとした場合は，例外を起こす(例外の条件は[qurge/cpu/exception.md](exception.md)，そのときの動作は[qurge/cpu/exception.md](exception.md)の「例外ハンドラへ飛ぶ処理」を参照)．  

- 領域の中の番地が，USIZE以上である(32ビットの番地全体で比べるため，負の値を足して折り返した番地もこれに当たる)  
- 命令を取り出す場合に，PC×8が32ビットに収まらない  
- 領域の中の番地に，UBASEに残っている値を足した番地が，メモリの容量以上になる  

# ユーザーモードでの制限
ユーザーモードでは，次の3種類のレジスタを，命令のオペランドとして読み書きできない．OSが状態を持つもの・動作状態の切り替えに関わるもの・周辺機器のものである(対象のレジスタは[qurge/cpu/register.md](register.md)の「ユーザーモードでの制限」を参照)．  

ユーザーモードでは，SYSRETを実行できない．3種類のレジスタを命令のオペランドに使う場合と，SYSRETを実行しようとする場合は，例外を起こす(例外の条件は[qurge/cpu/exception.md](exception.md)の「命令の内容の条件」，そのときの動作は[qurge/cpu/exception.md](exception.md)の「例外ハンドラへ飛ぶ処理」を参照)．  

SYSCALLは，ユーザーモードでは読み書きできないKENTRYとKRETを使う(飛び先をKENTRYから読み，戻り先をKRETへ書き込む)．ただし，この読み書きは命令のオペランドとしての読み書きではないため制限の対象外であり，SYSCALLはユーザーモードでも実行できる．
