# 動作状態
QurgeのCPUは，OSを動かすカーネルモードと，OSの状態を書き換えさせないプログラムを動かすユーザーモードの2つの動作状態を持つ．2つの動作状態の違いは次のとおりである．  

|項目|カーネルモード|ユーザーモード|
|:-|:-|:-|
|命令のオペランドとして読み書きできるレジスタ|[qurge/cpu/register.md](register.md)の読み書きの可否のとおり|次の3種類のレジスタを除く: OSが状態を持つもの・動作状態の切り替えに関わるもの・周辺機器のもの(「ユーザーモードでの制限」を参照)|
|動作状態を切り替える命令(「動作状態の切り替え」を参照)|SYSCALL・SYSRETとも実行できる|カーネルモードへ入るSYSCALLだけを実行でき，ユーザーモードへ戻るSYSRETは実行できない|
|命令を取り出す場所(「命令を取り出す場所」を参照)|ROM|OSが割り振ったメモリの領域|
|メモリを読み書きする番地|命令が指定した番地そのもの|命令が指定した番地を，領域の中の番地として変換した番地(「番地の変換」を参照)|
|メモリを読み書きできる範囲(「メモリを読み書きできる範囲」を参照)|M系の命令はメモリ全体，CALL/RETはメモリの前半|M系の命令もCALL/RETも領域の中|
|例外を検出したとき([qurge/cpu/exception.md](exception.md)を参照)|CPUが停止する|カーネルモードで例外ハンドラへ飛ぶ(「ユーザーモードの例外」を参照)|

動作状態はレジスタの番地に割り当てておらず，命令で直接読み書きすることはできない．  

# 命令を取り出す場所
カーネルモードでは，ROMの命令だけを実行し，メモリ上の命令は実行しない．PCがROMに対応する範囲とその外の扱いは，[qurge/rom.md](../rom.md)を参照．  

ユーザーモードでは，OSが割り振ったメモリの領域の中に置いた命令を実行し，ROMから命令を取り出さない．PCは領域の先頭の命令を0として数え，PCがpの命令は領域の中の番地p×8に置く(「番地の変換」を参照)．このため，領域を置く位置によらず同じプログラムを実行できる．1命令の中のバイトの並び方は，[qurge/cpu/isa.md](isa.md)の「基本構成」を参照．  

命令は，M系の命令で領域へ書き込めば置ける(命令を置くための専用の書き込み方法はない)．命令以外の値も置けるため，命令列の後ろにデータを置いてもよい．  
ROMでは，格納した命令数より先の番地の命令を実行できない([qurge/cpu/exception.md](exception.md)を参照)．領域にはこの区切りがなく，PCが領域の中を指していれば，その位置の内容を，命令として書き込んだものかどうかによらず実行する．  

# メモリを読み書きできる範囲
メモリの番地を容量の半分の番地で2つに分け，小さい側をメモリの前半，大きい側をメモリの後半と呼ぶ．現在の容量(64KB．[qurge/memory.md](../memory.md)を参照)では，前半は`0x0000`〜`0x7FFF`，後半は`0x8000`〜`0xFFFF`である．  

命令がメモリを読み書きできる範囲は，命令と動作状態によって次のとおり異なる．範囲の外の番地を読み書きしようとすると，例外を起こす([qurge/cpu/exception.md](exception.md)の「レジスタの値の条件」を参照)．  

|命令|カーネルモード|ユーザーモード|
|:-|:-|:-|
|M系の命令|メモリ全体．容量外の番地([qurge/memory.md](../memory.md)を参照)が範囲外にあたる|領域の中(「番地の変換」を参照)|
|CALL/RETが戻り先を積み下ろしするスタックの番地(CALLはSP−4，RETはSP)|メモリの前半．メモリの後半に入る番地も範囲外にあたる|領域の中|

カーネルモードのスタックは，メモリの前半の末尾から番地の小さい方へ伸びる(スタックの一般則は[qurge/cpu/stack.md](stack.md)を参照)．SPのリセット時の初期値`0x8000`([qurge/cpu/register.md](register.md)を参照)は，カーネルモードの空のスタックにあたり，前半の末尾のすぐ上の番地(メモリの後半の先頭)を指す．このため，カーネルモードの空のスタックでの`RET`は，読み出す番地(SP)がメモリの後半に入り，範囲外にあたる．  
メモリの後半も，M系の命令では通常どおり読み書きできる．SPからの相対位置をRMR/WMRで読み書きする場合も，M系の命令としてメモリ全体を読み書きできる．  

# 動作状態の切り替え
リセット直後と停止中はカーネルモードである(停止の扱いは[qurge/cpu/exception.md](exception.md)を参照)．  
実行を続けながら動作状態を切り替えるのは，次の2つの命令と，ユーザーモードで例外ハンドラへ飛ぶ処理(「ユーザーモードの例外」を参照)である．2つの命令の機械語は[qurge/cpu/isa.md](isa.md)の「ジャンプ系(J系)」を参照．  

|命令|動作|実行できる動作状態|
|:-|:-|:-|
|SYSCALL|次の命令のPC(SYSCALLのPC+1)をKRET(`6'h12`)へ書き込み，カーネルモードにして，KENTRY(`6'h11`)の値が示す番地へ飛ぶ|両方|
|SYSRET|ユーザーモードにして，KRETの値が示す番地へ飛ぶ|カーネルモードのみ|

KENTRY・KRETの内容は[qurge/cpu/register.md](register.md)を参照．使う側は次の点に注意する．  

- KENTRY・KRET・UBASE・USIZE・EENTRYの初期値は0である  
- ユーザーモードでプログラムを始めるときも，SYSRETで移る．SYSRETの前に，領域(UBASE・USIZE)を設定し，プログラムの先頭の命令のPCをKRETへ書き込んでおく(ユーザーモードのPCの数え方は「番地の変換」を参照)．KRETを書き込まずにSYSRETを実行すると，KRETに残っていたPC(初期値なら0)の命令を取り出そうとする．USIZEを設定していれば，その命令を意図せずユーザーモードで実行してしまう．USIZEが初期値の0のままなら，最初の命令の取り出しで例外を起こす  
- SYSRETの前に，SPを領域の中のスタックを指す値(何も積んでいなければUSIZE)にしておく．カーネルモードのSPのままユーザーモードへ移ると，CALLはその値を領域の中の番地とみなして戻り先を積む．その番地が範囲外なら例外を起こし，範囲内なら領域の意図しない位置を書き換えてしまう  
- ユーザーモードのプログラムが実行するSYSCALLは，KENTRYが示す番地へカーネルモードで飛ぶ．OSは，ユーザーモードへ移る前にKENTRYへシステムコールハンドラの番地を書き込んでおく．書き込まずにユーザーモードへ移ると，SYSCALLはKENTRYの初期値の0番地へ飛んでしまう  
- カーネルモードでSYSCALLを実行した場合もKRETを上書きする．SYSRETで戻る先を保ちたい場合は，SYSCALLの前にKRETの値を退避しておく  
- SYSCALLとSYSRETは，SPやほかのレジスタを切り替えない．ユーザーモードのプログラムが使っていたレジスタの退避は，OSが行う  
- SYSCALLで入った直後のSPは，ユーザーモードのプログラムが使っていた領域の中の番地のままである．カーネルモードでは番地を変換しないため，そのままCALLやスタックの読み書きに使うと，メモリの同じ番地(領域の外)を読み書きしてしまう．OSは，カーネルモードのスタックを指すようSPを書き換えるまで，CALLとスタックの読み書きを行わない  

# 番地の変換
ユーザーモードでは，命令の取り出しとメモリの読み書きに使う番地を，OSが割り振ったメモリの領域の中の番地として扱う．領域は，先頭の番地をUBASE(`6'h13`)に，大きさをUSIZE(`6'h14`)に書き込んで決める([qurge/cpu/register.md](register.md)を参照)．カーネルモードでは番地を変換せず，メモリの番地をそのまま使う．  

- 領域の中の番地は，領域の先頭を0とするバイト単位の番地である．メモリの番地は，領域の中の番地にUBASEを足して求める  
- PCは，領域の先頭の命令を0として数える．PCがpの命令は，領域の中の番地p×8に置く(「命令を取り出す場所」を参照)  
- JMP/CALLの飛び先，CALL/RETが積み下ろしする戻り先，SYSCALLがKRETへ書き込む戻り先，例外ハンドラへ飛ぶときにKRETへ書き込むPC(例外を起こした命令のPC)，PCを読み出した値は，いずれもこの数え方のPCである  
- SPは領域の中の番地として使い，SP=USIZEが空のスタックになる  
- M系の命令が読み書きする番地と，CALL/RETが戻り先を積み下ろしするスタックの番地(CALLはSP−4，RETはSP)は，いずれも領域の中の番地である  

UBASE・USIZEへ書き込んだ値は，下位3ビットと，メモリの番地・容量を表せる幅より上のビットが0になる([qurge/cpu/register.md](register.md)を参照)．このため，メモリの容量以上の値をUBASEへ書き込んでも例外にはならず，上位のビットを捨てた番地が領域の先頭になる．  
UBASEが8の倍数のため，領域の中の番地を変換しても，8で割った余りは変わらない．このため，8の倍数に揃う番地は次のとおり変換後も揃う．  

- 命令(8バイト)は，領域の中の8の倍数の番地(PCに8を掛けた番地)に置く．変換後のメモリの番地も8の倍数になる  
- 4バイト境界に揃えた読み書きの番地は，変換後のメモリの番地でも4バイト境界に揃う．読み書きの範囲がワードをまたがない条件は，[qurge/memory.md](../memory.md)を参照  

USIZEも8の倍数のため，領域は8バイトの命令をちょうど整数個収める大きさになる．  

次のいずれかに当たる番地は範囲外である．範囲外の番地から命令を取り出そうとした場合と，範囲外の番地を読み書きしようとした場合は，例外を起こす(例外の条件は[qurge/cpu/exception.md](exception.md)，そのときの動作は「ユーザーモードの例外」を参照)．  

- 領域の中の番地が，USIZE以上である(32ビットの番地全体で比べるため，負の値を足して折り返した番地もこれに当たる)  
- 命令を取り出す場合に，PC×8が32ビットに収まらない  
- 領域の中の番地に，UBASEに残っている値を足した番地が，メモリの容量以上になる  

# ユーザーモードでの制限
ユーザーモードでは，次の3種類のレジスタを，命令のオペランドとして読み書きできない．OSが状態を持つもの・動作状態の切り替えに関わるもの・周辺機器のものである(対象のレジスタは[qurge/cpu/register.md](register.md)の「ユーザーモードでの制限」を参照)．  

ユーザーモードで実行したSYSCALLも，飛び先をKENTRYから読み，戻り先をKRETへ書き込むが，オペランドとしての読み書きではないため，この制限を受けない．  
ユーザーモードでは，SYSRETも実行できない．  
これらのレジスタを命令のオペランドに使う場合と，SYSRETを実行しようとする場合は，例外を起こす(例外の条件は[qurge/cpu/exception.md](exception.md)の「命令の内容の条件」，そのときの動作は「ユーザーモードの例外」を参照)．  

# ユーザーモードの例外
ユーザーモードで例外([qurge/cpu/exception.md](exception.md)を参照)を検出すると，CPUは停止せずに次の3つを同時に行う．この3つを行うことを，例外ハンドラへ飛ぶと書く．  

1. 例外を起こした命令のPCを，KRET(`6'h12`)へ書き込む．命令を取り出す番地が範囲外の場合は，取り出そうとした命令のPCを書き込む  
1. 例外の番号([qurge/cpu/exception.md](exception.md)の「例外の種類」を参照)を，例外の原因としてECAUSE(`6'h16`)へ書き込む  
1. カーネルモードにして，EENTRY(`6'h15`)の値が示す番地(例外ハンドラの番地)へ飛ぶ  

KRET・ECAUSE・EENTRYの内容は[qurge/cpu/register.md](register.md)を参照．例外を起こした命令は，レジスタ・メモリのどちらへも書き込まない．それより前の命令の結果は，すべて残る．  

ECAUSEの初期値の0は，リセットしてからまだ例外ハンドラへ飛んでいないことを表す．  

使う側は次の点に注意する．  

- 例外ハンドラの番地(EENTRY)は，システムコールハンドラの番地(KENTRY)とは別である．OSは，ユーザーモードへ移る前にEENTRYへ例外ハンドラの番地を書き込んでおく．書き込まずにユーザーモードへ移ると，例外ハンドラへ飛ぶときにEENTRYの初期値の0番地へ飛ぶ．カーネルモードの0番地はROMの先頭の命令のため，レジスタとメモリを残したまま，OSを先頭から実行し直してしまう  
- KRETへ書き込むのは，SYSCALLと異なり，例外を起こした命令自身のPCである．そのままSYSRETで戻ると，同じ命令をもう一度実行する  
- ECAUSEは例外ハンドラへ飛ぶときにだけ書き換わり，次に例外ハンドラへ飛ぶまで値を保つ．SYSCALLとSYSRETは書き換えない  
- 例外ハンドラへ飛んだ直後のSPとほかのレジスタは，SYSCALLで入った直後と同じく，ユーザーモードのプログラムが使っていた値のままである．OSは，カーネルモードのスタックを指すようSPを書き換えるまで，CALLとスタックの読み書きを行わない(「動作状態の切り替え」の注意を参照)  
- 例外ハンドラはカーネルモードで実行するため，そこで例外を起こすとCPUが停止する
