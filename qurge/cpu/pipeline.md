# パイプライン
QurgeのCPUは，命令の処理を複数の段に分け，各段で別々の命令を同時に処理する(パイプライン)．  
パイプラインは実行にかかるサイクル数だけを変え，プログラムの実行結果は命令を1つずつ順に実行した場合と同じになる．  

# 段の構成
命令は次の4段を順に進む．ROMの命令は，各段が1サイクルで次の段へ命令を渡し，各段で別々の命令を同時に処理する．ただし，実行段が複数サイクルかかる命令を実行している間は，確認段の命令を待たせる．  
メインメモリの命令は，段を重ねずに1命令ずつ処理する(「メインメモリの命令」を参照)．「例外の判定」はROMとメインメモリの命令に共通する．それ以外の見出しは，段を重ねて処理するROMの命令についての説明である．  

|段|処理|
|:-|:-|
|取得段|PCが指す命令を，ROMかメインメモリから読み出す．ROMからは，偶数番地とその次の奇数番地の2命令をまとめて読み出す([qurge/rom.md](../rom.md)を参照)|
|取り込み段|取得した命令を，命令キュー(取得した命令を実行段へ渡すまでためておく入れ物)の末尾へ入れる|
|確認段|命令キューの先頭の命令が実行できるかを判定し(「例外の判定」を参照)，オペランドのレジスタを読み出して実行段へ渡す|
|実行段|命令を実行する．レジスタの値に基づく例外の判定(「例外の判定」を参照)もここで行う|

分岐・ジャンプ，複数サイクルかかる命令，「前の命令の結果の受け渡し」で述べる待ちがなければ，毎サイクル1命令以上の実行が終わる．  

# 例外の判定
例外の条件([qurge/cpu/exception.md](exception.md)を参照)は，判定に要る情報がそろう段で判定する．  

|例外の条件|判定する段|判定する時点|
|:-|:-|:-|
|命令を取り出す番地の条件のうち，ROMに対応する範囲の外とユーザーモードの領域の外|取得段|前の命令がすべて完了してパイプラインが空になった時点|
|命令を取り出す番地の条件のうち，ROMに対応する範囲の中で格納した命令数を超えた番地|確認段|その番地から取り出した命令を実行段へ渡す時点|
|命令の内容の条件|確認段|命令キューの先頭の命令を実行段へ渡す時点．レジスタの値を読む前に，命令と動作状態だけで判定する|
|レジスタの値の条件|実行段|命令を実行する時点．レジスタの値が確定するのが実行段であるため|

# 前の命令の結果の受け渡し
前の命令の結果は，レジスタへの書き込みを待たずに次の命令へ渡す(フォワーディング)．  
このため，結果を使う命令を直後に置いても，間に別の命令を挟む必要はない．  

ただし，読み書きの両方ができ，書き込んだ値の一部のビットだけが反映されるレジスタ(以下，一部だけ反映されるレジスタと書く．外部ピンの値や周辺機器の状態を毎サイクル取り込むビットを持つレジスタと，0固定のビットを持つUBASE・USIZEが当たる．[qurge/cpu/register.md](register.md)を参照)については，前の命令が書き込む値を次の命令へ渡さない．書き込む値と書き込んだ後に読み出せる値が異なるためである．  
一部だけ反映されるレジスタを読む命令は，前の命令の結果がそのレジスタへ書き込み終わるまで実行段へ渡さずに待つ．  

# 分岐・ジャンプ
取得段は，分岐・ジャンプの後も次の番地の命令を取得し続ける．J系の命令と成立したF系の命令は，それより後に取得した命令を捨て，飛び先から取得し直す．飛び先が次の番地であっても取得し直す．捨てた命令は実行しない．  

取得し直す時点は，命令によって次のとおり異なる．  

- ROMにある，飛び先をイミディエイトデータで指定したJMP・CALL: ROMから取得した時点．飛び先が命令だけから分かるため，他の分岐・ジャンプより取得し直しによる待ちが短い  
- それ以外のJ系の命令と，成立したF系の命令: 実行段で完了した時点  
- 成立しなかったF系の命令: 取得し直さず，取得していた次の番地からの命令をそのまま実行する  

# メインメモリの命令
メインメモリの命令(ユーザーモードの命令．カーネルモードの命令はすべてROMから取得する)は，それより前の命令がすべて完了してから取得を始め，4段を1命令ずつ順に進む([qurge/cpu/mode.md](mode.md)の「命令を取り出す場所」を参照)．  
前の命令の種類によらず，単純な演算の後でも完了を待つ．  
取得する命令が前の命令の影響を受ける場合が次のとおりあり，前の命令がそれに当たるかを調べずに，一律に待つためである．  

- 前の命令がメインメモリを読み出す場合: 前の命令の読み出しと命令の取得とが取り合いになる．メインメモリの読み出しは1回に1つしか行えない  
- 前の命令が分岐・ジャンプで行き先を変える場合: 取得する命令の番地が，前の命令が完了するまで決まらない  
- 前の命令がメインメモリへ命令を書き込む場合: 書き込み終える前に取得すると，書き込む前の内容を取得してしまう．完了を待つため，書き込んだ後の内容で実行される  

ユーザーモードの命令は1命令ずつ進むため，例外を起こした命令([qurge/cpu/mode.md](mode.md)の「ユーザーモードの例外」を参照)より後の命令は，まだ取得していない．このため，例外ハンドラへ飛ぶときに取り消す命令はなく，例外ハンドラから取得し直すだけでよい．  

段を重ねないため，単純な命令でも1命令ごとに4段ぶん以上のサイクルがかかる．さらに，段ごとに以下のサイクルが加わる．  

- 取得段: すべての命令で，メモリの応答を待つサイクルが加わる．64ビットの命令を，メモリから32ビットずつ2回に分けて読み出すためである  
- 実行段: ユーザーモードでメモリを読み書きする命令(M系・CALL・RET)で，1サイクルが加わる．番地の変換と範囲の判定([qurge/cpu/mode.md](mode.md)の「番地の変換」を参照)を終えてから，その後のサイクルにメモリへ読み書きを要求するためである  

# 同時実行
確認段と実行段は2本ずつあり，命令キューの先頭の命令(以下，先頭)とその次の命令(以下，2番目)が次の条件をすべて満たすとき，2命令を同じサイクルに実行段へ渡す(以下，同時実行と書く)．  

- 先頭と2番目がどちらも，確認段で実行できると判定される．2番目が実行できない場合は同時実行せず，2番目は先頭の後に単独で判定を受ける  
- 2番目が単純な演算である．単純な演算は，1サイクルで完了しレジスタへ書き込む以外の動作を持たない命令であり，複数サイクルかかる掛け算・割り算を除いたP系，S系，A系が当たる  
- 先頭がF系・J系の命令ではない．先頭で行き先が変わると，2番目は実行してはならない命令になるため  
- 2番目が読むレジスタに，先頭が書き込まない．2番目は先頭の完了を待たずに演算し，先頭の結果を受け取れないためである  
- 2番目の書き込み先が，先頭が書き込むレジスタと異なる  
- 2番目が，一部だけ反映されるレジスタを読まない．書き込みが終わるまで待たせる判定(「前の命令の結果の受け渡し」を参照)を，先頭に対してだけ行うため  

これらの条件の「2番目が読むレジスタ」は，2番目が演算に実際に使うものだけを指す．NOTのrs2のように命令が使わないものや，イミディエイトデータを使うため無視されるrs1・rs2は含まない．  
「先頭が書き込むレジスタ」は，rdと，割り算の剰余の格納先を指す．  

同時実行した2番目は先頭の命令が完了するサイクルに完了し，その結果を次のサイクルにレジスタへ書き込む．先頭が複数サイクルかかる命令であれば，2番目は先頭が完了するまで完了しない．  
完了したサイクルに書き込まないのは，2番目の演算結果を，先頭の結果と同じサイクルのうちに全レジスタへ届けられないためである．書き込みを待つ間に後の命令が2番目の結果を使う場合も，「前の命令の結果の受け渡し」のとおり結果を受け取るか，書き込みが終わるまで待つ．  
先頭の命令でCPUが停止した場合は，2番目の結果を書き込まない．  

同時実行の条件を満たす命令が続く区間では，1サイクルに2命令の実行が終わる．
