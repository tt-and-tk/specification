# スタック
CALL/RETは，関数の戻り先をメモリ上のスタックへ積み下ろしする(命令の動作は[qurge/cpu/isa.md](isa.md)の「ジャンプ系(J系)」を参照)．  
スタック専用の領域は設けず，SP(`6'h10`．[qurge/cpu/register.md](register.md)を参照)が指す番地から番地の小さい方へ伸ばす．  

# 積み方
スタックへの積み下ろしは，次のとおり行う．  

- スタックは番地の小さい方へ4バイト単位で伸びる  
- SPは，最後に積んだ値の番地を指す．何も積んでいない場合は，スタックに使う範囲の末尾のすぐ上の番地を指す(「空のスタック」を参照)  
- CALLは，戻り先をSP-4番地へ書き込んでからSPを4減らす  
- RETは，SP番地から戻り先を読み出してからSPを4増やす  

CALL/RETが積み下ろしする4バイトを同一ワード内に収めるため，SPは4の倍数に保つ必要がある．  

# 空のスタック
何も積まれていない空のスタックは，SPがスタックに使う範囲の末尾のすぐ上の番地を指す状態である．  
リセット時のSPの初期値は，カーネルモードの空のスタックにあたる([qurge/cpu/register.md](register.md)を参照)．  
空のスタックで`RET`を実行すると，読み出す番地(SP)がCALL/RETの読み書きできる範囲の外になり，例外を起こす([qurge/cpu/exception.md](exception.md)を参照)．  
スタックに使う範囲は動作状態によって異なる([qurge/cpu/mode.md](mode.md)の「メモリを読み書きできる範囲」を参照)．  

# スタック上の領域の確保
SPは他の汎用レジスタと同じく読み書きできる．  
SPを減らしてスタック上に領域を確保し，RMR/WMRでSPからの相対位置を指定すれば，その領域に値を置ける([qurge/cpu/isa.md](isa.md)の「メモリ系(M系)」を参照)．  
RMR/WMRで読み書きする番地の範囲は，M系の命令として判定し，CALL/RETの範囲の制限を受けない．  

# 深さの上限
スタックの深さの上限は，プログラムが変数などに使う領域と重なるまでの残り容量で決まる．  
CPUはスタックの領域の境界を持たないため，重なっても検出しない([qurge/cpu/exception.md](exception.md)の「検出しない不正」を参照)．
