# ソースの編集と合成
`qurge`リポジトリは，リポジトリ直下をルートとするVivadoのプロジェクトである．合成・実装はコマンドラインのビルドを持たず，Vivadoで操作する．  

# 編集の範囲
ソースは`mypc.srcs/`の下にあり，その下のディレクトリは編集の仕方によって次の2つに分かれる．  

## 直接編集するディレクトリ
次のディレクトリのファイルは，エディタなどで直接編集する．  

```
mypc.srcs/
├── boot/              BOOT.BINを作るスクリプトと，BOOT.BINの構成(boot.bif)
│                      使い方: qurge/develop/bitstream.md
├── constrs_1/new/     PYNQ-Z2のピンの制約(top.xdc)
│                      ピンの割り当て: board.md
├── pn/                QosmosのPynesisのソース
│                      構成: qosmos/develop/source.md
├── sim_1/             テストベンチ(new/)と，それをコンパイル・実行するスクリプト
│                      使い方: qurge/develop/simulation.md
└── sources_1/new/     CPUのHDLのソース(主な作業対象)
                       ROMの内容(rom_sv.sv)は手で編集せず，Qosmosのソースから生成する
                       生成の仕方: qosmos/develop/source.mdの「ROMの生成」
```

`boot/`と`pn/`は，Vivadoの標準の構成には無く，独自に加えたディレクトリである．  

## Vivadoを介してだけ変更するディレクトリ
次のディレクトリは，Vivadoが生成・管理する．中のファイルは，Vivadoを介した操作(GUIかTclかは問わない)でだけ変更し，エディタなどVivadoを介さない手段で書き換えない．  

```
mypc.srcs/
├── sources_1/
│   ├── bd/            ブロックダイアグラム(GUIの操作で変更する)．Git管理の対象
│   └── imports/       ブロックダイアグラムから生成したトップのラッパー．Git管理の対象
└── utils_1/           デザインチェックポイント(.dcp)．Git管理の対象外
```

ブロックダイアグラムとトップのラッパーは，チェックアウトしたディレクトリでプロジェクトを開いて合成するために実体が要るため，Git管理の対象とする．デザインチェックポイントは，合成・実装をやり直せば生成し直されるため，Git管理の対象外とし，削除してもよい．  

# 合成
リポジトリ直下の`mypc.xpr`をVivadoで開き，`Generate Bitstream`を実行する．Qosmosのソースを変更した場合は，先にROMの内容を生成し直す([qosmos/develop/source.md](../../qosmos/develop/source.md)の「ROMの生成」を参照)．  

チェックアウトしたばかりのディレクトリには，ブロックダイアグラムの出力生成物とデザインチェックポイントがまだ無い．このため，最初の1回だけ次の手順が要る．  

1. ブロックダイアグラムを開き，`Generate Output Products`を実行する．IPのHDL・ラッパー・合成用のファイルが生成される  
2. `Generate Bitstream`を実行する．中間生成物が無い状態からの合成になるため，長時間かかる  

チェックアウトした直後は，`mypc.xpr`に登録済みのデザインチェックポイントが見つからない旨の警告が出る．最初の合成で生成されるため，対処は要らない．  

# Vivadoが書き換えるファイル
`mypc.xpr`とブロックダイアグラムは，Vivadoが内容を自動で書き換える．ソースを変更していないのに生じたこれらの差分は，コミットしない．  
正当な変更をコミットする場合の扱いは，ファイルごとに次のとおりである．  

## mypc.xpr
`mypc.xpr`は，開いた場所によって変わる次の値を保持している．  

- 開いた場所の絶対パス: 開くだけで書き換わる  
- 各ソースの取り込み時刻: 開くだけで書き換わる  
- デザインチェックポイントのパス: 記録された場所と異なるディレクトリで，チェックポイントが無い状態から合成すると書き換わる．プロジェクト起点の`$PSRCDIR/...`から，`$PPRDIR/..`でプロジェクトの外をたどる相対パスになる  

ソースやブロックダイアグラムを変更して`mypc.xpr`をコミットする場合も，これら3種類の値の行は元の値に戻してからコミットする．そのまま入れると，ディレクトリを移るたびに書き換わり続けるためである．  

## ブロックダイアグラム
自作のHDLを取り込んだブロックの`ip_revision`は，Vivadoがそのブロックを更新するたびに変わる．値は，更新した時刻とみられる．この値は`top.bd`と，そのブロックの`.xci`にあり，`.xci`では`IPREVISION`も同じ値を持つ．別の場所で開いて合成すると変わり，同じ場所で開き直すだけでは変わらない．  

- 差分が`ip_revision`だけの場合: ファイルを編集せず，gitで差分を破棄する  
- ブロックダイアグラムを正当に変更した場合: `ip_revision`の変更もそのままコミットに含める  

正当な変更で`ip_revision`を戻さないのは，`mypc.xpr`の値と違い，開いた場所を表す値ではないためである．同じ`.xci`でポートの定義が変わっているのに版の番号だけを戻すと，食い違った状態になる．
