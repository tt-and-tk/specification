# 仕様
|用語|仕様|
|:-|:-|
|データバス|32ビット|
|アドレスバス|16ビット|
|容量|8ビットのレジスタ65536本，64KB|

書き込みと読み込みを別のインターフェースで同時に行える．\
同じアドレスに対して同時に書き込み・読み込みすることも可能だが，動作は保証しない．

CPUのリセット自体はメモリの内容を初期化せず，リセット前に書き込まれた値がそのまま残る(実機でCPUのリセットを入れるSRSTのボタンは，あわせてメモリも初期値に戻す．[qurge/board.md](board.md)の「SRSTのボタン」を参照)．このため，プログラムが書き込む前のメモリの値は保証されない．

バースト転送用の仕組み(last信号)は用意されているが，現時点では非対応であり，転送のたびにlast信号を`true`にして単発の転送として扱う．また，詳細仕様(タイミング・last信号の扱い等)自体も未検討である．

メモリアドレスは，データバス幅(32ビット)で扱われる．\
容量は2のべき乗とし，アドレスバス幅は容量をちょうど表現できるビット数とする．このため，アドレスバス幅を超える上位ビットが1ビットでも立っている番地が容量外の番地にあたる．これらは折り返して有効な番地とみなすことはせず，不正な番地として扱う(そのときの挙動は[qurge/cpu/exception.md](cpu/exception.md)を参照)．\
容量を変更する場合は，容量から決まる次の値もあわせて変更する必要がある．

- UBASE・USIZEが使うビットの幅([qurge/cpu/register.md](cpu/register.md)を参照)
- コンパイラが変数・命令列の配置を検査する際の上限([limitations.md](../limitations.md)を参照)
- 容量を半分に分けて決める，カーネルモードのスタックを置く前半の範囲とSPの初期値(下記「領域の配置」以降を参照)
- Qosmosが実行ファイルに割り振る領域の先頭の番地・大きさ([qosmos/program/executable.md](../qosmos/program/executable.md)を参照)と，そこから決まるアセンブラの実行ファイルの命令数の上限([pyntaxis/assembler.md](../pyntaxis/assembler.md)の「出力先」を参照)

読み込み・書き込みそれぞれにおいてマスクを使用して対象のバイトを指定できる．マスクのビット幅は4ビットで，1ビットが読み書き対象の1バイトに対応する．\
リトルエンディアン(番地の小さいほうがLSB側)を採用する．\
なお，メモリ上の番地自体は0,1,2,3,…と普通の昇順に並んでおり，特殊な並び替えはない．\
下記の図は物理的な番地の配置ではなく，`address`を起点に読み書きした際，各番地のバイトがレジスタ/データバス上のどのビット位置に対応するかを示したものであり，マスクのビット位置もこれと同一の対応に従う．すなわちマスクのビットi(i=0〜3)は`address+i`番地に対応する．
```
31          23          15          7        0
|address + 3|address + 2|address + 1|address|
```

1回の読み込み・書き込みでmaskが対象とするバイト範囲(`address`からmaskの最上位ビットが指す番地まで)は，4バイト境界に揃った同一ワード内に収まっている必要がある．ワードをまたぐ`address`とmaskの組み合わせを指定した場合，範囲外番地アクセスとしてのエラーにはならず，同一ワード内で折り返した誤った番地を読み書きする．\
コンパイラ(Pynesis)は全ての変数を4バイト境界に配置し，short(2バイト)・int(4バイト)型のアクセスもその境界内に収まるよう生成するため，変数・配列要素・メンバの読み書きはこの制約に抵触しない．整数からキャストで作ったポインタなど，境界に揃わない番地を指すポインタを通して読み書きする場合([pynesis/language.md](../pynesis/language.md)の「キャスト」を参照)，手書きのアセンブリ(Pyntaxis)でM系の命令を直接記述する場合，SPを書き換える場合(下記「スタック」を参照)は，この制約を意識する必要がある．

# 領域の配置
カーネルモードでは，メモリを前半と後半に分けて使う．ユーザーモードでは，OSが割り振った領域の中だけを使い，この配置は用いない([qurge/cpu/mode.md](cpu/mode.md)の「番地の変換」を参照)．

|番地|用途|
|:-|:-|
|`0x0000`〜`0x7FFF`|変数などを置く領域(0番地から上へ使う)とスタック(`0x8000`から下へ伸びる)|
|`0x8000`〜`0xFFFF`|カーネルモードのスタック(CALL/RET)が読み書きしない範囲．Qosmosは，ここを実行ファイルに割り振る領域として使う([qosmos/program/executable.md](../qosmos/program/executable.md)を参照)|

メモリの後半もM系の命令で通常どおり読み書きできる．CPUがこの配置を用いるのは，カーネルモードのスタック(CALL/RET)だけである．

# メモリ上の命令の実行
CPUは，ユーザーモードでは，OSが割り振った領域の中に置いた命令を実行する．PCは領域の先頭の命令を0として数え，PCがpの命令は領域の中の番地p×8に置く．このため，領域を置く位置によらず同じプログラムを実行できる([qurge/cpu/mode.md](cpu/mode.md)の「番地の変換」を参照)．\
カーネルモードでは，ROMの命令だけを実行し，メモリ上の命令は実行しない(ROMに対応するPCは[qurge/rom.md](rom.md)を参照)．

1命令は8バイトを占め，64ビットの命令の下位32ビット(イミディエイトデータ)を番地の小さい側に，上位32ビット(機械語)を番地の大きい側に置く(命令のビットの割り当ては[qurge/cpu/isa.md](cpu/isa.md)を参照)．それぞれの4バイトの中は，他のデータと同じくリトルエンディアンで並べる．

|命令の先頭からの番地|内容|
|:-|:-|
|+0〜+3|イミディエイトデータ(命令のビット31〜0)|
|+4〜+7|機械語(命令のビット63〜32)|

命令は，M系の命令で領域へ書き込めば置ける(命令を置くための専用の書き込み方法はない)．命令以外の値も置けるため，命令列の後ろにデータを置いてもよい(Qosmosの実行ファイルのグローバル変数など．[qosmos/program/executable.md](../qosmos/program/executable.md)を参照)．\
ROMでは，格納した命令数より先の番地の命令を実行できない([qurge/cpu/exception.md](cpu/exception.md)を参照)．領域にはこの区切りがなく，PCが領域の中を指していれば，その位置の内容を，命令として書き込んだものかどうかによらず実行する．

# スタック
CALL/RETは，関数の戻り先をメモリ上のスタックへ積み下ろしする(命令の動作は[qurge/cpu/isa.md](cpu/isa.md)を参照)．スタックは番地の小さい方へ4バイト単位で伸び，SP(`6'h10`．[qurge/cpu/register.md](cpu/register.md)を参照)は最後に積んだ値の番地を指す．\
スタック専用の領域は設けず，カーネルモードではメモリの前半の末尾から番地の小さい方へ伸ばす(ユーザーモードのスタックは[qurge/cpu/mode.md](cpu/mode.md)の「番地の変換」を参照)．SPのリセット時の初期値は`0x8000`で，何も積まれていない空のスタックでは，前半の末尾のすぐ上の番地(メモリの後半の先頭)を指す．CALL/RETが積み下ろしする4バイトを同一ワード内に収めるため，SPは4の倍数に保つ必要がある．

スタックの深さの上限は，プログラムが変数などに使う領域と重なるまでの残り容量で決まり，重なっても検出しない(そのときの挙動は[qurge/cpu/exception.md](cpu/exception.md)を参照)．\
カーネルモードでは，CALL/RETが戻り先を積み下ろしする番地(CALLはSP−4，RETはSP)はメモリの前半に限られ，メモリの後半に入る番地を読み書きしようとすると停止する(空のスタックでの`RET`もこれに当たる．[qurge/cpu/exception.md](cpu/exception.md)を参照)．SPからの相対位置をRMR/WMRで読み書きする場合は，M系の命令としてメモリ全体を読み書きでき，この制限を受けない．

SPは他の汎用レジスタと同じく読み書きできる．SPを減らしてスタック上に領域を確保し，RMR/WMRでSPからの相対位置を指定すれば，その領域に値を置ける．
