# ROM
ROMは，カーネルモードのCPUが実行する命令を格納し，受け取ったPCに対応する命令を返す(どの動作状態でROMから命令を取り出すかは[qurge/cpu/mode.md](cpu/mode.md)の「命令を取り出す場所」を参照)．  
2つの読み出しポートを持ち，それぞれが受け取ったPCに対応する命令をクロック同期で返す(1サイクルに2つの番地の命令を読み出せる)．  
命令のビット数は64ビット(機械語32ビット+イミディエイトデータ32ビット)で，ROMの1つの番地が1命令に対応する．命令の形式とPCの数え方は[qurge/cpu/isa.md](cpu/isa.md)の「基本構成」を参照．  

# 容量と命令数の上限
ROMに置けるプログラムの命令数の上限は，16384命令に固定されている．  
ハードウェアは，32ビットのプログラムカウンタのうち，上限をちょうど表現できる下位14ビットをROMへ渡す．  
上限を超えるPC(`0x4000`以上)は，折り返して有効な番地とみなさず，不正な番地として扱う(そのときの挙動は[qurge/cpu/exception.md](cpu/exception.md)を参照)．  

ROMに実際に確保される容量は，プログラムの命令数に応じてアセンブラが自動算出する．  
アセンブラとコンパイラは，同じ値を安全上限として検査し，超過するとエラーにする([pyntaxis/language/target.md](../pyntaxis/language/target.md)の「命令数の上限」，[pynesis/language/limit.md](../pynesis/language/limit.md)の「命令数」を参照)．  

上限を増やす場合は，次のものを合わせて変更する．  

- ハードウェア: 命令数の上限と，そこから決まるROMへ渡すプログラムカウンタの幅  
- アセンブラ・コンパイラ: 命令数の安全上限  

ROM読み出し回路はBlock RAM(BRAM)に推論され，36KbitのBRAM1個におよそ512個の64ビット命令が収まる．上限は，ファイルシステム(FAT32)を含むQosmos全体を収めた上で今後の機能追加にも余裕を残す値として定めている．上限まで使ってもPYNQ-Z2搭載のZynq-7020(XC7Z020)が持つ140個のうち32個(約23%)にとどまり，残りはメインメモリに充てられる．
